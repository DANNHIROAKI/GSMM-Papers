## ABSTRACT

## 摘要

Massively parallel join algorithms have received much attention in recent years, while most prior work has focused on worst-optimal algorithms. However, the worst-case optimality of these join algorithms relies on hard instances having very large output sizes, which rarely appear in practice. A stronger notion of optimality is output-optimal, which requires an algorithm to be optimal within the class of all instances sharing the same input and output size. An even stronger optimality is instance-optimal, i.e., the algorithm is optimal on every single instance, but this may not always be achievable.

近年来，大规模并行连接算法备受关注，但多数研究聚焦于最坏情况最优算法。然而这些算法的最优性依赖于输出量极大的极端实例，这类情况在实践中极为罕见。更强的输出最优性要求算法在输入输出规模相同的所有实例类中保持最优。更严苛的实例最优性则要求算法在每个具体实例上都达到最优，但这往往难以实现。

In the traditional RAM model of computation, the classical Yannakakis algorithm is instance-optimal on any acyclic join. But in the massively parallel computation (MPC) model, the situation becomes much more complicated. We first show that for the class of r-hierarchical joins, instance-optimality can still be achieved in the MPC model. Then, we give a new MPC algorithm for an arbitrary acyclic join with load $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ ,where $\mathrm{{IN}},\mathrm{{OUT}}$ are the input and output sizes of the join,and $p$ is the number of servers in the MPC model. This improves the MPC version of the Yannakakis algorithm by an $O\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$ factor. Furthermore,we show that this is output-optimal when OUT $= O\left( {p \cdot  \mathrm{{IN}}}\right)$ ,for every acyclic but non-r-hierarchical join. Finally, we give the first output-sensitive lower bound for the triangle join in the MPC model, showing that it is inherently more difficult than acyclic joins.

在传统RAM计算模型中，经典Yannakakis算法对任意无环连接具有实例最优性。但在大规模并行计算(MPC)模型中，情况变得复杂得多。我们首先证明对于r-层次连接类，MPC模型中仍可实现实例最优性。随后提出新型MPC算法处理任意无环连接，其负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$，其中$\mathrm{{IN}},\mathrm{{OUT}}$表示连接的输入输出规模，$p$为MPC模型中的服务器数量。该算法将Yannakakis算法的MPC版本提升了$O\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$倍效率。进一步证明当OUT$= O\left( {p \cdot  \mathrm{{IN}}}\right)$时，该算法对所有无环但非r-层次连接都具有输出最优性。最后首次给出MPC模型中三角形连接的输出敏感下界，揭示其本质难度高于无环连接。

## 1 INTRODUCTION

## 1 引言

A (natural) join is defined as a hypergraph $Q = \left( {\mathcal{V},\mathcal{E}}\right)$ ,where the vertices $\mathcal{V} = \left\{  {{x}_{1},\ldots ,{x}_{n}}\right\}$ model the attributes and the hyperedges $\mathcal{E} = \left\{  {{e}_{1},\ldots ,{e}_{m}}\right\}   \subseteq  {2}^{\mathcal{V}}$ model the relations. Let $\operatorname{dom}\left( x\right)$ be the domain of attribute $x \in  \mathcal{V}$ . An instance of $Q$ is a set of relations $\mathcal{R} = \{ R\left( e\right)  : e \in  \mathcal{E}\}$ ,where $R\left( e\right)$ is a set of tuples, where each tuple is an assignment that assigns a value from $\operatorname{dom}\left( x\right)$ to $x$ for every $x \in  e$ . We use $\operatorname{IN} = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {R\left( e\right) }\right|$ to denote the size of $\mathcal{R}$ . The join results of $\mathcal{Q}$ on $\mathcal{R}$ ,denoted as $\mathcal{Q}\left( \mathcal{R}\right)$ ,consist of all combinations of tuples,one from each $R\left( e\right)$ ,such that they share common values on their common attributes. Let $\mathrm{{OUT}} = \left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$ be the output size. We study the data complexity of join algorithms, i.e., we assume that the query size,namely $n$ and $m$ ,are constants. In this paper, we focus on acyclic joins,i.e.,when the hypergraph $Q$ is acyclic (formal definition given later).

（自然）连接被定义为一个超图$Q = \left( {\mathcal{V},\mathcal{E}}\right)$，其中顶点$\mathcal{V} = \left\{  {{x}_{1},\ldots ,{x}_{n}}\right\}$建模属性，超边$\mathcal{E} = \left\{  {{e}_{1},\ldots ,{e}_{m}}\right\}   \subseteq  {2}^{\mathcal{V}}$建模关系。设$\operatorname{dom}\left( x\right)$为属性$x \in  \mathcal{V}$的域。$Q$的实例是一组关系$\mathcal{R} = \{ R\left( e\right)  : e \in  \mathcal{E}\}$，其中$R\left( e\right)$是元组的集合，每个元组是一个赋值，为每个$x \in  e$从$\operatorname{dom}\left( x\right)$到$x$分配一个值。我们用$\operatorname{IN} = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {R\left( e\right) }\right|$表示$\mathcal{R}$的大小。$\mathcal{Q}$在$\mathcal{R}$上的连接结果，记为$\mathcal{Q}\left( \mathcal{R}\right)$，由所有元组的组合构成，每个组合包含来自每个$R\left( e\right)$的一个元组，且这些元组在共有属性上具有相同的值。设$\mathrm{{OUT}} = \left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$为输出大小。我们研究连接算法的数据复杂度，即假设查询大小（即$n$和$m$）为常数。本文重点关注无环连接，即当超图$Q$为无环时（正式定义后述）。

### 1.1 The model of computation

### 1.1 计算模型

The problem gets much more interesting in the parallel setting. In this paper, we consider the massively parallel computation (MPC) model $\left\lbrack  {1,2,6,7,{21},{23},{25}}\right\rbrack$ ,which has become the standard model of computation for studying massively parallel algorithms, especially for join algorithms.

在并行环境下，该问题变得更为有趣。本文采用大规模并行计算（MPC）模型$\left\lbrack  {1,2,6,7,{21},{23},{25}}\right\rbrack$，该模型已成为研究大规模并行算法（尤其是连接算法）的标准计算模型。

In the MPC model, data is initially distributed evenly over $p$ servers with each server holding IN/ $p$ tuples. Computation proceeds in rounds. In each round, each server first sends messages to other servers, receives messages from other servers, and then does some local computation. The complexity of the algorithm is measured by the number of rounds and the load,denoted as $L$ ,which is the maximum message size received by any server in any round. A linear load $L = O\left( \frac{\mathrm{{IN}}}{p}\right)$ is the ideal case (since the initial load is already $\left. \frac{\mathrm{{IN}}}{p}\right)$ ,while if $L = O\left( \mathrm{{IN}}\right)$ ,all problems can be solved trivially in one round by simply sending all data to one server. Initial efforts were mostly spent on what can be done in a single round of computation $\left\lbrack  {2,6,7,{23},{25},{25}}\right\rbrack$ ,but recently, more interest has been given to multi-round (but still a constant) algorithms $\left\lbrack  {1,{21},{23}}\right\rbrack$ ,since new main memory based systems, such as Spark and Flink, have much lower overhead per round than previous generations like Hadoop.

MPC模型中，数据最初均匀分布在$p$台服务器上，每台服务器持有IN/$p$个元组。计算以轮次进行：每轮中，服务器先向其他服务器发送消息，接收来自其他服务器的消息，然后执行本地计算。算法复杂度通过轮次数量和负载（记为$L$，即任一轮次中单台服务器接收的最大消息量）衡量。线性负载$L = O\left( \frac{\mathrm{{IN}}}{p}\right)$是最理想情况（初始负载已为$\left. \frac{\mathrm{{IN}}}{p}\right)$），而若$L = O\left( \mathrm{{IN}}\right)$，所有问题均可通过将数据全部发送至单台服务器在一轮内简单解决。早期研究主要集中于单轮计算$\left\lbrack  {2,6,7,{23},{25},{25}}\right\rbrack$能实现的目标，但近年来，随着Spark、Flink等基于主内存的新系统每轮开销远低于Hadoop等前代系统，多轮（但仍为常数轮）算法$\left\lbrack  {1,{21},{23}}\right\rbrack$受到更多关注。

The MPC model can be considered as a simplified version of the BSP model [31], but it has enjoyed more popularity in recent years. This is mostly because the BSP model takes too many measures into consideration, such as communication costs, local computation time, memory consumption, etc. The MPC model unifies all these costs with one parameter $L$ , which makes the model much simpler. Meanwhile, although $L$ is defined as the maximum incoming message size of a server, it is also closely related with the local computation time and memory consumption, which are both increasing functions of $L$ . Thus, $L$ serves as a good surrogate of these other cost measures. This is also why the MPC model does not limit the outgoing message size of a server, which is less relevant to other costs.

MPC模型可视为BSP模型[31]的简化版本，但近年来更受青睐。这主要因为BSP模型需考量过多因素，如通信成本、本地计算时间、内存消耗等。MPC模型通过单一参数$L$统一所有这些成本，大幅简化了模型。虽然$L$定义为服务器的最大输入消息大小，但它与本地计算时间和内存消耗密切相关——二者都是$L$的递增函数。因此$L$能有效替代这些成本指标，这也是MPC模型不限制服务器输出消息大小的原因，因其与其他成本关联性较低。

All our algorithms work under the mild assumption $\operatorname{IN} \geq$ ${p}^{1 + \epsilon }$ where $\epsilon  > 0$ is any small constant. This assumption clearly holds on any reasonable values of IN and $p$ in practice; theoretically, this is the minimum requirement for the model to be able to compute some almost trivial functions, like the "or" of IN bits,in $O\left( 1\right)$ rounds. Our lower bounds hold under IN $\geq  {p}^{c}$ for some constant $c$ ,which may depend on the particular lower bound construction.

我们所有算法都在$\operatorname{IN} \geq$${p}^{1 + \epsilon }$的温和假设下成立，其中$\epsilon  > 0$为任意小常数。该假设显然适用于实践中所有合理的IN和$p$值；理论上，这是模型能计算某些近乎平凡函数（如IN比特的"或"运算）的最低要求，所需轮数为$O\left( 1\right)$。我们的下界在IN$\geq  {p}^{c}$条件下成立，其中常数$c$可能随具体下界构造而变化。

We confine ourselves to tuple-based join algorithms, i.e., the tuples are atomic elements that must be processed and communicated in their entirety. The only way to create a tuple is by making a copy, from either the original tuple or one of its copies. We say that an MPC algorithm computes the join $\mathcal{Q}$ on instance $\mathcal{R}$ if the following is achieved: For any join result $\left( {{t}_{1},\ldots ,{t}_{m}}\right)  \in  \mathcal{Q}\left( \mathcal{R}\right)$ where ${t}_{i} \in  R\left( {e}_{i}\right)$ , $i = 1,\ldots ,m$ ,these $m$ tuples (or their copies) must all be present on the same server at some point. Then the server will call a zero-cost function $\operatorname{emit}\left( {{t}_{1},\ldots ,{t}_{m}}\right)$ to report the join result. Note that since we only consider constant-round algorithms, whether a server is allowed to keep the tuples it has received from previous rounds is irrelevant: if not, it can just keep sending all these tuples to itself over the rounds, increasing the load by a constant factor. All known join algorithms in the MPC model are tuple-based and obey these requirements. Our lower bounds are combinatorial in nature: we only count the number of tuples that must be communicated in order to emit all join results, while all other information can be communicated for free. The upper bounds include all messages, with a tuple and an integer of $O\left( {\log \mathrm{{IN}}}\right)$ bits both counted as 1 unit of communication.

我们限定基于元组的连接算法，即元组作为原子元素必须整体处理和传输。创建元组的唯一方式是通过复制原始元组或其副本。当满足以下条件时，我们称MPC算法在实例$\mathcal{R}$上计算连接$\mathcal{Q}$：对于任何连接结果$\left( {{t}_{1},\ldots ,{t}_{m}}\right)  \in  \mathcal{Q}\left( \mathcal{R}\right)$（其中${t}_{i} \in  R\left( {e}_{i}\right)$,$i = 1,\ldots ,m$），这些$m$个元组（或其副本）必须曾在同一服务器上共存，该服务器随后调用零成本函数$\operatorname{emit}\left( {{t}_{1},\ldots ,{t}_{m}}\right)$输出结果。由于仅考虑常数轮算法，服务器是否保留前轮收到的元组并不影响——若不保留，只需每轮向自身发送这些元组，负载仅增加常数倍。MPC模型中所有已知连接算法都基于元组并遵循这些要求。我们的下界本质是组合性的：仅统计产生全部连接结果所需传输的元组数量，其他信息可免费传输。上界统计所有消息，每个元组和$O\left( {\log \mathrm{{IN}}}\right)$比特整数均计为1个通信单位。

### 1.2 Instance and output optimality

### 1.2 实例与输出最优性

In worst-case analysis, the entire space of instances is divided into classes by the input size IN, and the running time is measured on the worst instance in each class. For many important computational problems, this is too coarse-grained and cannot accurately characterize the performance of the algorithm. For the join problem, no algorithm can do better than $O\left( {\mathrm{{IN}}}^{1/\rho }\right)$ time in the worst case,where $\rho$ is the fractional edge cover number of the hypergraph $Q\left\lbrack  {{28},{32}}\right\rbrack$ . This bound drastically overestimates the running time on most typical instances.

在最坏情况分析中，实例空间按输入规模IN划分为若干类别，运行时间以各类别中最差实例为准。这对许多重要计算问题而言过于粗粒度，无法准确刻画算法性能。对于连接问题，最坏情况下任何算法都无法超越$O\left( {\mathrm{{IN}}}^{1/\rho }\right)$时间，其中$\rho$是超图$Q\left\lbrack  {{28},{32}}\right\rbrack$的分数边覆盖数。该界限严重高估了大多数典型实例的实际运行时间。

A more refined approach is parameterized analysis, which further subdivides the instance space into smaller classes by introducing more parameters that supposedly better characterize the difficulty of each class. For the join problem, the output size OUT is a commonly used parameter, and each class of instances share the same input and output size. Let $\mathfrak{R}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$ be the class of instances with input size $\mathrm{{IN}}$ and output size OUT. Then the load of an MPC algorithm $\mathcal{A}$ is thus a function of both IN and OUT, defined as

一种更为精细的方法是参数化分析，它通过引入更多参数进一步将实例空间细分为更小的类别，这些参数被认为能更好地刻画每个类别的难度。对于连接问题，输出大小OUT是一个常用参数，每个实例类别共享相同的输入和输出规模。设$\mathfrak{R}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$表示输入规模为$\mathrm{{IN}}$且输出大小为OUT的实例类别，那么MPC算法$\mathcal{A}$的负载即为IN和OUT的函数，其定义为

$$
{L}_{\mathcal{A}}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)  = \mathop{\max }\limits_{{\mathcal{R} \in  \mathfrak{R}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right) }}{L}_{\mathcal{A}}\left( \mathcal{R}\right) ,
$$

where ${L}_{\mathcal{A}}\left( \mathcal{R}\right)$ denotes the load of $\mathcal{A}$ on $\mathcal{R}$ . Algorithm $\mathcal{A}$ is output-optimal if

其中${L}_{\mathcal{A}}\left( \mathcal{R}\right)$表示$\mathcal{A}$算法在$\mathcal{R}$上的负载。若满足以下条件，则称算法$\mathcal{A}$具有输出最优性：

$$
{L}_{\mathcal{A}}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)  = O\left( {{L}_{{\mathcal{A}}^{\prime }}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right) }\right) ,
$$

for every algorithm ${\mathcal{A}}^{\prime }$ .

对于所有算法${\mathcal{A}}^{\prime }$均成立。

Further subdividing the instance space leads to more refined analyses. In extreme case when each class contains just one instance, we obtain instance-optimal algorithms. More precisely,an algorithm $\mathcal{A}$ is instance-optimal if

进一步细分实例空间可实现更精细的分析。当每个类别仅包含单个实例时，我们得到实例最优算法。准确地说，若算法$\mathcal{A}$满足

$$
{L}_{\mathcal{A}}\left( \mathcal{R}\right)  = O\left( {{L}_{{\mathcal{A}}^{\prime }}\left( \mathcal{R}\right) }\right) ,
$$

for every instance $\mathcal{R}$ and every algorithm ${A}^{\prime }$ . Note that by definition, an instance-optimal algorithm must be output-optimal, and an output-optimal algorithm must be worst-case optimal, but the reserve direction may not be true.

对于任意实例$\mathcal{R}$和任意算法${A}^{\prime }$均成立，则该算法具有实例最优性。根据定义，实例最优算法必然具有输出最优性，输出最优算法必然具有最坏情况最优性，但反之则不一定成立。

In the traditional RAM model of computation, the classical Yannakakis algorithm [33] can compute any acyclic join in time $O$ (IN + OUT),which is both output-optimal and instance-optimal,because on any instance $\mathcal{R}$ ,any algorithm has to spend at least $\Omega \left( \mathrm{{IN}}\right)$ time to read all the inputs ${}^{1}$ and $\Omega$ (OUT) time to enumerate the outputs. Thus,the two notions of optimality coincide (but both are stronger than worst-case optimality). Fundamentally, this is because the difficulty of any instance $\mathcal{R}$ is precisely characterized by its input size and output size,and all instances in $\mathfrak{R}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$ have exactly the same complexity $O\left( {\mathrm{{IN}} + \mathrm{{OUT}}}\right)$ .

在传统RAM计算模型中，经典Yannakakis算法[33]可在$O$(IN+OUT)时间内计算任何无环连接，该算法同时具有输出最优性和实例最优性。因为在任何实例$\mathcal{R}$上，所有算法至少需要花费$\Omega \left( \mathrm{{IN}}\right)$时间读取全部输入，并需要${}^{1}$(OUT)时间枚举输出结果。因此这两种最优性概念在此重合（但都比最坏情况最优性更强）。本质上，这是因为任何实例$\mathcal{R}$的难度都精确取决于其输入规模和输出规模，且$\mathfrak{R}\left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$中所有实例都具有完全相同的复杂度$O\left( {\mathrm{{IN}} + \mathrm{{OUT}}}\right)$。

### 1.3 Join algorithms in the MPC model

### 1.3 MPC模型中的连接算法

The situation becomes much more interesting in the MPC model. First, it has been observed that the Yannakakis algorithm can be easily implemented in the MPC model with a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right) {\left\lbrack  1\right\rbrack  }^{2}$ ,but this is not optimal. In particular, it is known that the binary join ${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$ can be computed with load $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) \left\lbrack  {7,{16}}\right\rbrack$ . This is optimal by the following simple lower bound argument: Each server can only produce $O\left( {L}^{2}\right)$ join results in a constant number of rounds with the load limited to $L$ ,so all the $p$ servers can produce at most $O\left( {p \cdot  {L}^{2}}\right)$ join results. Thus,producing OUT join results needs at least a load of $L = \Omega \left( \sqrt{\frac{\mathrm{{OUT}}}{p}}\right)$ . Meanwhile, since $L \geq  \mathrm{{IN}}/p$ by definition,the $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ bound is optimal. Note that this argument can be applied on a per-instance basis, which means that the load complexity of any instance is still precisely captured by IN and OUT,and $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ is both an instance-optimal and output-optimal bound.

在MPC模型中，情况变得更为有趣。首先，已观察到Yannakakis算法可以轻松在负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right) {\left\lbrack  1\right\rbrack  }^{2}$的MPC模型中实现，但这并非最优。特别值得注意的是，二元连接${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$可在$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) \left\lbrack  {7,{16}}\right\rbrack$负载下完成计算。通过以下简单下界论证可知其最优性：每台服务器在负载不超过$L$的恒定轮次中仅能生成$O\left( {L}^{2}\right)$个连接结果，因此所有$p$台服务器至多产生$O\left( {p \cdot  {L}^{2}}\right)$个连接结果。因此，生成OUT个连接结果至少需要$L = \Omega \left( \sqrt{\frac{\mathrm{{OUT}}}{p}}\right)$的负载。同时，根据定义$L \geq  \mathrm{{IN}}/p$，$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$边界是最优的。需注意的是，该论证可基于每个实例单独应用，这意味着任何实例的负载复杂度仍由IN和OUT精确刻画，且$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$既是实例最优边界也是输出最优边界。

However, when the join involves three relations, the situation becomes subtler, and we start to see a separation between the two notions of optimality, meaning that the load complexity of an instance may not depend only on IN and OUT. Let us start with the simplest 3-relation join ${R}_{1}\left( A\right)  \bowtie$ ${R}_{2}\left( B\right)  \bowtie  {R}_{3}\left( C\right)$ ,i.e.,computing the Cartesian product of 3 sets of tuples. Consider a particular class $\Re$ (IN,OUT) when $\mathrm{{OUT}} = {\mathrm{{IN}}}^{2}$ . Suppose the 3 relations have sizes ${N}_{1},{N}_{2},{N}_{3}$ , respectively. Then $\Re \left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$ consists of all instances with ${N}_{1} + {N}_{2} + {N}_{3} = \mathrm{{IN}}$ and ${N}_{1}{N}_{2}{N}_{3} = \mathrm{{OUT}} = {\mathrm{{IN}}}^{2}$ . Consider the following two instances: (1) ${N}_{1} = {N}_{2} = \Theta \left( \sqrt{\mathrm{{IN}}}\right) ,{N}_{3} = \Theta \left( \mathrm{{IN}}\right)$ , applying the same argument above except that each server now can produce $O\left( {L}^{3}\right)$ join results,i.e., $p \cdot  {L}^{3} = \Omega$ (OUT),we have $L = \Omega \left( {\left( \frac{\mathrm{{OUT}}}{p}\right) }^{1/3}\right)$ ; (2) if ${N}_{1} = 1,{N}_{2} = {N}_{3} = \Theta \left( \mathrm{{IN}}\right)$ ,then the problem boils down to computing the Cartesian product of two sets,which has a lower bound of $L = \Omega \left( {\left( \frac{\partial \mathrm{{UT}}}{p}\right) }^{1/2}\right)$ . The reason why instance (2) has a higher lower bound than instance (1) is that it has a higher skew, which causes more difficulty for the MPC model. Note that this phenomenon does not exist in the RAM model, in which both instances (in fact all instances in $\Re \left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$ ) have the same complexity of $O\left( {\mathrm{{IN}} + \mathrm{{OUT}}}\right)$ . Fundamentally,this is because the MPC model is all about locality: An MPC algorithm should strive to bring all related tuples to one server so as to produce as many join results as possible, while a higher skew reduces locality.

然而，当连接涉及三个关系时，情况变得更为微妙，我们开始观察到两种最优性概念之间的分离，这意味着实例的负载复杂度可能不仅仅取决于输入(IN)和输出(OUT)。让我们从最简单的三关系连接${R}_{1}\left( A\right)  \bowtie$${R}_{2}\left( B\right)  \bowtie  {R}_{3}\left( C\right)$开始，即计算三个元组集合的笛卡尔积。考虑特定类别$\Re$(输入(IN),输出(OUT))当$\mathrm{{OUT}} = {\mathrm{{IN}}}^{2}$时。假设这三个关系的大小分别为${N}_{1},{N}_{2},{N}_{3}$。那么$\Re \left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$包含所有满足${N}_{1} + {N}_{2} + {N}_{3} = \mathrm{{IN}}$和${N}_{1}{N}_{2}{N}_{3} = \mathrm{{OUT}} = {\mathrm{{IN}}}^{2}$的实例。考虑以下两个实例：(1)${N}_{1} = {N}_{2} = \Theta \left( \sqrt{\mathrm{{IN}}}\right) ,{N}_{3} = \Theta \left( \mathrm{{IN}}\right)$，应用上述相同论证，只是现在每个服务器可以生成$O\left( {L}^{3}\right)$个连接结果，即$p \cdot  {L}^{3} = \Omega$(输出(OUT))，我们得到$L = \Omega \left( {\left( \frac{\mathrm{{OUT}}}{p}\right) }^{1/3}\right)$；(2)如果${N}_{1} = 1,{N}_{2} = {N}_{3} = \Theta \left( \mathrm{{IN}}\right)$，则该问题简化为计算两个集合的笛卡尔积，其下界为$L = \Omega \left( {\left( \frac{\partial \mathrm{{UT}}}{p}\right) }^{1/2}\right)$。实例(2)比实例(1)具有更高下界的原因在于其偏斜度更高，这给MPC模型带来了更大困难。值得注意的是，这种现象在RAM模型中并不存在，其中所有实例（实际上是$\Re \left( {\mathrm{{IN}},\mathrm{{OUT}}}\right)$中的所有实例）都具有相同的复杂度$O\left( {\mathrm{{IN}} + \mathrm{{OUT}}}\right)$。从根本上说，这是因为MPC模型的核心在于局部性：MPC算法应努力将所有相关元组集中到一台服务器，以生成尽可能多的连接结果，而更高的偏斜度会降低局部性。

We can extend this argument to computing the Cartesian product of $m$ sets of sizes ${N}_{1},\ldots ,{N}_{m}$ . Any algorithm computing the full Cartesian product obviously must also compute the Cartesian product of any subset of the $n$ sets, thus the load must be at least

我们可以将此论证推广到计算$m$个大小分别为${N}_{1},\ldots ,{N}_{m}$的集合的笛卡尔积。任何计算完整笛卡尔积的算法显然也必须计算这$n$个集合中任意子集的笛卡尔积，因此负载至少为

$$
{L}_{\text{Cartesian }}\left( {p,\mathcal{R}}\right)  \mathrel{\text{:=}} \mathop{\max }\limits_{{S \subseteq  \{ 1,\ldots ,m\} }}{\left( \frac{\mathop{\prod }\limits_{{i \in  S}}{N}_{i}}{p}\right) }^{\frac{1}{\left| S\right| }}. \tag{1}
$$

It has been shown that the HyperCube algorithm [2] incurs a load of ${L}_{\text{Cartesian }}\left( {p,\mathcal{R}}\right)  \cdot  {\log }^{O\left( 1\right) }p$ on any instance $\mathcal{R}\left\lbrack  7\right\rbrack$ . Thus, it can be considered as an instance-optimal algorithm for computing Cartesian products, with an optimality ratio of ${\log }^{O\left( 1\right) }p$ .

已有研究表明，超立方算法[2]在任何实例$\mathcal{R}\left\lbrack  7\right\rbrack$上产生的负载为${L}_{\text{Cartesian }}\left( {p,\mathcal{R}}\right)  \cdot  {\log }^{O\left( 1\right) }p$。因此，它可以被视为计算笛卡尔积的实例最优算法，其最优性比率为${\log }^{O\left( 1\right) }p$。

The binary join and Cartesian products are the simplest joins. Then the obvious question is, do instance-optimal algorithms exist for larger classes of joins? If not, how about output-optimal algorithms? These are the main questions we wish to address in this paper.

二元连接和笛卡尔积是最简单的连接类型。那么显而易见的问题是：对于更广泛的连接类别是否存在实例最优算法？如果不存在，输出最优算法又如何？这些正是本文希望解决的核心问题。

### 1.4 Classification of acyclic joins

### 1.4 无环连接分类

Before describing our results, we first define some sub-classes of acyclic joins.

在阐述我们的研究成果之前，我们首先定义无环连接的若干子类别。

Acyclic joins [8]. We use the common notion of acyclicity, which is also known as $\alpha$ -acyclicity. A join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ is acyclic if there exists an undirected tree $\mathcal{T}$ whose nodes are in one-to-one correspondence with the edges in $\mathcal{E}$ such that for any vertex $v \in  \mathcal{V}$ ,all nodes containing $v$ form a connected subtree. Such a tree $\mathcal{T}$ is called the join tree of $Q$ . Note that the join tree may not be unique for a given $Q$ .

无环连接[8]。我们采用常见的无环性定义，也称为$\alpha$-无环性。当存在一个无向树$\mathcal{T}$，其节点与$\mathcal{E}$中的边形成一一对应关系，且对于任意顶点$v \in  \mathcal{V}$，包含$v$的所有节点构成连通子树时，连接$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$即为无环。这样的树$\mathcal{T}$称为$Q$的连接树。注意对于给定的$Q$，连接树可能不唯一。

Hierarchical joins [11]. A join $Q = \left( {\mathcal{V},\mathcal{E}}\right)$ is hierarchical if for every pair of vertices $x,y$ ,there is ${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$ ,or ${\mathcal{E}}_{y} \subseteq  {\mathcal{E}}_{x}$ , or ${\mathcal{E}}_{x} \cap  {\mathcal{E}}_{y} = \varnothing$ ,where ${\mathcal{E}}_{x} = \{ e \in  \mathcal{E} : x \in  e\}$ is the set of hyperedges containing attribute $x$ . Thus,all attributes can be organized into a forest,such that $x$ is a descendant of $y$ iff ${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$ . Hierarchical joins have been enjoyed nice properties in probabilistic databases $\left\lbrack  {{11},{12}}\right\rbrack$ and query answering under updates [9], but their role in the MPC model has not been studied so far.

层次化连接[11]。若对于每对顶点$x,y$，存在${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$、${\mathcal{E}}_{y} \subseteq  {\mathcal{E}}_{x}$或${\mathcal{E}}_{x} \cap  {\mathcal{E}}_{y} = \varnothing$（其中${\mathcal{E}}_{x} = \{ e \in  \mathcal{E} : x \in  e\}$是包含属性$x$的超边集合），则连接$Q = \left( {\mathcal{V},\mathcal{E}}\right)$是层次化的。因此所有属性可组织成森林结构，当且仅当${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$时，$x$是$y$的后代节点。层次化连接在概率数据库$\left\lbrack  {{11},{12}}\right\rbrack$和更新场景下的查询应答[9]中展现出优良特性，但其在MPC模型中的作用尚未被研究。

r-hierarchical joins. We consider a slightly larger class of hierarchical joins. A reduce procedure on a hypergraph (V,E)is to remove an edge $e \in  \mathcal{E}$ if there exists another edge ${e}^{\prime } \in  \mathcal{E}$ such that $e \subseteq  {e}^{\prime }$ . We can repeatedly apply the reduce procedure until no more edge can be reduced, and the resulting hypergraph is said to be reduced. A join is $r$ -hierarchical if its reduced join hypergraph is hierarchical. A hierarchical join must be r-hierarchical, but not vice versa. For example, the join ${R}_{1}\left( A\right)  \bowtie  {R}_{2}\left( {A,B}\right)  \bowtie  {R}_{3}\left( B\right)$ is r-hierarchical but not hierarchical. On the other hand, an r-hierarchical join must be acyclic.

r-层次化连接。我们研究一类更广义的层次化连接。超图(V,E)的约简操作指：当存在另一条边${e}^{\prime } \in  \mathcal{E}$满足$e \subseteq  {e}^{\prime }$时，移除边$e \in  \mathcal{E}$。重复执行约简操作直至无法继续，所得超图称为约简超图。若约简后的连接超图是层次化的，则该连接称为$r$-层次化连接。层次化连接必为r-层次化连接，反之则不成立。例如连接${R}_{1}\left( A\right)  \bowtie  {R}_{2}\left( {A,B}\right)  \bowtie  {R}_{3}\left( B\right)$是r-层次化但非层次化的。另一方面，r-层次化连接必为无环连接。

### 1.5 Our results

### 1.5 研究成果

This paper gives an almost complete characterization of acyclic joins with respect to instance-optimality and output-optimality in the MPC model. Our results are summarized in Table 1, and we explain them below in more detail.

本文在MPC模型下近乎完整地刻画了无环连接在实例最优性和输出最优性方面的特征。研究成果总结于表1，下文将进行详细阐释。

Instance-optimality. First, we extend the Cartesian product lower bound (1) to a general join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ . For any subset of relations $S \subseteq  \mathcal{E}$ ,define

实例最优性。首先将笛卡尔积下界(1)推广至一般连接$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$。对于任意关系子集$S \subseteq  \mathcal{E}$，定义

$$
Q\left( {\mathcal{R},S}\right)  \mathrel{\text{:=}} \left( {{ \bowtie  }_{e \in  S}R\left( e\right) }\right)  \ltimes  Q\left( \mathcal{R}\right) ,
$$

i.e.,the join results of relations in $S$ that are part of a full join result. Clearly,any algorithm computing $\mathcal{Q}\left( \mathcal{R}\right)$ must implicitly also compute $Q\left( {\mathcal{R},S}\right)$ for every $S$ . Because each join result in $\mathcal{Q}\left( {\mathcal{R},S}\right)$ consists of $\left| S\right|$ tuples,one from each relation in $S$ ,a server can emit at most $O\left( {L}^{\left| S\right| }\right)$ join results of $\mathcal{Q}\left( {\mathcal{R},S}\right)$ ,so we must have $p \cdot  {L}^{\left| S\right| } = \Omega \left( \left| {\mathcal{Q}\left( {\mathcal{R},S}\right) }\right| \right.$ . Thus,we obtain the following per-instance lower bound on the load:

即关系子集$S$中构成完整连接结果的局部连接结果。显然，任何计算$\mathcal{Q}\left( \mathcal{R}\right)$的算法都需隐式计算所有$S$对应的$Q\left( {\mathcal{R},S}\right)$。由于$\mathcal{Q}\left( {\mathcal{R},S}\right)$中每个连接结果由$\left| S\right|$个元组构成（每个元组来自$S$中的关系），单服务器最多可输出$O\left( {L}^{\left| S\right| }\right)$个$\mathcal{Q}\left( {\mathcal{R},S}\right)$连接结果，故必有$p \cdot  {L}^{\left| S\right| } = \Omega \left( \left| {\mathcal{Q}\left( {\mathcal{R},S}\right) }\right| \right.$。由此得到如下基于实例的负载下界：

$$
{L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  \mathrel{\text{:=}} \mathop{\max }\limits_{{S \subseteq  \mathcal{E}}}{\left( \frac{\left| \mathcal{Q}\left( \mathcal{R},S\right) \right| }{p}\right) }^{\frac{1}{\left| S\right| }}. \tag{2}
$$

The BinHC algorithm [7] is a generalization of the HyperCube algorithm to general joins. The load of the BinHC algorithm is parameterized by the degrees of all subsets of attribute values (more detail given in Section 3). Beame et al. [7] show that BinHC is optimal (up to polylog factors) within the class of instances sharing the same degrees, among all one-round MPC algorithms. In this paper, we strengthen this result by giving a new analysis of the BinHC algorithm, showing that it is actually instance-optimal (up to polylog factors) for (1) all tall-flat joins,and (2) all r-hierarchical joins provided that the instance does not contain dangling tuples (a dangling tuple is one that does not appear in the join results). Furthermore, because the per-instance lower bound (2) also holds for multi-round algorithms, these instance-optimality results extend to multi-round algorithms as well. For r-hierarchical joins with dangling tuples, one-round algorithms cannot achieve $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ load,but we can remove the dangling tuples in $O\left( 1\right)$ rounds with $O\left( \frac{\mathrm{{IN}}}{p}\right)$ load [33], and then run then BinHC algorithm. This gives a multi-round, $\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right) {\log }^{O\left( 1\right) }p$ -load algorithm, where the $O\left( 1\right)$ exponent depends on the query size,and is at least $m$ ,the number of relations. Then we give a new multi-round algorithm for r-hierarchical joins with load $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ ,i.e.,improving the instance-optimality ratio from ${\log }^{O\left( 1\right) }p$ to $O\left( 1\right)$ .

BinHC算法[7]是HyperCube算法在通用连接场景下的泛化形式。该算法的负载由属性值所有子集的度数参数化（详见第3节）。Beame等人[7]证明，在所有单轮MPC算法中，对于共享相同度数的实例类，BinHC算法具有最优性（相差多项式对数因子）。本文通过重新分析BinHC算法强化了这一结论，证明其实际上对于(1)所有高瘦平坦连接，(2)不含悬空元组（即不出现于连接结果的元组）的所有r-层次连接，均具有实例最优性（相差多项式对数因子）。由于针对单个实例的下界(2)同样适用于多轮算法，这些实例最优性结论也延伸至多轮算法。对于含悬空元组的r-层次连接，单轮算法无法实现$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$负载，但可通过$O\left( 1\right)$轮次以$O\left( \frac{\mathrm{{IN}}}{p}\right)$负载[33]消除悬空元组后执行BinHC算法，从而获得负载为$\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right) {\log }^{O\left( 1\right) }p$的多轮算法——其中$O\left( 1\right)$指数取决于查询规模且至少为$m$（关系数）。随后我们提出新型多轮算法，将r-层次连接的负载降至$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$，从而将实例最优性比率从${\log }^{O\left( 1\right) }p$提升至$O\left( 1\right)$。

The instance-optimal load $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ is not achievable beyond r-hierarchical joins ${}^{3}$ . More precisely,we show that for every acyclic join that is not r-hierarchical, there is an instance $\mathcal{R}$ with ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( \frac{\mathrm{{IN}}}{p}\right)$ but any multi-round algorithm must incur a load of ${}^{4}\widetilde{\Omega }\left( \frac{\mathrm{{IN}}}{{p}^{1/2}}\right)$ on $\mathcal{R}$ . This is actually a corollary following our output-sensitive lower bound, which is described next.

超出r-层次连接${}^{3}$范围时，实例最优负载$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$无法实现。具体而言，我们证明对于每个非r-层次的无环连接，存在满足${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( \frac{\mathrm{{IN}}}{p}\right)$的实例$\mathcal{R}$，但任何多轮算法在该实例上必然产生${}^{4}\widetilde{\Omega }\left( \frac{\mathrm{{IN}}}{{p}^{1/2}}\right)$负载。这实际上是我们接下来描述的输出敏感下界的推论。

Output-optimality. One-round algorithms have severe limitations with respect to OUT: As shown in [25], any non-tall-flat joins must incur load $\omega \left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ if only one round is allowed. On the other hand, as mentioned, the classical Yannakakis algorithm is a multi-round MPC algorithm that works for all acyclic joins and has a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ $\left\lbrack  {1,{24}}\right\rbrack$ . Thus,our focus will be on multi-round algorithms and see if this result can be improved. An instance-optimal algorithm must also be output-optimal, so we have automatically obtained output-optimal algorithms for r-hierarchical joins. In fact,we show that ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ for all r-hierarchical joins, so this is already an asymptotic improvement over the Yannakakis algorithm. But the more important question is, how about acyclic joins that are not r-hierarchical?

输出最优性。单轮算法在输出结果(OUT)方面存在严重局限：如文献[25]所示，任何非高平连接(non-tall-flat joins)在仅允许单轮计算时必然产生$\omega \left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$的负载。另一方面，经典的Yannakakis算法作为多轮MPC算法适用于所有无环连接(acyclic joins)，其负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$$\left\lbrack  {1,{24}}\right\rbrack$。因此，我们将重点研究多轮算法，探究能否改进这一结果。实例最优算法必然也是输出最优的，故我们已自动获得r-层次连接(r-hierarchical joins)的输出最优算法。事实上，我们证明${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$适用于所有r-层次连接，这相较Yannakakis算法已是渐进性改进。但更重要的问题是：非r-层次结构的无环连接表现如何？

Our main output-optimal result is a new MPC algorithm for acyclic joins achieving a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ ,which is an $O\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$ -factor improvement from the Yannakakis algorithm. Interestingly enough, we observe that while the join order does not change the running time of the Yannakakis algorithm by more than a constant factor in the RAM model, it does have asymptotic consequences in the MPC model. However, there are instances on which no join order is good, in which case we recursively decompose the join into multiple parts, and choose a good join order for each part. The number of parts is exponential in the query size but constant in terms of data size. To achieve this result, we first give a simple algorithm on the line-3 join ${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)  \bowtie  {R}_{3}\left( {C,D}\right)$ (Section 4), and then extend it to arbitrary acyclic joins (Section 5).

我们的核心输出最优成果是一个新型MPC算法，针对无环连接实现$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$的负载，相较Yannakakis算法有$O\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$倍的提升。有趣的是，我们发现虽然连接顺序在RAM模型中仅使Yannakakis算法的运行时间产生常数倍变化，但在MPC模型中却会导致渐进性差异。当不存在最优连接顺序时，我们采用递归分解策略将连接拆分为多个部分，并为每个部分选择最优连接顺序。部分数量随查询规模呈指数增长，但相对于数据规模为常数。为实现该成果，我们首先给出line-3连接${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)  \bowtie  {R}_{3}\left( {C,D}\right)$的简易算法（第4节），进而推广至任意无环连接（第5节）。

We also give a matching lower bound (up to a $\log$ factor), thereby establishing the output-optimality of the algorithm. However,the lower bound only holds when OUT $= O(p \cdot$ IN). This restriction on OUT is actually inherent, because the $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ bound cannot be optimal for all values of OUT. When OUT is large enough, a worst-case optimal algorithm will take over. For example, on the line-3 join, the worst-case optimal algorithm,which has load $O\left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right) \left\lbrack  {{17},{23}}\right\rbrack$ , becomes better when OUT $> p \cdot$ IN. Our lower bound actually indicates that the $O\left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right)$ bound is output-optimal (though it does not depend on OUT) for all OUT $> p \cdot$ IN. Thus,we now have a complete understanding of the line-3 join with respect to output-optimality. For more complicated joins, their worst-case optimal algorithms have a higher load, and the output-optimality for OUT values in the middle is still unclear.

我们还给出了匹配的下界（相差$\log$因子），从而确立算法的输出最优性。但该下界仅在OUT$= O(p \cdot$IN时成立。这种限制具有内在必然性，因为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$边界不可能对所有OUT值都最优。当OUT足够大时，最坏情况最优算法将占优。例如在line-3连接中，具有$O\left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right) \left\lbrack  {{17},{23}}\right\rbrack$负载的最坏情况最优算法在OUT$> p \cdot$IN时表现更佳。我们的下界证明$O\left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right)$边界对于所有OUT$> p \cdot$IN都是输出最优的（尽管不依赖OUT值）。至此我们已完全理解line-3连接的输出最优性。对于更复杂的连接，其中等OUT值范围的输出最优性仍不明确。

Next, we extend these results to join-aggregate (including join-project) queries that are free-connex (formal definition given in Section 6). More precisely, we give an MPC algorithm with linear load that removes all the non-output attributes of the query, converting it into an acyclic join. Then we apply our instance-optimal or output-optimal algorithm on the resulting acyclic join.

接下来，我们将这些成果扩展至自由连接(free-connex)的聚合连接（含投影连接）查询（正式定义见第6节）。具体而言，我们提出具有线性负载的MPC算法，可消除查询中所有非输出属性，将其转换为无环连接，随后对结果应用实例最优或输出最优算法。

Finally in Section 7,we turn to the triangle join ${R}_{1}\left( {B,C}\right)  \bowtie$ ${R}_{2}\left( {A,C}\right)  \bowtie  {R}_{3}\left( {A,B}\right)$ ,which is the simplest cyclic join,and give the first output-sensitive lower bound $\widetilde{\Omega }\left( {\min \left\{  {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right. }\right.$ , $\left. \left. \frac{\mathrm{{IN}}}{{p}^{2/3}}\right\}  \right)$ in the MPC model. Previously,only a worst-case bound of $\Omega \left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$ is known $\left\lbrack  {{23},{29}}\right\rbrack$ and that construction uses an instance with the maximum possible output size OUT $=$ ${\mathrm{{IN}}}^{3/2}$ . Note that the second term in the lower bound is smaller as long as $\mathrm{{OUT}} = \Omega \left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$ ,which means that under this parameter range,the $\widetilde{O}\left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$ -load algorithm [23] is not only worst-case optimal but also output-optimal. For OUT $=$ $o\left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$ ,the lower bound becomes $\widetilde{\Omega }\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ while we do not have a matching upper bound yet (some explanation on why this is difficult is given below). But at least, this shows a separation from acyclic joins, i.e., cyclic joins are harder than acyclic ones by at least a factor of $\widetilde{\Omega }\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$ .

最终在第7节中，我们转向三角形连接${R}_{1}\left( {B,C}\right)  \bowtie$${R}_{2}\left( {A,C}\right)  \bowtie  {R}_{3}\left( {A,B}\right)$——这是最简单的循环连接，并给出了MPC模型中首个输出敏感的下界$\widetilde{\Omega }\left( {\min \left\{  {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right. }\right.$，$\left. \left. \frac{\mathrm{{IN}}}{{p}^{2/3}}\right\}  \right)$。此前仅知最坏情况下界为$\Omega \left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$$\left\lbrack  {{23},{29}}\right\rbrack$，且该构造使用了可能达到最大输出规模OUT$=$${\mathrm{{IN}}}^{3/2}$的实例。需注意当下界第二项满足$\mathrm{{OUT}} = \Omega \left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$时其值更小，这意味着在此参数范围内，$\widetilde{O}\left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$负载算法[23]不仅是最坏情况最优的，同时也是输出最优的。当OUT$=$$o\left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$时，下界变为$\widetilde{\Omega }\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$，而我们尚未找到匹配的上界（下文将阐述其难点）。但至少这表明了循环连接与无环连接的分离性，即循环连接比无环连接至少困难$\widetilde{\Omega }\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$倍。

### 1.6 Other related results

### 1.6 其他相关研究成果

Most existing work on join algorithms in the MPC model has focused on the worst case. Here, the goal is to achieve a load of $O\left( \frac{\mathrm{{IN}}}{{p}^{1/\rho }}\right)$ ,where $\rho$ is the fractional edge cover number of the hypergraph $Q$ . So far,this bound has been achieved on Berge-acyclic joins ${}^{5}$ [17],joins where each relation has two attributes (i.e., $Q$ is an ordinary graph) [21],and LW joins ${\left\lbrack  {23}\right\rbrack  }^{6}$ . Whether this bound can be achieved for arbitrary joins, or even just $\alpha$ -acyclic joins,is still open. Assuming this is achievable, our output-sensitive algorithm is still better when $\mathrm{{OUT}} = O\left( {{p}^{2 - 2/\rho } \cdot  \mathrm{{IN}}}\right)$ .

现有关于MPC模型中连接算法的研究大多聚焦最坏情况。其目标是实现$O\left( \frac{\mathrm{{IN}}}{{p}^{1/\rho }}\right)$负载，其中$\rho$表示超图$Q$的分数边覆盖数。目前该界限已在Berge-无环连接${}^{5}$[17]、每个关系含两个属性的连接（即$Q$为普通图）[21]以及LW连接${\left\lbrack  {23}\right\rbrack  }^{6}$上达成。对于任意连接乃至$\alpha$-无环连接能否实现该界限仍属开放性问题。假设可达成，当$\mathrm{{OUT}} = O\left( {{p}^{2 - 2/\rho } \cdot  \mathrm{{IN}}}\right)$时我们的输出敏感算法仍具优势。

Joglekar et al. [19] described a multi-round MPC algorithm for arbitrary joins, whose load complexity depends on IN, OUT, as well as the degrees of the values. However, the load of their algorithm is at least $\Omega \left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ ,i.e.,no better than the Yannakakis algorithm on acyclic joins.

Joglekar等人[19]提出了一种适用于任意连接的多轮MPC算法，其负载复杂度取决于输入规模IN、输出规模OUT及数值度数。然而该算法负载至少为$\Omega \left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$，即在无环连接上未优于Yannakakis算法。

In the RAM model, output-sensitive join algorithms have been extensively studied. The running time of most algorithms is in form of $O\left( {{\mathrm{{IN}}}^{w} + \mathrm{{OUT}}}\right)$ ,where $w$ is certain notion of width of the hypergraph $Q\left\lbrack  {{13},{15},{22},{26}}\right\rbrack$ . However, it is not clear if this is optimal. Even for the triangle join, it is not known what the output-optimal bound is. For the triangle join,any notion of width has $w \geq  {1.5}$ ,thus these algorithms are no better than the worst-case optimal algorithm, which has running time $O\left( {\mathrm{{IN}}}^{1.5}\right)$ . Recently,an improved triangle algorithm has been developed with a running time of $O\left( {{\mathrm{{IN}}}^{1.408} + {\mathrm{{IN}}}^{1.222}{\mathrm{{OUT}}}^{0.186}}\right) \left\lbrack  {10}\right\rbrack$ ,which is better than the worst-case optimal algorithm when OUT $< {\mathrm{{IN}}}^{1.495}$ . On the lower bound side,it is known that when $\mathrm{{OUT}} \geq  \mathrm{{IN}}$ ,at least $\Omega \left( {\mathrm{{IN}}}^{4/3 - o\left( 1\right) }\right)$ time is needed,assuming the $3\mathrm{{SUM}}$ conjecture [30]. Thus, output-optimal algorithms for cyclic joins still remain a wide open problem.

在RAM模型中，输出敏感的连接算法已被广泛研究。大多数算法的运行时间表现为$O\left( {{\mathrm{{IN}}}^{w} + \mathrm{{OUT}}}\right)$形式，其中$w$代表超图$Q\left\lbrack  {{13},{15},{22},{26}}\right\rbrack$的某种宽度概念。然而这是否最优尚不明确。即便是三角形连接，其输出最优边界仍属未知。对于三角形连接而言，任何宽度概念的取值都$w \geq  {1.5}$，因此这些算法并不比最坏情况最优算法更优——后者的运行时间为$O\left( {\mathrm{{IN}}}^{1.5}\right)$。最近提出的改进三角形算法运行时间为$O\left( {{\mathrm{{IN}}}^{1.408} + {\mathrm{{IN}}}^{1.222}{\mathrm{{OUT}}}^{0.186}}\right) \left\lbrack  {10}\right\rbrack$，当输出量OUT$< {\mathrm{{IN}}}^{1.495}$时优于最坏情况最优算法。在下界方面，已知当$\mathrm{{OUT}} \geq  \mathrm{{IN}}$时至少需要$\Omega \left( {\mathrm{{IN}}}^{4/3 - o\left( 1\right) }\right)$时间（基于$3\mathrm{{SUM}}$猜想[30]）。因此，循环连接的输出最优算法仍是悬而未决的难题。

## 2 MPC PRIMITIVES

## 2 MPC原语

Assume IN $> {p}^{1 + \epsilon }$ where $\epsilon  > 0$ is any small constant. We first introduce the following primitives in the MPC model, all of which can be computed with linear load $O\left( \frac{\mathrm{{IN}}}{p}\right)$ in $O\left( 1\right)$ rounds.

假设输入量IN$> {p}^{1 + \epsilon }$（其中$\epsilon  > 0$为任意小常数）。我们首先介绍MPC模型中的以下原语，均可在$O\left( 1\right)$轮次内以线性负载$O\left( \frac{\mathrm{{IN}}}{p}\right)$完成计算。

Multi-numbering [16]: Given IN (key, value) pairs, for each key,assigns consecutive numbers $1,2,3,\ldots$ to all the pairs with the same key.

多重编号[16]：给定IN个(键,值)对，为每个键的所有相同键值对分配连续编号$1,2,3,\ldots$。

Sum-by-key [16]: Given IN (key, value) pairs, compute the sum of values for each key, where the sum is defined by any associative operator.

键控求和[16]：给定IN个(键,值)对，计算每个键的值之和（求和运算可由任意结合算子定义）。

Multi-search [16]: Given ${N}_{1}$ elements ${x}_{1},{x}_{2},\cdots ,{x}_{{N}_{1}}$ as set $X$ and ${N}_{2}$ elements ${y}_{1},{y}_{2},\cdots ,{y}_{{N}_{2}}$ as set $Y$ ,where all elements are drawn from an ordered domain. Set $\mathrm{{IN}} = {N}_{1} + {N}_{2}$ . For each ${x}_{i}$ ,find its predecessor in $Y$ ,i.e.,the largest element in $Y$ but smaller than ${x}_{i}$ .

多重搜索[16]：给定${N}_{1}$个元素${x}_{1},{x}_{2},\cdots ,{x}_{{N}_{1}}$作为集合$X$和${N}_{2}$个元素${y}_{1},{y}_{2},\cdots ,{y}_{{N}_{2}}$作为集合$Y$（所有元素来自有序域）。设$\mathrm{{IN}} = {N}_{1} + {N}_{2}$。对于每个${x}_{i}$，在$Y$中寻找其前驱（即$Y$中小于${x}_{i}$的最大元素）。

Semi-Join: Given two relations ${R}_{1}$ and ${R}_{2}$ with a common attribute $x$ ,the semijoin ${R}_{1} \ltimes  {R}_{2}$ returns all the tuples in ${R}_{1}$ whose value on $x$ matches that of at least one tuple in ${R}_{2}$ . This can be reduced to a multi-search problem: For each $t \in  {R}_{1}$ ,if its predecessor on the $x$ attribute in ${R}_{2}$ is the same as that of $t$ ,then it is in the semijoin.

半连接：给定具有共同属性$x$的两个关系${R}_{1}$和${R}_{2}$，半连接${R}_{1} \ltimes  {R}_{2}$返回${R}_{1}$中在$x$属性上匹配${R}_{2}$至少一个元组的所有元组。这可转化为多重搜索问题：对于每个$t \in  {R}_{1}$，若其在${R}_{2}$的$x$属性上前驱与$t$相同，则该元组属于半连接结果。

Note that we can remove all dangling tuples in an acyclic-join [33] by a constant number of semi-joins, so it can be done in $O\left( 1\right)$ rounds with linear load.

注意对于无环连接[33]，可通过常数次半连接消除所有悬空元组，因此可在$O\left( 1\right)$轮次内以线性负载完成。

Parallel-packing: Given IN numbers ${x}_{1},{x}_{2},\cdots ,{x}_{\mathrm{{IN}}}$ where $0 < {x}_{i} \leq  1$ for $i = 1,2,\cdots ,\mathrm{{IN}}$ ,group them into $m$ sets ${Y}_{1},{Y}_{2},\cdots ,{Y}_{m}$ such that $\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \leq  1$ for all $j$ ,and $\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \geq$ $\frac{1}{2}$ for all but one $j$ . Initially,the IN numbers are distributed arbitrarily across all servers, and the algorithm should produce all pairs(i,j)if $i \in  {Y}_{j}$ when done. Note that $m \leq  1 + 2\mathop{\sum }\limits_{i}{x}_{i}$ .

并行装箱问题：给定IN个数字${x}_{1},{x}_{2},\cdots ,{x}_{\mathrm{{IN}}}$，其中$0 < {x}_{i} \leq  1$对于$i = 1,2,\cdots ,\mathrm{{IN}}$，将它们分成$m$个集合${Y}_{1},{Y}_{2},\cdots ,{Y}_{m}$，使得对于所有$j$满足$\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \leq  1$，且对于除一个$j$外的所有情况满足$\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \geq$$\frac{1}{2}$。初始时，这些IN个数字任意分布在所有服务器上，算法完成时应输出所有满足$i \in  {Y}_{j}$的配对(i,j)。注意$m \leq  1 + 2\mathop{\sum }\limits_{i}{x}_{i}$。

We are not aware of an explicit reference on this primitive, but it can be solved quite easily, as shown in the full version of the paper [18].

我们未找到关于此基础问题的明确文献引用，但其解法相当简单，详见论文完整版[18]所述。

Computing the output size OUT of an acyclic join: This primitive is a special case of our join-aggregate algorithm, which will be described in Section 6.

## 3 R-HIERARCHICAL JOINS

## 3 R-层次化连接

Recall that in a hierarchical join, all attributes can be organized into a forest,such that $x$ is a descendant of $y$ if and only if ${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$ . Each $e \in  \mathcal{E}$ corresponds to a node $x$ in the forest,such that $e$ contains precisely $x$ and all its ancestors. A subclass of hierarchical joins are tall-flat joins. For a tall-flat join, this attribute forest takes the form of a special tree, which consists of a single "stem" plus a number of leaves at the bottom. For example, ${\mathcal{Q}}_{1} = {R}_{1}\left( {x}_{1}\right)  \bowtie  {R}_{2}\left( {{x}_{1},{x}_{2}}\right)  \bowtie$ ${R}_{3}\left( {{x}_{1},{x}_{2},{x}_{3}}\right)  \bowtie  {R}_{4}\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{4}}\right)  \bowtie  {R}_{5}\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{5}}\right)  \bowtie  {R}_{6}\left( {x}_{1}\right.$ , $\left. {{x}_{2},{x}_{3},{x}_{6}}\right)$ is a tall-flat join; ${\mathcal{Q}}_{2} = {R}_{1}\left( {{x}_{1},{x}_{2}}\right)  \bowtie  {R}_{2}\left( {{x}_{1},{x}_{3},{x}_{4}}\right)  \bowtie$ ${R}_{3}\left( {{x}_{1},{x}_{3},{x}_{5}}\right)$ is a hierarchical join (but not tall-flat). Their attribute forests (actually, trees for these two cases) are shown in Figure 2.

回顾层次化连接中，所有属性可组织成森林结构，当且仅当${\mathcal{E}}_{x} \subseteq  {\mathcal{E}}_{y}$时，$x$是$y$的后代节点。每个$e \in  \mathcal{E}$对应森林中的节点$x$，使得$e$精确包含$x$及其所有祖先节点。高平连接是层次化连接的子类，其属性森林由单一"主干"加底部若干叶子节点构成。例如${\mathcal{Q}}_{1} = {R}_{1}\left( {x}_{1}\right)  \bowtie  {R}_{2}\left( {{x}_{1},{x}_{2}}\right)  \bowtie$${R}_{3}\left( {{x}_{1},{x}_{2},{x}_{3}}\right)  \bowtie  {R}_{4}\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{4}}\right)  \bowtie  {R}_{5}\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{5}}\right)  \bowtie  {R}_{6}\left( {x}_{1}\right.$、$\left. {{x}_{2},{x}_{3},{x}_{6}}\right)$属于高平连接；${\mathcal{Q}}_{2} = {R}_{1}\left( {{x}_{1},{x}_{2}}\right)  \bowtie  {R}_{2}\left( {{x}_{1},{x}_{3},{x}_{4}}\right)  \bowtie$${R}_{3}\left( {{x}_{1},{x}_{3},{x}_{5}}\right)$属于层次化连接（但非高平连接）。图2展示了这两种情况的属性森林（实际为树结构）。

In this section, we study r-hierarchical joins. A join is r-hierarchical if its reduced join is hierarchical. For example, ${Q}_{3} = {Q}_{2} \bowtie  {R}_{4}\left( {{x}_{3},{x}_{5}}\right)  \bowtie  {R}_{5}\left( {x}_{5}\right)$ is an $\mathrm{r}$ -hierarchical join (but not hierarchical). After an r-hierarchical join is reduced, its hyperedges correspond to the leaves of the attribute forest.

本节研究r-层次化连接。当连接的约简形式为层次化时，该连接即r-层次化。例如${Q}_{3} = {Q}_{2} \bowtie  {R}_{4}\left( {{x}_{3},{x}_{5}}\right)  \bowtie  {R}_{5}\left( {x}_{5}\right)$属于$\mathrm{r}$-层次化连接（但非普通层次化连接）。r-层次化连接经约简后，其超边对应属性森林的叶节点。

### 3.1 BinHC algorithm revisited

### 3.1 BinHC算法再探讨

We mentioned above that the HyperCube algorithm [2] is an instance-optimal algorithm for computing Cartesian products. The BinHC algorithm [7] is a generalization of the HyperCube algorithm to general joins. For a join $Q$ ,denote the residual query by removing attributes $\mathbf{x} \subseteq  \mathcal{V}$ as ${\mathcal{Q}}_{\mathbf{x}}$ . Let $\mathbf{u}$ be any fractional edge packing of ${Q}_{\mathbf{x}}$ that saturates the attributes $\mathbf{x}$ ,i.e., $\mathop{\sum }\limits_{{e : x \in  e}}\mathbf{u}\left( e\right)  \geq  1$ for every $x \in  \mathbf{x}$ ,and $\mathop{\sum }\limits_{{e : x \in  e}}\mathbf{u}\left( e\right)  \leq  1$ for every $x \in  \mathcal{V} - \mathbf{x}$ . Assuming knowing all degree information in advance, this algorithm computes $\mathcal{Q}$ on instance $\mathcal{R}$ in a single round with a load of $\widetilde{O}\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right) }\right)$ ,where

前文提到，HyperCube算法[2]是计算笛卡尔积的实例最优算法。BinHC算法[7]将该算法推广至通用连接操作。对于连接$Q$，移除属性$\mathbf{x} \subseteq  \mathcal{V}$后的剩余查询记为${\mathcal{Q}}_{\mathbf{x}}$。设$\mathbf{u}$为${Q}_{\mathbf{x}}$的任意分数边填充，其饱和属性$\mathbf{x}$满足：对每个$x \in  \mathbf{x}$有$\mathop{\sum }\limits_{{e : x \in  e}}\mathbf{u}\left( e\right)  \geq  1$，对每个$x \in  \mathcal{V} - \mathbf{x}$有$\mathop{\sum }\limits_{{e : x \in  e}}\mathbf{u}\left( e\right)  \leq  1$。在预先获知所有度信息的情况下，该算法单轮计算实例$\mathcal{R}$上的$\mathcal{Q}$，其负载为$\widetilde{O}\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right) }\right)$，其中

$$
{L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right)  \mathrel{\text{:=}} \mathop{\max }\limits_{{\mathbf{x},\mathbf{u}}}{\left( \frac{\mathop{\sum }\limits_{{\mathbf{a} \in  \operatorname{dom}\left( \mathbf{x}\right) }}\mathop{\prod }\limits_{{e \in  \mathcal{E}}}{\left| {\sigma }_{\mathbf{x} = \mathbf{a}}R\left( e\right) \right| }^{\mathbf{u}\left( e\right) }}{p}\right) }^{\frac{1}{\mathop{\sum }\limits_{{e \in  \mathcal{E}}}\mathbf{u}\left( e\right) }}
$$

Here we define ${0}^{0} = 0$ . Note that for any $e \subseteq  \mathbf{x},\left| {{\sigma }_{\mathbf{x} = \mathbf{a}}R\left( e\right) }\right|$ is either 0 or 1,so we can just set $\mathbf{u}\left( e\right)  = 0$ for each such $e$ in the definition above.

此处定义${0}^{0} = 0$。注意到对于任意$e \subseteq  \mathbf{x},\left| {{\sigma }_{\mathbf{x} = \mathbf{a}}R\left( e\right) }\right|$其值非0即1，因此可直接在上述定义中为每个$e$设定$\mathbf{u}\left( e\right)  = 0$。

We prove the following results and the proofs can be found in the full version of the paper [18].

我们证明以下结论，完整证明参见论文[18]的正式版本。

THEOREM 3.1. On any tall-flat join and any instance $\mathcal{R}$ , ${L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right)  = O\left( {{L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right) .$

定理3.1. 对于任何高扁平和实例$\mathcal{R}$，${L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right)  = O\left( {{L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right) .$

THEOREM 3.2. On any $r$ -hierarchical join $Q$ and instance $\mathcal{R}$ without dangling tuples, ${L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right)  = O\left( {{L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ .

定理3.2. 对于任何$r$-层次化连接$Q$及不含悬空元组的实例$\mathcal{R}$，${L}_{\text{BinHC }}\left( {p,\mathcal{R}}\right)  = O\left( {{L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$。

Note that since ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$ is a per-instance lower bound even for multi-round algorithms, this means that the BinHC algorithm is instance-optimal even among all multi-round algorithms, up to polylogarithmic factors. This result also incorporates the instance-optimality of the HyperCube algorithm on Cartesian products, which are special r-hierarchical joins without dangling tuples.

需注意，由于${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$是即便多轮算法也适用的实例下界，这意味着BinHC算法在至多多对数因子范围内，是所有多轮算法中的实例最优解。该结果也涵盖了HyperCube算法在笛卡尔积（即不含悬空元组的特殊r-层次化连接）上的实例最优性。

Remark. Koutris and Suciu [25] show that non-tall-flat joins cannot be done with load $\widetilde{O}\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ by one-round algorithms. This does not contradict Theorem 3.2 since their lower bound construction uses dangling tuples. Our result implies that the key barrier for one-round algorithms is actually the dangling tuples. If they do not exist, one-round algorithms can go beyond tall-flat joins and solve r-hierarchical joins instance-optimally, up to polylog factors. On the other hand,once $O\left( 1\right)$ rounds are allowed,dangling tuples become irrelevant, since they can be removed with linear load and $O\left( 1\right)$ rounds.

注记. Koutris与Suciu[25]证明非高扁平连接无法通过单轮算法实现$\widetilde{O}\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$负载。这与定理3.2并不矛盾，因其下界构造使用了悬空元组。我们的结果表明，单轮算法的关键障碍实为悬空元组。若其不存在，单轮算法可突破高扁平连接限制，在至多多对数因子范围内实现r-层次化连接的实例最优求解。反之，若允许$O\left( 1\right)$轮次，则悬空元组不再构成障碍，因其可通过线性负载与$O\left( 1\right)$轮次消除。

### 3.2 An instance-optimal algorithm

### 3.2 实例最优算法

We have shown that the BinHC algorithm is an instance-optimal algorithm for r-hierarchical joins, but it has an instance-optimality ratio of ${\log }^{O\left( 1\right) }p$ ,where the $O\left( 1\right)$ exponent depends on the query size,and is at least $m$ ,the number of relations. In this section, we improve the optimality ratio to $O\left( 1\right)$ ,i.e.,achieving a load of $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ . Our algorithm uses $O\left( 1\right)$ rounds,but note that BinHC also needs $O\left( 1\right)$ rounds to remove the dangling tuples if they exist. Furthermore, our algorithm is deterministic while BinHC is randomized.

我们已证明BinHC算法是r-层次连接(r-hierarchical joins)的实例最优算法，但其最优性比率为${\log }^{O\left( 1\right) }p$，其中$O\left( 1\right)$指数取决于查询规模，且至少为$m$（关系数）。本节将该比率优化至$O\left( 1\right)$，即实现$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$的负载。本算法使用$O\left( 1\right)$轮通信，需注意BinHC同样需要$O\left( 1\right)$轮来消除悬空元组（若存在）。此外，本算法为确定性算法，而BinHC是随机化的。

As a preprocessing step, we remove all dangling tuples. Then we reduce the join hypergraph,since if $e \subseteq  {e}^{\prime },R\left( e\right)$ will not affect the final join results after dangling tuples are removed ${}^{7}$ . Thus,we are left with a hierarchical join $Q$ on an instance $\mathcal{R}$ with no dangling tuples.

预处理阶段首先移除所有悬空元组，随后简化连接超图——因为当$e \subseteq  {e}^{\prime },R\left( e\right)$时，移除悬空元组后${}^{7}$将不影响最终连接结果。由此我们得到无悬空元组的实例$\mathcal{R}$上的层次化连接$Q$。

Let $\mathcal{T}$ be the attribute forest of $\mathcal{Q}$ . Recall that after the join is reduced,each relation corresponds to a leaf of $\mathcal{T}$ , whose attributes are precisely the leaf’s ancestors in $\mathcal{T}$ . Our algorithm is recursive. We will show that the load of this algorithm is $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ for any hierarchical join $\mathcal{Q}$ on any instance $\mathcal{R}$ . To simplify notation,we will not derive the exact constant in the big-Oh, which depends (exponentially) on the recursion depth. Since the recursion depth is proportional to (actually,twice) the height of $\mathcal{T}$ ,which is a constant, this is not a concern. Similarly, the number of servers employed by the algorithm will be $O\left( p\right)$ ,where the hidden constant may also depend on the recursion depth.

设$\mathcal{T}$为$\mathcal{Q}$的属性森林。需注意简化连接后，每个关系对应$\mathcal{T}$的叶节点，其属性恰好是该叶节点在$\mathcal{T}$中的祖先。本递归算法对任意实例$\mathcal{R}$上的层次化连接$\mathcal{Q}$均可实现$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$的负载。为简化表示，大O记号中的常数项（与递归深度呈指数相关）不作精确推导。由于递归深度与$\mathcal{T}$高度（实际为两倍）成比例且为常量，故无需考虑。同理，算法使用的服务器数量为$O\left( p\right)$，其中隐含常数亦可能取决于递归深度。

The base case is when $Q$ has just one relation. In this case the algorithm just emits all tuples in the relation, achieving the bound $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$ trivially.

基础情形是当$Q$仅含单个关系时，算法直接输出该关系所有元组，显然满足$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right) }\right)$的负载边界。

For a general hierarchical join $Q$ and an instance $\mathcal{R}$ ,we proceed as follows. We first compute ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$ : We use $p$ servers to compute $\left| {{ \bowtie  }_{e \in  S}R\left( e\right) }\right|$ for each $S \subseteq  \mathcal{E}$ (recall that computing the output size of an acyclic join is an MPC primitive). This requires $O\left( p\right)$ servers with load $O\left( \frac{\mathrm{{IN}}}{p}\right)$ . Note that $Q\left( {\mathcal{R},S}\right)  = { \bowtie  }_{e \in  S}R\left( e\right)$ when there is no dangling tuples in $\mathcal{R}$ ,so we can compute ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$ as defined in (2). Setting $L = \frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$ ,we will show below how to compute the join with $O\left( p\right)$ servers and load $O\left( L\right)$ .

对于一般层次化连接$Q$和实例$\mathcal{R}$，处理流程如下：首先计算${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$——使用$p$台服务器为每个$S \subseteq  \mathcal{E}$计算$\left| {{ \bowtie  }_{e \in  S}R\left( e\right) }\right|$（需注意无环连接输出大小计算是MPC原语）。此步骤需要$O\left( p\right)$台服务器及$O\left( \frac{\mathrm{{IN}}}{p}\right)$负载。由于$\mathcal{R}$中无悬空元组时$Q\left( {\mathcal{R},S}\right)  = { \bowtie  }_{e \in  S}R\left( e\right)$，故可按式(2)定义计算${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$。设$L = \frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R}}\right)$，下文将展示如何用$O\left( p\right)$台服务器和$O\left( L\right)$负载完成连接计算。

Let $k$ be the number of trees in $\mathcal{T}$ . We handle the following two cases using different recursive strategies:

令$k$表示$\mathcal{T}$中的树数量，我们采用不同递归策略处理以下两种情形：

Case (1): $k = 1$ . In this case, $\mathcal{T}$ is a tree. Suppose the root attribute of $\mathcal{T}$ is $x$ ,which is included in all the relations. Consider every $a \in  \operatorname{dom}\left( x\right)$ ,and let ${\mathcal{R}}_{a} = \left\{  {{\sigma }_{x = a}R\left( e\right)  : e \in  \mathcal{E}}\right\}$ . It suffices to compute the residual query ${Q}_{x}$ on each ${\mathcal{R}}_{a}$ ,but all the ${\mathcal{Q}}_{x}\left( {\mathcal{R}}_{a}\right)$ ’s have to be computed in parallel,using $O\left( p\right)$ servers in total. Thus, the key is to allocate servers to these residual queries appropriately so as to ensure a uniform load of $O\left( L\right)$ . To do so,we first compute ${\mathrm{{IN}}}_{a}$ ,the input size of ${\mathcal{R}}_{a}$ ,for all $a \in  \operatorname{dom}\left( x\right)$ . Since ${\mathrm{{IN}}}_{a} = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {{\sigma }_{x = a}R\left( e\right) }\right|$ ,and each tuple belongs to exactly one ${\mathcal{R}}_{a}$ ,this is a sum-by-key problem,i.e.,each tuple $t$ with ${\pi }_{x}t = a$ has key $a$ and weight 1. Note that $\mathrm{{IN}} = \mathop{\sum }\limits_{a}{\mathrm{{IN}}}_{a}$ .

情形(1): $k = 1$。此情形下，$\mathcal{T}$为树结构。假设$\mathcal{T}$的根属性是$x$（该属性存在于所有关系中）。对于每个$a \in  \operatorname{dom}\left( x\right)$，令${\mathcal{R}}_{a} = \left\{  {{\sigma }_{x = a}R\left( e\right)  : e \in  \mathcal{E}}\right\}$。只需在各${\mathcal{R}}_{a}$上计算残余查询${Q}_{x}$，但所有${\mathcal{Q}}_{x}\left( {\mathcal{R}}_{a}\right)$需并行计算，共使用$O\left( p\right)$台服务器。因此关键在于合理分配服务器资源给这些残余查询，以确保$O\left( L\right)$的均匀负载。为此，我们首先计算所有$a \in  \operatorname{dom}\left( x\right)$对应的${\mathcal{R}}_{a}$输入规模${\mathrm{{IN}}}_{a}$。由于${\mathrm{{IN}}}_{a} = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {{\sigma }_{x = a}R\left( e\right) }\right|$且每个元组仅属于一个${\mathcal{R}}_{a}$，这属于按键求和问题，即每个具有${\pi }_{x}t = a$的元组$t$以$a$为键、权重为1。注意$\mathrm{{IN}} = \mathop{\sum }\limits_{a}{\mathrm{{IN}}}_{a}$。

An instance ${\mathcal{R}}_{a}$ is heavy if ${\mathrm{{IN}}}_{a} > L$ and light otherwise. We handle heavy and light instances in different ways.

若实例${\mathcal{R}}_{a}$满足${\mathrm{{IN}}}_{a} > L$则称其为重型实例，否则为轻型实例。我们对重型与轻型实例采用不同处理方式。

Case (1.1): Light instances. We use the parallel-packing primitive to put the light instances into $O\left( \frac{\mathrm{{IN}}}{L}\right)  = O\left( p\right)$ groups with each group having total input size $O\left( L\right)$ . Then we simply use one server to solve the instances in each group. The load of each server is $O\left( L\right)$ .

情形(1.1): 轻型实例。使用并行打包原语将轻型实例分入$O\left( \frac{\mathrm{{IN}}}{L}\right)  = O\left( p\right)$个组，每组总输入规模为$O\left( L\right)$。随后每组分配一台服务器处理实例，每台服务器负载为$O\left( L\right)$。

Case (1.2): Heavy instances. By definition, there are at most $\frac{\mathrm{{IN}}}{L} = O\left( p\right)$ heavy instances. For each heavy instance ${\mathcal{R}}_{a}$ ,we allocate ${p}_{a} = \left\lceil  {p \cdot  \frac{{\mathrm{{IN}}}_{a}}{\mathrm{{IN}}}}\right\rceil$ servers to compute in parallel the join size $\left| {{\mathcal{Q}}_{x}\left( {{\mathcal{R}}_{a},S}\right) }\right|$ for all $a \in  \operatorname{dom}\left( x\right)$ and all $S \subseteq  \mathcal{E}$ . This uses $O\left( p\right)$ servers,and the load is $O\left( {\mathop{\max }\limits_{a}\frac{{\mathrm{{IN}}}_{a}}{{p}_{a}}}\right)  = O\left( \frac{\mathrm{{IN}}}{p}\right)$ . Next,for each heavy instance ${\mathcal{R}}_{a}$ ,we allocate

## 4 三线连接

The simplest acyclic but not $r$ -hierarchical join is the line-3 join ${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)  \bowtie  {R}_{3}\left( {C,D}\right)$ . In this section,we give an output-optimal MPC algorithm with load $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ , together with a matching lower bound. In particular, the lower bound implies that instance-optimal algorithms are not possible for the line-3 join. In Section 5, we extend these results to arbitrary acyclic joins.

最简单的无环但非$r$层次化连接是三线连接${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)  \bowtie  {R}_{3}\left( {C,D}\right)$。本节提出负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$的输出最优MPC算法，并给出匹配下界。该下界特别表明：对于三线连接不存在实例最优算法。第5节将把这些结果推广到任意无环连接。

### 4.1 The Yannakakis algorithm revisited

### 4.1 重探Yannakakis算法

The Yannakakis algorithm first removes all the dangling tuples, which is just a series of semi-joins and can be done with load $O\left( \frac{\mathrm{{IN}}}{p}\right)$ . Then the algorithm performs pairwise joins in some arbitrary order. In the RAM model, the join order does not affect the asymptotic running time: After dangling tuples have been removed, any intermediate join result is part of a full join result, so the running time of the last join, which is $\Theta \left( \mathrm{{OUT}}\right)$ ,dominates that of any intermediate join. In fact, this argument applies on a per-instance basis, and the Yannakakis algorithm is instance-optimal on any instance with any join order.

Yannakakis算法首先移除所有悬空元组（仅需一系列半连接操作，可在$O\left( \frac{\mathrm{{IN}}}{p}\right)$负载下完成），随后以任意顺序执行两两连接。在RAM模型中，连接顺序不影响渐近运行时间：移除悬空元组后，任何中间连接结果都是全连接结果的组成部分，因此最终连接（其时间复杂度为$\Theta \left( \mathrm{{OUT}}\right)$）主导所有中间连接耗时。事实上，该论证基于每个实例成立，使得Yannakakis算法对采用任意连接顺序的任意实例都具有实例最优性。

Interestingly, the join order does matter in the MPC model. Consider the following instance of the line-3 join (see the top half of Figure 3). Attributes $A,B,C,D$ have domain sizes $\frac{\mathrm{{OUT}}}{N},\frac{{N}^{2}}{\mathrm{{OUT}}},N,1$ ,respectively. Set ${R}_{1}\left( {A,B}\right)  = \operatorname{dom}\left( A\right)  \times  \operatorname{dom}\left( B\right)$ , ${R}_{2}\left( {B,C}\right)$ is a one-to-many relation from $\operatorname{dom}\left( B\right)$ to $\operatorname{dom}\left( C\right)$ , and ${R}_{3}\left( {C,D}\right)  = \operatorname{dom}\left( C\right)  \times  \operatorname{dom}\left( D\right)$ . Note that this instance has $\mathrm{{IN}} = \Theta \left( N\right)$ and the output size is exactly OUT. Consider first the join plan $\left( {{R}_{1} \bowtie  {R}_{2}}\right)  \bowtie  {R}_{3}$ ,and note that $\mid  {R}_{1} \bowtie$ ${R}_{2}\left|  = \right| {R}_{1} \bowtie  {R}_{2} \bowtie  {R}_{3} \mid   =$ OUT. Using the $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ -load algorithm $\left\lbrack  {7,{16}}\right\rbrack$ for binary joins,the load of computing ${R}_{1} \bowtie  {R}_{2}$ is $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ . However,since the output of the first join is the input of the second join, the input size for the second join is OUT, so the load of the second join is $O\left( {\frac{\mathrm{{OUT}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)  = O\left( \frac{\mathrm{{OUT}}}{p}\right)$ . In general,the intermediate join result can be as large as $O\left( \mathrm{{OUT}}\right)$ ,which is why the Yannakakis algorithm incurs a load of $O\left( \frac{\mathrm{{OUT}}}{p}\right)$ (after dangling tuples are removed) on an acyclic join, as observed in [1, 24].

有趣的是，在MPC模型中连接顺序确实至关重要。考虑以下line-3连接的实例（见图3上半部分）。属性$A,B,C,D$的域大小分别为$\frac{\mathrm{{OUT}}}{N},\frac{{N}^{2}}{\mathrm{{OUT}}},N,1$。集合${R}_{1}\left( {A,B}\right)  = \operatorname{dom}\left( A\right)  \times  \operatorname{dom}\left( B\right)$与${R}_{2}\left( {B,C}\right)$构成从$\operatorname{dom}\left( B\right)$到$\operatorname{dom}\left( C\right)$的一对多关系，且${R}_{3}\left( {C,D}\right)  = \operatorname{dom}\left( C\right)  \times  \operatorname{dom}\left( D\right)$。注意该实例具有$\mathrm{{IN}} = \Theta \left( N\right)$特征，输出大小恰好为OUT。首先考察连接计划$\left( {{R}_{1} \bowtie  {R}_{2}}\right)  \bowtie  {R}_{3}$，可见$\mid  {R}_{1} \bowtie$${R}_{2}\left|  = \right| {R}_{1} \bowtie  {R}_{2} \bowtie  {R}_{3} \mid   =$OUT。使用$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$-负载算法$\left\lbrack  {7,{16}}\right\rbrack$处理二元连接时，计算${R}_{1} \bowtie  {R}_{2}$的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。然而由于首次连接输出将作为二次连接的输入，二次连接的输入规模为OUT，因此其负载达$O\left( {\frac{\mathrm{{OUT}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)  = O\left( \frac{\mathrm{{OUT}}}{p}\right)$。一般而言，中间连接结果可能高达$O\left( \mathrm{{OUT}}\right)$，这正是Yannakakis算法在无环连接中（去除悬空元组后）会产生$O\left( \frac{\mathrm{{OUT}}}{p}\right)$负载的原因，如文献[1,24]所述。

Now consider the alternative plan ${R}_{1} \bowtie  \left( {{R}_{2} \bowtie  {R}_{3}}\right)$ . Note that $\left| {{R}_{2} \bowtie  {R}_{3}}\right|  = O\left( \mathrm{{IN}}\right)$ ,so the load of computing ${R}_{2} \bowtie  {R}_{3}$ is $O\left( \frac{\mathrm{{IN}}}{p}\right)$ ,while the load of computing the second join is $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ . Crucially,the reason why the second plan is better is that it has a smaller intermediate join size. Note that a smaller intermediate join size does not matter in the RAM model, where the total cost is always dominated by the last join. But it does matter in the MPC model, because of the $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ load complexity of a binary join,which has a linear dependency on the input size but sublinear in the output size. Fundamentally, this is because the MPC model is all about locality: algorithms strive to send all "related" tuples to the same server so as to maximize the number of join results that can be found by the server locally.

现在考虑替代计划${R}_{1} \bowtie  \left( {{R}_{2} \bowtie  {R}_{3}}\right)$。注意到$\left| {{R}_{2} \bowtie  {R}_{3}}\right|  = O\left( \mathrm{{IN}}\right)$，因此计算${R}_{2} \bowtie  {R}_{3}$的负载为$O\left( \frac{\mathrm{{IN}}}{p}\right)$，而二次连接的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。关键在于，第二方案更优的原因在于其更小的中间连接规模。需注意在RAM模型中较小的中间连接规模无关紧要，因为总成本始终由最终连接决定。但在MPC模型中这至关重要，由于二元连接的$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$负载复杂度对输入规模呈线性依赖，而对输出规模呈次线性关系。本质上，这是因为MPC模型的核心是局部性：算法致力于将所有"相关"元组发送至同一服务器，从而最大化服务器本地可发现的连接结果数量。

Now, the key question is if there is always a join plan with an intermediate join size asymptotically smaller than $O$ (OUT). Unfortunately,the answer is no. A bad example can be easily constructed, by just putting two of the above instances together, but in opposite directions (see Figure 3). Nevertheless, this bad example precisely points us to the right direction: Although a global best join order may not exist, but if we decompose the join into multiple pieces, it is possible to find a provably good join order for each. This is exactly the basic idea of our algorithm, presented next.

现在，关键问题在于是否存在一种连接方案，其中间连接规模始终渐进小于$O$(OUT)。遗憾的是，答案是否定的。只需将上述两个实例以相反方向组合（见图3），就能轻易构造出反例。然而这个反例恰恰为我们指明了正确方向：虽然全局最优连接顺序可能不存在，但若将连接分解为多个部分，就有可能为每个部分找到可证明的良好连接顺序。这正是我们接下来要介绍的算法核心理念。

### 4.2 A new algorithm for the line-3 join

### 4.2 针对三路连接的新算法

We first compute OUT (an MPC primitive). Then we proceed in two steps:

我们首先计算OUT（MPC原语），然后分两步进行：

Step (1): Computing degrees. For a value in attribute $B$ , it is heavy if its degree in relation ${R}_{1}$ ,i.e., $\left| {{\sigma }_{B = b}{R}_{1}}\right|$ ,is greater than $\tau$ (value to be determined later),otherwise light. We first use the sum-by-key primitive to compute the degrees of all $b$ ’s for $b \in  \operatorname{dom}\left( B\right)$ . After classifying the values in $\operatorname{dom}\left( B\right)$ as heavy and light,we divide tuples in ${R}_{1}$ and ${R}_{2}$ also into heavy tuples and light tuples,depending on their $B$ value. More precisely,a tuple in ${R}_{1}$ or ${R}_{2}$ is heavy if its $B$ value is heavy, and light otherwise. This can be done by the multi-search primitive. We denote the heavy (resp. light) tuples in ${R}_{i}$ as ${R}_{i}^{H}$ (resp. ${R}_{i}^{L}$ ),for $i = 1,2$ .

步骤(1)：计算度数。对于属性$B$中的值，若其在关系${R}_{1}$中的度数（即$\left| {{\sigma }_{B = b}{R}_{1}}\right|$）大于$\tau$（该阈值将在后续确定），则称其为重值，否则为轻值。我们首先使用键值求和原语计算$b \in  \operatorname{dom}\left( B\right)$中所有$b$的度数。将$\operatorname{dom}\left( B\right)$中的值划分为重值和轻值后，根据$B$值的类型，将${R}_{1}$和${R}_{2}$中的元组也划分为重元组和轻元组。具体而言，${R}_{1}$或${R}_{2}$中的元组若其$B$值为重值则归为重元组，否则为轻元组。这可通过多重搜索原语实现。我们将${R}_{i}$中的重元组（相应地，轻元组）记为${R}_{i}^{H}$（相应地，${R}_{i}^{L}$），其中$i = 1,2$。

Step (2): Decomposing the join. We decompose the join into the following two parts, and compute them using different join orders:

步骤(2)：分解连接。我们将连接分解为以下两部分，并采用不同的连接顺序计算：

$$
{Q}_{1} = {R}_{1}^{H} \bowtie  \left( {{R}_{2}^{H} \bowtie  {R}_{3}}\right) ,
$$

$$
{Q}_{2} = \left( {{R}_{1}^{L} \bowtie  {R}_{2}^{L}}\right)  \bowtie  {R}_{3}.
$$

Note that since ${R}_{1}$ and ${R}_{2}$ are both divided according to the $B$ attribute, ${R}_{1}^{H}$ do not join with ${R}_{2}^{L},{R}_{1}^{L}$ do not join with ${R}_{2}^{H}$ .

注意由于${R}_{1}$和${R}_{2}$都是根据$B$属性划分的，${R}_{1}^{H}$不与${R}_{2}^{L},{R}_{1}^{L}$连接，${R}_{2}^{H}$也不参与连接。

Now we analyze the load. For ${Q}_{1}$ ,the intermediate join ${R}_{23} = {R}_{2}^{H} \bowtie  {R}_{3}$ has size bounded by $\frac{\mathrm{{OUT}}}{\tau }$ ,since each intermediate join result from ${R}_{23}$ has a heavy $B$ value,so it joins with at least $\tau$ tuples in ${R}_{1}$ . Thus,the load of computing ${\mathcal{Q}}_{1}$ is $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p\tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ .

现在分析负载。对于${Q}_{1}$，中间连接${R}_{23} = {R}_{2}^{H} \bowtie  {R}_{3}$的规模受限于$\frac{\mathrm{{OUT}}}{\tau }$，因为来自${R}_{23}$的每个中间连接结果都包含重值$B$，故至少会与${R}_{1}$中的$\tau$个元组连接。因此，计算${\mathcal{Q}}_{1}$的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p\tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。

For ${Q}_{2}$ ,the intermediate join ${R}_{12} = {R}_{1}^{L} \bowtie  {R}_{2}^{L}$ has size bounded by $\mathrm{{IN}} \cdot  \tau$ ,since each light tuple from ${R}_{2}$ can join with at most $\tau$ tuples from ${R}_{1}$ . Thus,the load of computing ${Q}_{2}$ is $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{IN}} \cdot  \tau }{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) .$

对于${Q}_{2}$，中间连接${R}_{12} = {R}_{1}^{L} \bowtie  {R}_{2}^{L}$的规模受限于$\mathrm{{IN}} \cdot  \tau$，因为来自${R}_{2}$的每个轻元组最多与${R}_{1}$中的$\tau$个元组连接。因此，计算${Q}_{2}$的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{IN}} \cdot  \tau }{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) .$

Setting $\tau  = \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}$ balances the second term in both cases, and we obtain the claimed result (note that $\sqrt{\frac{\mathrm{{OUT}}}{p}} \leq  \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}$ for $\left. {\mathrm{{IN}} \geq  p}\right)$ :

通过设置$\tau  = \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}$可平衡两种情况的第二项，由此得到最终结果（注意对于$\left. {\mathrm{{IN}} \geq  p}\right)$有$\sqrt{\frac{\mathrm{{OUT}}}{p}} \leq  \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}$）：

THEOREM 4.1. There is an algorithm computing the line-3 join in $O\left( 1\right)$ rounds with load $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ .

定理4.1. 存在一种算法可在$O\left( 1\right)$轮次内计算线型3连接，其负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$。

### 4.3 Lower bound

### 4.3 下界证明

In the full version [18], we prove the following lower bound on any tuple-based algorithm for computing the line-3 join.

在完整版论文[18]中，我们证明了以下关于任何基于元组的线型3连接算法的下界。

THEOREM 4.2. For any OUT $\geq$ IN,there exists an instance $\mathcal{R}$ for the line-3 join with input size $\Theta \left( \mathrm{{IN}}\right)$ and output size $\Theta$ (OUT),such that any tuple-based algorithm computing the join in $O\left( 1\right)$ rounds must have a load of $\Omega \left( {\min \left\{  {\frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p \cdot  \log \mathrm{{IN}}},\frac{\mathrm{{IN}}}{\sqrt{p}}}\right\}  }\right)$ .

定理4.2. 对于任意输出$\geq$输入的情况，存在一个输入规模为$\Theta \left( \mathrm{{IN}}\right)$、输出规模为$\Theta$(OUT)的线型3连接实例$\mathcal{R}$，使得任何在$O\left( 1\right)$轮次内计算该连接的基于元组算法，其负载必须达到$\Omega \left( {\min \left\{  {\frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p \cdot  \log \mathrm{{IN}}},\frac{\mathrm{{IN}}}{\sqrt{p}}}\right\}  }\right)$。

Ignoring logarithmic factors, this lower bound completes our understanding of the line-3 join in terms of output-optimality: (1) When OUT $\leq$ IN,the Yannakakis algorithm has linear load $O\left( \frac{\mathrm{{IN}}}{p}\right)$ . (2) When $\mathrm{{IN}} < \mathrm{{OUT}} \leq  p \cdot  \mathrm{{IN}}$ ,the lower bound becomes $\widetilde{\Omega }\left( \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}\right)$ ,which is matched by our new algorithm. (3) When OUT $\geq  p \cdot$ IN,the lower bound is $\Omega \left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right)$ ,which is matched by the worst-case optimal algorithm in [17, 23]. In particular, this means that when OUT is large enough, the load complexity of the join is no longer output-sensitive. This also stands in contrast with the RAM model, where the complexity of any acyclic join always grows linearly with OUT.

忽略对数因子后，该下界完善了我们对线型3连接输出最优性的理解：(1)当OUT$\leq$输入时，Yannakakis算法具有线性负载$O\left( \frac{\mathrm{{IN}}}{p}\right)$；(2)当$\mathrm{{IN}} < \mathrm{{OUT}} \leq  p \cdot  \mathrm{{IN}}$时，下界变为$\widetilde{\Omega }\left( \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}\right)$，这与我们新算法的性能匹配；(3)当OUT$\geq  p \cdot$输入时，下界为$\Omega \left( \frac{\mathrm{{IN}}}{\sqrt{p}}\right)$，这与文献[17,23]中的最坏情况最优算法一致。特别地，这意味着当OUT足够大时，连接操作的负载复杂度不再具有输出敏感性。这也与RAM模型形成对比——在RAM模型中，任何无环连接的复杂度总是与OUT呈线性增长。

An easy corollary (proof in the full version [18]) is the following result, which shows that instance-optimality is not achievable for the line-3 join.

一个简单推论（证明见完整版[18]）如下，该结果表明线型3连接无法实现实例最优性。

COROLLARY 4.3. For any $\mathrm{{IN}} \geq  {p}^{3/2}$ ,there is an instance $\mathcal{R}$ with input size $\Theta \left( \mathrm{{IN}}\right)$ for the line-3 join,such that any tuple-based algorithm computing the join in $O\left( 1\right)$ rounds must have $a\operatorname{load}$ of $\Omega \left( \frac{\mathrm{{IN}}}{{p}^{1/2}\log \mathrm{{IN}}}\right)$ ,while ${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( \frac{\mathrm{{IN}}}{p}\right)$ .

推论4.3. 对于任意$\mathrm{{IN}} \geq  {p}^{3/2}$，存在一个输入规模为$\Theta \left( \mathrm{{IN}}\right)$的线型3连接实例$\mathcal{R}$，使得任何在$O\left( 1\right)$轮次内计算该连接的基于元组算法，其$a\operatorname{load}$必须达到$\Omega \left( \frac{\mathrm{{IN}}}{{p}^{1/2}\log \mathrm{{IN}}}\right)$，而${L}_{\text{instance }}\left( {p,\mathcal{R}}\right)  = O\left( \frac{\mathrm{{IN}}}{p}\right)$。

## 5 ACYCLIC JOINS

## 5 无环连接

In this section, we first extend the results from the previous section to arbitrary acyclic joins. Specifically, the algorithm is a (nontrivial) generalization of the line-3 algorithm, but it is self-contained; the lower bound builds on top of the hard instance of the line-3 join.

本节首先将前文结论推广至任意无环连接。具体而言，该算法是line-3算法的（非平凡）泛化，但自成体系；其下界建立在line-3连接的困难实例之上。

### 5.1 Algorithm

### 5.1 算法

As preprocessing, we remove all dangling tuples. Assume the output size OUT has been computed (an MPC primitive).

预处理阶段将移除所有悬空元组。假设输出规模OUT已计算完成（此为MPC原语）。

Recall that in an acyclic join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ ,the hyperedges $\mathcal{E}$ can be organized into a join tree $\mathcal{T}$ ,such that for each attribute $x \in  \mathcal{V}$ ,the nodes corresponding to ${\mathcal{E}}_{x}$ are connected in $\mathcal{T}$ . Given such a join tree $\mathcal{T}$ ,our algorithm recursively decomposes the join into multiple pieces, and apply a different join strategy for each.

需知在无环连接$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$中，超边$\mathcal{E}$可组织为连接树$\mathcal{T}$，使得对于每个属性$x \in  \mathcal{V}$，对应${\mathcal{E}}_{x}$的节点在$\mathcal{T}$中相互连通。给定该连接树$\mathcal{T}$后，本算法递归地将连接分解为多个部分，并对每部分采用不同的连接策略。

We start from an internal node of $\mathcal{T}$ whose children are all leaves. Let this node be ${e}_{0}$ ,which has $k$ leaf children ${e}_{1},\cdots ,{e}_{k}$ (see Figure 4 for an example). Let ${s}_{i} = {e}_{0} \cap  {e}_{i}$ be the set of join attributes between ${e}_{0}$ and ${e}_{i}$ . We will assume ${s}_{i} \neq  \varnothing$ ; otherwise we can add a dummy attribute to both ${e}_{0}$ and ${e}_{i}$ and all tuples in $R\left( {e}_{0}\right)$ and $R\left( {e}_{i}\right)$ share the same value on this dummy attribute (e.g.,we add a dummy attribute ${H}^{\prime }$ to both ${e}_{0}$ and ${e}_{6}$ in Figure 4). Note that the join tree ensures the property that if $x \in  {e}_{i} \cap  {e}_{j}$ for $i \neq  j$ ,then $x \in  {e}_{0}$ .

我们从$\mathcal{T}$的某个内部节点出发，其子节点均为叶节点。设该节点为${e}_{0}$，拥有$k$个叶节点子元素${e}_{1},\cdots ,{e}_{k}$（示例见图4）。令${s}_{i} = {e}_{0} \cap  {e}_{i}$表示${e}_{0}$与${e}_{i}$间的连接属性集合。假设${s}_{i} \neq  \varnothing$；否则可向${e}_{0}$和${e}_{i}$添加虚拟属性，且$R\left( {e}_{0}\right)$和$R\left( {e}_{i}\right)$中所有元组在此虚拟属性上取值相同（例如图4中向${e}_{0}$和${e}_{6}$添加虚拟属性${H}^{\prime }$）。注意连接树需满足：若$i \neq  j$满足$x \in  {e}_{i} \cap  {e}_{j}$，则$x \in  {e}_{0}$。

Let ${N}_{\alpha } = \mathop{\sum }\limits_{{i = 1}}^{k}\left| {R\left( {e}_{i}\right) }\right|$ and ${N}_{\beta } = \mathrm{{IN}} - {N}_{\alpha }$ . We will actually prove a slightly tighter bound, that the load of our algorithm is bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ .

设${N}_{\alpha } = \mathop{\sum }\limits_{{i = 1}}^{k}\left| {R\left( {e}_{i}\right) }\right|$与${N}_{\beta } = \mathrm{{IN}} - {N}_{\alpha }$。实际上我们将证明一个更紧的界：算法负载受限于$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。

Set $\tau  = \sqrt{\frac{\mathrm{{OUT}}}{{N}_{\beta }}}$ . Our algorithm proceeds in three steps.

设定$\tau  = \sqrt{\frac{\mathrm{{OUT}}}{{N}_{\beta }}}$。算法执行分为三步。

Step (1): Computing data statistics. In each relation $R\left( {e}_{i}\right)$ , $i = 1,\ldots ,k$ ,let $v$ be an assignment of values for attributes ${s}_{i}$ . The set of heavy assignments in $R\left( {e}_{i}\right)$ is

步骤(1)：计算数据统计量。在每个关系$R\left( {e}_{i}\right)$中，$i = 1,\ldots ,k$表示属性${s}_{i}$的赋值组合。$R\left( {e}_{i}\right)$中的高频赋值集合定义为

$$
H\left( {{s}_{i},{e}_{i}}\right)  = \left\{  {v \in  {\pi }_{{s}_{i}}R\left( {e}_{i}\right)  : \left| {{\sigma }_{{s}_{i} = v}R\left( {e}_{i}\right) }\right|  \geq  \tau }\right\}  .
$$

Tuples in $R\left( {e}_{i}\right)$ can also be identified as heavy or light,depending on their projection on attributes ${s}_{i}$ . More precisely, a tuple $t \in  R\left( {e}_{i}\right)$ is heavy if ${\pi }_{{s}_{i}}t \in  H\left( {{s}_{i},{e}_{i}}\right)$ . The set of heavy tuples and light tuples in $R\left( {e}_{i}\right)$ are denoted as ${R}_{H}\left( {e}_{i}\right)$ and ${R}_{L}\left( {e}_{i}\right)$ ,respectively. All the statistics can be computed in by the sum-by-key and multi-search primitives with linear load.

在$R\left( {e}_{i}\right)$中的元组可根据其在属性${s}_{i}$上的投影被标识为重型或轻型。具体而言，若满足条件${\pi }_{{s}_{i}}t \in  H\left( {{s}_{i},{e}_{i}}\right)$，则元组$t \in  R\left( {e}_{i}\right)$为重型。$R\left( {e}_{i}\right)$中重型元组与轻型元组集合分别记为${R}_{H}\left( {e}_{i}\right)$和${R}_{L}\left( {e}_{i}\right)$。所有统计量均可通过键值求和及多路搜索原语以线性负载计算得出。

Let $\overline{\mathcal{E}} = \mathcal{E} - \left\{  {{e}_{0},{e}_{1},\cdots ,{e}_{k}}\right\}$ . We decompose the join into the following sub-joins:

设$\overline{\mathcal{E}} = \mathcal{E} - \left\{  {{e}_{0},{e}_{1},\cdots ,{e}_{k}}\right\}$。我们将连接操作分解为以下子连接：

$$
R\left( {e}_{0}\right)  \bowtie  {R}_{?}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{?}\left( {e}_{k}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right) ,
$$

where each ? can be either $H$ or $L$ . Note that there are ${2}^{k}$ , which is a constant,sub-joins,so we can afford to use $p$ servers for each sub-join. If a sub-join involves at least one ${R}_{H}\left( {e}_{i}\right)$ ,we apply the procedure in step (2) to it. In step (3), we handle the case where all? are $L$ .

其中每个?可为$H$或$L$。注意存在${2}^{k}$个（此为常量）子连接，因此可为每个子连接分配$p$台服务器。若子连接涉及至少一个${R}_{H}\left( {e}_{i}\right)$，则对其应用步骤(2)的流程。步骤(3)处理所有?均为$L$的情况。

Step (2): Sub-joins with at least one ${R}_{H}\left( {e}_{i}\right)$ . Without loss of generality,suppose ${R}_{H}\left( {e}_{1}\right)$ is in the sub-join,i.e.,we need to compute the sub-join

步骤(2)：含至少一个${R}_{H}\left( {e}_{i}\right)$的子连接。不失一般性，假设${R}_{H}\left( {e}_{1}\right)$参与子连接，即需计算如下子连接：

$$
R\left( {e}_{0}\right)  \bowtie  {R}_{H}\left( {e}_{1}\right)  \bowtie  {R}_{?}\left( {e}_{2}\right)  \bowtie  \cdots  \bowtie  {R}_{?}\left( {e}_{k}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right) ,
$$

where each ? can be either $H$ or $L$ . The algorithm consists of three steps:

其中每个?可为$H$或$L$。算法包含三个步骤：

(2.1) Compute ${R}^{\prime }\left( {e}_{0}\right)  = R\left( {e}_{0}\right)  \ltimes  {R}_{H}\left( {e}_{1}\right)$ .

(2.1) 计算${R}^{\prime }\left( {e}_{0}\right)  = R\left( {e}_{0}\right)  \ltimes  {R}_{H}\left( {e}_{1}\right)$

(2.2) Compute ${R}^{\prime } = {R}^{\prime }\left( {e}_{0}\right)  \bowtie  {R}_{?}\left( {e}_{2}\right)  \bowtie  \cdots  \bowtie  {R}_{?}\left( {e}_{k}\right)  \bowtie$ $\left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$ by any order.

(2.2) 按任意顺序计算${R}^{\prime } = {R}^{\prime }\left( {e}_{0}\right)  \bowtie  {R}_{?}\left( {e}_{2}\right)  \bowtie  \cdots  \bowtie  {R}_{?}\left( {e}_{k}\right)  \bowtie$$\left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$

(2.3) Compute ${R}_{H}\left( {e}_{1}\right)  \bowtie  {R}^{\prime }$ .

(2.3) 计算${R}_{H}\left( {e}_{1}\right)  \bowtie  {R}^{\prime }$

We analyze the load in each step: (2.1) is a primitive operation that incurs linear load. To bound the load of (2.2), observe that $\left| {R}^{\prime }\right|  \leq  \frac{\text{ OUT }}{\tau }$ ,since each tuple in ${R}^{\prime }$ joins with at least $\tau$ tuples in ${R}_{H}\left( {e}_{1}\right)$ ,each producing one final join result. Thus,the load is bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau }}\right)$ . The binary join in (2.3) has input size $\frac{\mathrm{{OUT}}}{\tau } + \mathrm{{IN}}$ and output size $\mathrm{{OUT}}$ ,incurring a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ ,which dominates the first two steps. Plugging in the value of $\tau$ ,the total load is bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ ,as desired.

我们分析各步骤负载：(2.1)作为原语操作产生线性负载。为界定(2.2)的负载，注意到$\left| {R}^{\prime }\right|  \leq  \frac{\text{ OUT }}{\tau }$——因${R}^{\prime }$中每个元组至少与${R}_{H}\left( {e}_{1}\right)$中$\tau$个元组连接，每个连接生成一个最终结果。故负载上限为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau }}\right)$。(2.3)的二元连接输入规模$\frac{\mathrm{{OUT}}}{\tau } + \mathrm{{IN}}$、输出规模$\mathrm{{OUT}}$，产生$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$负载（主导前两步）。代入$\tau$值后，总负载如预期不超过$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。

Step (3): The sub-join with all ${R}_{L}\left( {e}_{i}\right)$ . It remains to compute the following sub-join:

步骤(3): 包含所有${R}_{L}\left( {e}_{i}\right)$的子连接。仍需计算以下子连接：

$$
R\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{L}\left( {e}_{k}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right) .
$$

We further divide $R\left( {e}_{0}\right)$ into heavy and light tuples,as follows. Let $s = {s}_{1} \cup  {s}_{2} \cup  \cdots  \cup  {s}_{k}$ ,and let $v$ be an assignment over attributes $s$ . The set of heavy assignments in $R\left( {e}_{0}\right)$ is define as

我们将$R\left( {e}_{0}\right)$进一步划分为重元组和轻元组，具体如下。设$s = {s}_{1} \cup  {s}_{2} \cup  \cdots  \cup  {s}_{k}$，并令$v$为属性$s$上的赋值。定义$R\left( {e}_{0}\right)$中的重赋值集合为

$$
H\left( {s,{e}_{0}}\right)  = \left\{  {v \in  {\pi }_{s}R\left( {e}_{0}\right)  : \mathop{\prod }\limits_{{i = 1}}^{k}\left| {{\sigma }_{{s}_{i} = {\pi }_{{s}_{i}}v}{R}_{L}\left( {e}_{i}\right) }\right|  \geq  \tau }\right\}  .
$$

Tuples in $R\left( {e}_{0}\right)$ are classified as heavy or light,depending on their projection on attributes $s$ ,i.e.,a tuple $t \in  R\left( {e}_{0}\right)$ is heavy if ${\pi }_{s}t \in  H\left( {s,{e}_{0}}\right)$ ,and light otherwise. Similarly,denote the heavy and light tuples in $R\left( {e}_{0}\right)$ as ${R}_{H}\left( {e}_{0}\right)$ and ${R}_{L}\left( {e}_{0}\right)$ , respectively.

$R\left( {e}_{0}\right)$中的元组根据其在属性$s$上的投影被分类为重或轻，即元组$t \in  R\left( {e}_{0}\right)$若满足${\pi }_{s}t \in  H\left( {s,{e}_{0}}\right)$则为重，否则为轻。类似地，将$R\left( {e}_{0}\right)$中的重元组和轻元组分别记为${R}_{H}\left( {e}_{0}\right)$和${R}_{L}\left( {e}_{0}\right)$。

These statistics can also be computed using the primitives,but with some more care. For each relation ${R}_{L}\left( {e}_{i}\right)$ , we first use sum-by-key to compute $\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right|$ for every ${v}_{i} \in  {\pi }_{{s}_{i}}{R}_{L}\left( {e}_{i}\right)$ . This gives us a list of $\left( {{v}_{i},\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right| }\right)$ pairs. Then,we use multi-search to find,for each tuple $t \in  R\left( {e}_{0}\right)$ , the up to $k$ pairs $\left( {{v}_{i},\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right| }\right)$ such that ${\sigma }_{{s}_{i}}t = {v}_{i}$ . After this step,each tuple $t \in  R\left( {e}_{0}\right)$ is attached with $k$ values,and we multiply them together to decide if $t$ is heavy or light.

这些统计量也可通过原语计算，但需更谨慎处理。对每个关系${R}_{L}\left( {e}_{i}\right)$，我们首先使用键值求和计算每个${v}_{i} \in  {\pi }_{{s}_{i}}{R}_{L}\left( {e}_{i}\right)$对应的$\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right|$。这将生成$\left( {{v}_{i},\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right| }\right)$对的列表。随后通过多重搜索，为每个元组$t \in  R\left( {e}_{0}\right)$查找最多$k$个满足${\sigma }_{{s}_{i}}t = {v}_{i}$的$\left( {{v}_{i},\left| {{\sigma }_{{s}_{i} = {v}_{i}}{R}_{L}\left( {e}_{i}\right) }\right| }\right)$对。此步骤后，每个元组$t \in  R\left( {e}_{0}\right)$将关联$k$个值，我们将它们相乘以判定$t$属于重或轻。

Step (3.1): The sub-join with ${R}_{H}\left( {e}_{0}\right)$ . We first compute the following sub-join:

步骤(3.1): 与${R}_{H}\left( {e}_{0}\right)$的子连接。首先计算以下子连接：

$$
{R}_{H}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{L}\left( {e}_{k}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right) .
$$

The algorithm consists of three steps:

算法包含三个步骤：

(3.1.1) Compute ${R}^{\prime }\left( {e}_{0}\right)  = {R}_{H}\left( {e}_{0}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$ by any order.

(3.1.1) 按任意顺序计算${R}^{\prime }\left( {e}_{0}\right)  = {R}_{H}\left( {e}_{0}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$

(3.1.2) Compute ${R}^{\prime }\left( {e}_{i}\right)  = {R}_{H}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{i}\right)$ for each $i = 1,\cdots ,k$ .

(3.1.2) 为每个$i = 1,\cdots ,k$计算${R}^{\prime }\left( {e}_{i}\right)  = {R}_{H}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{i}\right)$

(3.1.3) Compute ${R}^{\prime }\left( {e}_{0}\right)  \bowtie  {R}^{\prime }\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}^{\prime }\left( {e}_{k}\right)$ . Note that each of these relations contains all attributes in ${e}_{0}$ ,so it is a hierarchical join (it is actually tall-flat), so we can use the instance-optimal algorithm in Section 3 to compute this join.

(3.1.3) 计算${R}^{\prime }\left( {e}_{0}\right)  \bowtie  {R}^{\prime }\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}^{\prime }\left( {e}_{k}\right)$。注意这些关系均包含${e}_{0}$的所有属性，因此属于分层连接（实际为高平型连接），可采用第3节的实例最优算法进行计算。

Now we analyze the load of each step: First, observe that $\left| {{R}^{\prime }\left( {e}_{0}\right) }\right|  \leq  \frac{\text{ OUT }}{\tau }$ . This is because the projection of each tuple in ${R}^{\prime }\left( {e}_{0}\right)$ on $s$ is a heavy assignment,so it will produce at least $\tau$ join results after joining with the ${R}_{L}\left( {e}_{i}\right)$ ’s. Therefore,the load of computing the join in (3.1.1) is $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau }}\right)$ . Each binary join in (3.1.2) has a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ . Note that each join result ${R}^{\prime }\left( {e}_{i}\right)$ has size bounded by ${N}_{\beta } \cdot  \tau$ ,since any tuple in $R\left( {e}_{0}\right)$ can join with at most $\tau$ tuples in ${R}_{L}\left( {e}_{i}\right)$ . Thus,the hierarchical join in (3.1.3) has input size $O\left( {{N}_{\beta } \cdot  \tau  + \frac{\mathrm{{OUT}}}{\tau }}\right)$ and output size OUT, so the instance-optimal algorithm has load $O\left( {\frac{{N}_{\beta } \cdot  \tau }{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ according to Corollary 3.5. All the loads are bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ ,as desired.

现在分析各步骤的计算负载：首先观察到$\left| {{R}^{\prime }\left( {e}_{0}\right) }\right|  \leq  \frac{\text{ OUT }}{\tau }$，这是因为${R}^{\prime }\left( {e}_{0}\right)$中每个元组在$s$上的投影属于重度赋值，因此与${R}_{L}\left( {e}_{i}\right)$连接后至少会产生$\tau$个连接结果。因此，(3.1.1)中连接计算的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau }}\right)$。(3.1.2)中每个二元连接的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。注意每个连接结果${R}^{\prime }\left( {e}_{i}\right)$的大小受限于${N}_{\beta } \cdot  \tau$，因为$R\left( {e}_{0}\right)$中的任意元组最多只能与${R}_{L}\left( {e}_{i}\right)$中的$\tau$个元组连接。因此，(3.1.3)中的分层连接输入规模为$O\left( {{N}_{\beta } \cdot  \tau  + \frac{\mathrm{{OUT}}}{\tau }}\right)$，输出规模为OUT，根据推论3.5，实例最优算法的负载为$O\left( {\frac{{N}_{\beta } \cdot  \tau }{p} + \frac{\mathrm{{OUT}}}{p \cdot  \tau } + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。所有负载均不超过$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$，符合预期。

Step (3.2): The sub-join with ${R}_{L}\left( {e}_{0}\right)$ . Finally,we are left with the sub-join

步骤(3.2)：与${R}_{L}\left( {e}_{0}\right)$的子连接。最后剩余的子连接为

$$
{R}_{L}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{L}\left( {e}_{k}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right) .
$$

This is actually the only case where we need recursion:

这是唯一需要递归处理的情形：

(3.2.1) Compute ${R}_{L}^{\prime }\left( {e}_{0}\right)  = {R}_{L}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{L}\left( {e}_{k}\right)$ by any order.

(3.2.1) 按任意顺序计算${R}_{L}^{\prime }\left( {e}_{0}\right)  = {R}_{L}\left( {e}_{0}\right)  \bowtie  {R}_{L}\left( {e}_{1}\right)  \bowtie  \cdots  \bowtie  {R}_{L}\left( {e}_{k}\right)$

(3.2.2) If $\overline{\mathcal{E}} \neq  \varnothing$ ,compute ${R}_{L}^{\prime }\left( {e}_{0}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$ recursively.

(3.2.2) 若$\overline{\mathcal{E}} \neq  \varnothing$，则递归计算${R}_{L}^{\prime }\left( {e}_{0}\right)  \bowtie  \left( {{ \bowtie  }_{e \in  \overline{\mathcal{E}}}R\left( e\right) }\right)$

Now we analyze the load: First,we have $\left| {{R}_{L}^{\prime }\left( {e}_{0}\right) }\right|  \leq  {N}_{\beta } \cdot  \tau$ , since the projection of each tuple in ${R}_{L}\left( {e}_{0}\right)$ on $s$ is a light assignment. Thus,the load of step (3.2.1) is $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{{N}_{\beta } \cdot  \tau }{p}}\right)$ , which is also bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ . So far, we have completed the base case of the induction proof.

现在分析负载：首先得到$\left| {{R}_{L}^{\prime }\left( {e}_{0}\right) }\right|  \leq  {N}_{\beta } \cdot  \tau$，因为${R}_{L}\left( {e}_{0}\right)$中每个元组在$s$上的投影属于轻度赋值。因此步骤(3.2.1)的负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{{N}_{\beta } \cdot  \tau }{p}}\right)$，该值同样受限于$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。至此已完成归纳证明的基础步骤。

For the join to be computed recursively in step (3.2.2), its input size is at most $\mathrm{{IN}} + {N}_{\beta } \cdot  \tau$ and output size is at most OUT. More importantly, ${N}_{\beta }$ can only become smaller, since ${e}_{0}$ becomes a leaf in the residual join and $\left| {R\left( {e}_{0}\right) }\right|$ is no longer included in ${N}_{\beta }$ ,no matter which node in the residual join is picked to be its new ${e}_{0}$ . By the induction hypothesis, computing the residual join recursively incurs a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{{N}_{\beta } \cdot  \tau }{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ ,thus bounded by $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ .

为了在步骤(3.2.2)中递归计算连接操作，其输入大小最多为$\mathrm{{IN}} + {N}_{\beta } \cdot  \tau$，输出大小最多为OUT。更重要的是，${N}_{\beta }$只会变得更小，因为${e}_{0}$在剩余连接中成为叶子节点，且无论选择剩余连接中的哪个节点作为新的${e}_{0}$，$\left| {R\left( {e}_{0}\right) }\right|$都不再包含在${N}_{\beta }$中。根据归纳假设，递归计算剩余连接会产生$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{{N}_{\beta } \cdot  \tau }{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$的负载，因此受限于$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$。

Note that the recursion will increase the constant in the big-Oh, but as the recursion depth depends only on the query not the data size, it does not change the asymptotic result.

注意递归会增加大O表示法中的常数项，但由于递归深度仅取决于查询而非数据规模，这不会改变渐近结果。

This completes the induction proof that the algorithm has a load of $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ . Observing that ${N}_{\beta } \leq  \mathrm{{IN}}$ and $\sqrt{\frac{\mathrm{{OUT}}}{p}} \leq  \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}$ ,we obtain the following result.

至此完成了归纳证明，表明该算法具有$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{{N}_{\beta } \cdot  \mathrm{{OUT}}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$的负载。观察到${N}_{\beta } \leq  \mathrm{{IN}}$和$\sqrt{\frac{\mathrm{{OUT}}}{p}} \leq  \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}$，我们得到以下结论。

THEOREM 5.1. There is an algorithm that computes any acyclic join in $O\left( 1\right)$ rounds with load $O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$ .

定理5.1. 存在一种算法可在$O\left( 1\right)$轮次内计算任何无环连接，其负载为$O\left( {\frac{\mathrm{{IN}}}{p} + \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}}\right)$。

### 5.2 Lower bound

### 5.2 下界

In Section 4.2 we have constructed a hard instance for the line-3 join and have shown that any algorithm must incur a load of $\Omega \left( {\min \left\{  {\frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p \cdot  \log \mathrm{{IN}}},\frac{\mathrm{{IN}}}{\sqrt{p}}}\right\}  }\right)$ on this instance. In this section, we generalize this lower bound to an arbitrary acyclic join that is not r-hierarchical. Note that for r-hierarchical joins,we can achieve a smaller load $O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$ (see the full version [18]), so this establishes a separation between r-hierarchical joins and acyclic joins.

在4.2节中，我们为line-3连接构造了一个困难实例，并证明任何算法在该实例上必须承受$\Omega \left( {\min \left\{  {\frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p \cdot  \log \mathrm{{IN}}},\frac{\mathrm{{IN}}}{\sqrt{p}}}\right\}  }\right)$的负载。本节我们将这个下界推广到任意非r-层次的无环连接。需要注意的是，对于r-层次连接，我们可以实现更小的负载$O\left( {\frac{\mathrm{{IN}}}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right)$（参见完整版本[18]），这确立了r-层次连接与无环连接之间的分离。

The basic idea in the lower bound is that any acyclic join must "include" a line-3 join, such that any algorithm computing the acyclic join must also compute the line-3 join. This is more formally captured by the following structural lemma on acyclic and r-hierarchical joins. To state the lemma, we need some terminology. In a hypergraph $Q = \left( {\mathcal{V},\mathcal{E}}\right)$ ,a path between $x,y \in  \mathcal{V}$ ,denoted $P\left( {x,y}\right)$ ,is a sequence of vertices starting with $x$ and ending with $y$ ,such that each consecutive pair of vertices appear together in an edge. The length of a path is defined as the number of vertices in $P\left( {x,y}\right)$ minus 1 . A path $P\left( {x,y}\right)$ is minimal if there is no other path ${P}^{\prime }\left( {x,y}\right)$ that is a strict subsequence of $P\left( {x,y}\right)$ . It is easy to see that $P\left( {{x}_{1},{x}_{k}}\right)  = \left( {{x}_{1},{x}_{2},\cdots ,{x}_{k}}\right)$ is minimal if and only if there exists no edge $e \in  \mathcal{E}$ containing ${x}_{i}$ and ${x}_{j}$ with $\left| {j - i}\right|  > 1$ . Note that a shortest path must be minimal, but not vice versa.

下界的基本思想是，任何无环连接都必须"包含"一个线-3连接，因此计算该无环连接的算法也必须计算线-3连接。这可以通过以下关于无环连接与r-层次连接的结构性引理更形式化地表述。在陈述引理前，我们需要定义一些术语。在超图$Q = \left( {\mathcal{V},\mathcal{E}}\right)$中，顶点$x,y \in  \mathcal{V}$之间的路径（记作$P\left( {x,y}\right)$）是指以$x$起始、$y$结尾的顶点序列，其中每对相邻顶点都共同出现在某条边中。路径长度定义为$P\left( {x,y}\right)$中顶点数减1。当不存在严格子序列路径${P}^{\prime }\left( {x,y}\right)$时，称路径$P\left( {x,y}\right)$为极小路径。显然，当且仅当不存在包含${x}_{i}$和${x}_{j}$且满足$\left| {j - i}\right|  > 1$的边$e \in  \mathcal{E}$时，$P\left( {{x}_{1},{x}_{k}}\right)  = \left( {{x}_{1},{x}_{2},\cdots ,{x}_{k}}\right)$才是极小路径。需注意最短路径必定是极小的，但反之不成立。

LEMMA 5.2. An acyclic join query is not $r$ -hierarchical if and only if it has a minimal path of length 3 .

引理5.2. 一个无环连接查询不是$r$-层次连接的，当且仅当它存在长度为3的极小路径。

The proof is given in the full version [18]. With this lemma, we can extend the hard instance for the line-3 join to any acyclic but non-r-hierarchical join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ .

完整证明见文献[18]。基于该引理，我们可以将线-3连接的困难实例推广至任何无环但非r-层次连接的$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$。

Let $\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{4}}\right)$ be a minimal path of length 3 in $Q$ ,and suppose $\left\{  {{x}_{1},{x}_{2}}\right\}   \subseteq  {e}_{1},\left\{  {{x}_{2},{x}_{3}}\right\}   \subseteq  {e}_{2},\left\{  {{x}_{3},{x}_{4}}\right\}   \subseteq  {e}_{3}$ . Let $\mathcal{R} =$ $\left\{  {{R}_{1}\left( {{x}_{1},{x}_{2}}\right) ,{R}_{2}\left( {{x}_{2},{x}_{3}}\right) ,{R}_{3}\left( {{x}_{3},{x}_{4}}\right) }\right\}$ be the hard instance for the line-3 join. We construct the hard instance ${\mathcal{R}}^{\prime } = \left\{  {{R}^{\prime }\left( e\right)  : e \in  }\right.$ $\mathcal{E}\}$ for $Q$ as follows. The domain of ${x}_{i},i = 1,2,3,4$ is the same as in $\mathcal{R}$ . For any other attribute $y$ ,set $\left| {\operatorname{dom}\left( y\right) }\right|  = 1$ .

设$\left( {{x}_{1},{x}_{2},{x}_{3},{x}_{4}}\right)$是$Q$中长度为3的极小路径，且假定$\left\{  {{x}_{1},{x}_{2}}\right\}   \subseteq  {e}_{1},\left\{  {{x}_{2},{x}_{3}}\right\}   \subseteq  {e}_{2},\left\{  {{x}_{3},{x}_{4}}\right\}   \subseteq  {e}_{3}$。令$\mathcal{R} =$$\left\{  {{R}_{1}\left( {{x}_{1},{x}_{2}}\right) ,{R}_{2}\left( {{x}_{2},{x}_{3}}\right) ,{R}_{3}\left( {{x}_{3},{x}_{4}}\right) }\right\}$为线-3连接的困难实例。我们按如下方式构造$Q$的困难实例${\mathcal{R}}^{\prime } = \left\{  {{R}^{\prime }\left( e\right)  : e \in  }\right.$$\mathcal{E}\}$：属性${x}_{i},i = 1,2,3,4$的域与$\mathcal{R}$中相同，其他属性$y$的域则设为$\left| {\operatorname{dom}\left( y\right) }\right|  = 1$。

Since the path is minimal,each $e \in  \mathcal{E}$ must fall into one of the following three cases:

## 6 JOIN-AGGREGATE QUERIES

## 6 连接聚合查询

We consider join-aggregate queries over annotated relations $\left\lbrack  {{14},{20}}\right\rbrack$ . Let $\left( {\mathbb{R},\oplus , \otimes  }\right)$ be a commutative semiring. Every tuple $t$ is associated with an annotation $w\left( t\right)  \in  \mathbb{R}$ . Let $Q = \left( {\mathcal{V},\mathcal{E}}\right)$ be a join hypergraph. The annotation of a join result $t \in$ $\mathcal{Q}\left( \mathcal{R}\right)$ is $w\left( t\right)  \mathrel{\text{:=}} { \otimes  }_{{t}_{e} \in  R\left( e\right) ,{\pi }_{e}t = {t}_{e},e \in  \mathcal{E}}w\left( {t}_{e}\right)$ . Let $\mathbf{y} \subseteq  \mathcal{V}$ be a set of output attributes and $\overline{\mathbf{y}} = \mathcal{V} - \mathbf{y}$ the non-output attributes. A join-aggregate query ${\mathcal{Q}}_{\mathrm{y}}\left( \mathcal{R}\right)$ asks us to compute ${ \oplus  }_{\bar{\mathrm{y}}}\mathcal{Q}\left( \mathcal{R}\right)  =$

我们研究带注解关系上的连接-聚合查询$\left\lbrack  {{14},{20}}\right\rbrack$。设$\left( {\mathbb{R},\oplus , \otimes  }\right)$为交换半环，每个元组$t$关联一个注解$w\left( t\right)  \in  \mathbb{R}$。设$Q = \left( {\mathcal{V},\mathcal{E}}\right)$为连接超图，连接结果$t \in$$\mathcal{Q}\left( \mathcal{R}\right)$的注解是$w\left( t\right)  \mathrel{\text{:=}} { \otimes  }_{{t}_{e} \in  R\left( e\right) ,{\pi }_{e}t = {t}_{e},e \in  \mathcal{E}}w\left( {t}_{e}\right)$。设$\mathbf{y} \subseteq  \mathcal{V}$为输出属性集，$\overline{\mathbf{y}} = \mathcal{V} - \mathbf{y}$为非输出属性。连接-聚合查询${\mathcal{Q}}_{\mathrm{y}}\left( \mathcal{R}\right)$要求计算${ \oplus  }_{\bar{\mathrm{y}}}\mathcal{Q}\left( \mathcal{R}\right)  =$

$$
\left\{  {\left( {{t}_{\mathrm{y}},w\left( {t}_{\mathrm{y}}\right) }\right)  : {t}_{\mathrm{y}} \in  {\pi }_{\mathrm{y}}\mathcal{Q}\left( \mathcal{R}\right) ,w\left( {t}_{\mathrm{y}}\right)  = { \oplus  }_{t \in  \mathcal{Q}\left( \mathcal{R}\right)  : {\pi }_{\mathrm{y}}t = {t}_{\mathrm{y}}}w\left( t\right) }\right\}  .
$$

In plain language, a join-aggregate query first computes the join $\mathcal{Q}\left( \mathcal{R}\right)$ and the annotation of each join result,which is the $\otimes$ -aggregate of the tuples comprising the join result. Then it partitions $Q\left( \mathcal{R}\right)$ into groups by their projection on $\mathbf{y}$ . Finally,for each group,it computes the $\oplus$ -aggregate of the annotations of the join results.

简言之，连接-聚合查询首先计算连接$\mathcal{Q}\left( \mathcal{R}\right)$及每个连接结果的注解（即组成该结果的元组的$\otimes$聚合），然后按$\mathbf{y}$上的投影将$Q\left( \mathcal{R}\right)$分组，最后计算每组内连接结果注解的$\oplus$聚合。

Many queries can be formulated as special join-aggregate queries. For example,if we take $\mathbb{R}$ to be the domain of integers, $\oplus$ to be addition, $\otimes$ to be multiplication,and set $w\left( t\right)  = 1$ for all $t$ ,then it becomes the COUNT (*) GROUP BY y query; in particular,if $\mathbf{y} = \varnothing$ ,the query computes $\left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$ .

许多查询可表述为特殊连接-聚合查询。例如取$\mathbb{R}$为整数域、$\oplus$为加法、$\otimes$为乘法，且对所有$t$设$w\left( t\right)  = 1$，则转化为COUNT(*) GROUP BY y查询；特别当$\mathbf{y} = \varnothing$时，该查询计算$\left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$。

The join-project query ${\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R}\right)$ ,also known as a conjunctive query, is a special join-aggregate query, and we extend the terminology from [5] to join-aggregate queries. A width- 1 GHD of a hypergraph $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ is a tree $\mathcal{T}$ ,where each node $u \in  \mathcal{T}$ is a subset of $\mathcal{V}$ ,such that

连接-投影查询${\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R}\right)$（又称合取查询）是特殊连接-聚合查询，我们将文献[5]的术语扩展至此类查询。超图$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$的宽度1广义超树分解是树$\mathcal{T}$，其每个节点$u \in  \mathcal{T}$是$\mathcal{V}$的子集，满足：

(1) (coherence) for each attribute $x \in  \mathcal{V}$ ,the nodes containing $x$ are connected in $\mathcal{T}$ ;

(1)（一致性）对每个属性$x \in  \mathcal{V}$，包含$x$的节点在$\mathcal{T}$中连通；

(2) (edge coverage) for each hyperedge $e \in  \mathcal{E}$ ,there exists a node $u \in  \mathcal{T}$ such that $e \subseteq  u$ ; and

(2)（边覆盖）对每条超边$e \in  \mathcal{E}$，存在节点$u \in  \mathcal{T}$使得$e \subseteq  u$；

(3) (width-1) for each node $u \in  \mathcal{T}$ ,there exists a hyper-edge $e \in  \mathcal{E}$ such that $u \subseteq  e$ .

(3)（宽度1）对每个节点$u \in  \mathcal{T}$，存在超边$e \in  \mathcal{E}$使得$u \subseteq  e$。

Given a set of output attributes $\mathbf{y}$ (a.k.a. free variables),we say that $\mathcal{T}$ is free-connex if there is a subset of connected nodes of $\mathcal{T}$ including its root,denoted as ${\mathcal{T}}^{\prime }$ (such a ${\mathcal{T}}^{\prime }$ is said to be a connex subset),such that $\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$ . A join-aggregate query ${Q}_{\mathrm{y}}$ is free-connex if it has a free-connex width-1 GHD.

给定一组输出属性$\mathbf{y}$（又称自由变量），若存在包含其根节点的$\mathcal{T}$连通节点子集（记为${\mathcal{T}}^{\prime }$，此类${\mathcal{T}}^{\prime }$称为连通子集），且满足$\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$，则称$\mathcal{T}$是自由连通的。当连接聚合查询${Q}_{\mathrm{y}}$具有自由连通的宽度1广义超树分解(GHD)时，该查询即为自由连通查询。

As preprocessing, we remove the dangling tuples and apply the reduce procedure repeatedly to remove an $e \in  \mathcal{E}$ if there is another ${e}^{\prime } \in  \mathcal{E}$ such that $e \subset  {e}^{\prime }$ . Note that while dangling tuples can be just discarded, we cannot simply discard $R\left( e\right)$ in the reduce procedure. To ensure that the annotations will be computed correctly,we should replace $R\left( {e}^{\prime }\right)$ with $R\left( e\right)  \bowtie  R\left( {e}^{\prime }\right)$ and then discard $R\left( e\right)$ . Note that by the earlier definition,the annotation of a join result is the $\otimes$ -aggregate of the annotations of tuples comprising the join result, so the annotation in $R\left( e\right)$ are aggregated into those in $R\left( {e}^{\prime }\right)$ .

预处理阶段，我们移除悬空元组并反复应用归约过程：当存在另一个${e}^{\prime } \in  \mathcal{E}$使得$e \subset  {e}^{\prime }$时，就移除$e \in  \mathcal{E}$。需注意，悬空元组可直接丢弃，但在归约过程中不能简单丢弃$R\left( e\right)$。为确保注解计算正确，应先用$R\left( e\right)  \bowtie  R\left( {e}^{\prime }\right)$替换$R\left( {e}^{\prime }\right)$再移除$R\left( e\right)$。根据先前定义，连接结果的注解是构成该结果的元组注解的$\otimes$聚合，因此$R\left( e\right)$中的注解会被聚合到$R\left( {e}^{\prime }\right)$中。

We find a free-connex width-1 GHD $\mathcal{T}$ of $\mathcal{Q}\left\lbrack  {4,5}\right\rbrack$ . Note that the nodes of $\mathcal{T}$ also define a hypergraph,and can be regarded as another join-aggregate query, but with the property that it has a free-connex subset ${\mathcal{T}}^{\prime }$ such that $\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$ . We construct an instance ${\mathcal{R}}_{\mathcal{T}} = \{ R\left( u\right)  : u \in  \mathcal{T}\}$ such that ${\mathcal{Q}}_{\mathrm{y}}\left( \mathcal{R}\right)  = \mathcal{T}\left( {\mathcal{R}}_{\mathcal{T}}\right)$ ,where $\mathcal{T}\left( {\mathcal{R}}_{\mathcal{T}}\right)$ denotes the result of running the query defined by ${\pi }_{\mathbf{y}}\mathcal{T}$ on ${\mathcal{R}}_{\mathcal{T}}$ . Observe that on a reduced $\mathcal{Q}$ ,the condition $e \subseteq  u$ in property (2) of a width-1 GHD can be replaced by $e = u$ ,since if $e \subset  u$ and $u \subseteq  {e}^{\prime }$ for some other ${e}^{\prime } \in  \mathcal{E}$ due to property (3),we would find $e \subset  {e}^{\prime }$ . This implies that $\mathcal{T}$ has only two types of nodes: (1) all hy-peredges in $\mathcal{E}$ ,and (2) nodes that are a proper subset of some $e \in  \mathcal{E}$ . Then we construct ${\mathcal{R}}_{\mathcal{T}}$ as follows. For each $u \in  \mathcal{T}$ of type (1),we set $R\left( u\right)  \mathrel{\text{:=}} R\left( e\right)$ where $e = u$ ; for each $u \in  \mathcal{T}$ of type (2),we set $R\left( u\right)  \mathrel{\text{:=}} R\left( e\right)$ for any $e \in  \mathcal{E},u \subset  e$ ,but the annotations of all tuples in $R\left( u\right)$ are set to 1 (the $\otimes$ -identity). Below,we will focus on computing $\mathcal{T}\left( {\mathcal{R}}_{\mathcal{T}}\right)$ .

我们发现一个自由连接宽度为1的广义超树分解(GHD)$\mathcal{T}$。注意$\mathcal{T}$的节点也定义了一个超图，可视为另一个连接-聚合查询，但具有自由连接子集${\mathcal{T}}^{\prime }$的特性，使得$\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$。我们构建实例${\mathcal{R}}_{\mathcal{T}} = \{ R\left( u\right)  : u \in  \mathcal{T}\}$，其中$\mathcal{T}\left( {\mathcal{R}}_{\mathcal{T}}\right)$表示在${\mathcal{R}}_{\mathcal{T}}$上运行${\pi }_{\mathbf{y}}\mathcal{T}$定义查询的结果。观察到在简化后的$\mathcal{Q}$上，宽度1 GHD属性(2)中的条件$e \subseteq  u$可替换为$e = u$，因为若由于属性(3)存在$e \subset  u$和$u \subseteq  {e}^{\prime }$，我们将发现$e \subset  {e}^{\prime }$。这意味着$\mathcal{T}$仅包含两类节点：(1)$\mathcal{E}$中所有超边，(2)某些$e \in  \mathcal{E}$的真子集节点。随后我们如下构建${\mathcal{R}}_{\mathcal{T}}$：对类型(1)的每个$u \in  \mathcal{T}$，设$R\left( u\right)  \mathrel{\text{:=}} R\left( e\right)$其中$e = u$；对类型(2)的每个$u \in  \mathcal{T}$，为任意$e \in  \mathcal{E},u \subset  e$设$R\left( u\right)  \mathrel{\text{:=}} R\left( e\right)$，但$R\left( u\right)$中所有元组的注释设为1($\otimes$恒等)。下文将聚焦于计算$\mathcal{T}\left( {\mathcal{R}}_{\mathcal{T}}\right)$。

此外，若${\mathcal{T}}^{\prime }$是r-层次结构的，我们运行实例最优算法计算${\mathcal{T}}^{\prime }\left( {\mathcal{R}}_{{\mathcal{T}}^{\prime }}\right)$。实际上，我们可以精确定义具有r-层次结构${\mathcal{T}}^{\prime }$的查询类。若查询是自由连接且移除所有非输出属性后的剩余查询为r-层次结构，则称其为外层次查询。我们在完整版[18]中给出了以下结果的证明。

LEMMA 6.4. A join-aggregate query ${Q}_{\mathrm{y}}$ is out-hierarchical if and only if it has a width-1 GHD $\mathcal{T}$ with a connex subset ${\mathcal{T}}^{\prime }$ such that $\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$ and ${\mathcal{T}}^{\prime }$ is $r$ -hierarchical.

引理6.4. 当且仅当聚合查询${Q}_{\mathrm{y}}$存在宽度为1的广义超树分解$\mathcal{T}$，且其连接子集${\mathcal{T}}^{\prime }$满足$\mathbf{y} = \mathop{\bigcup }\limits_{{u \in  {\mathcal{T}}^{\prime }}}u$同时${\mathcal{T}}^{\prime }$是$r$-层次结构时，该查询为外层次查询。

THEOREM 6.5. For out-hierarchical query ${Q}_{\mathrm{y}}$ and any instance $\mathcal{R}$ ,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R},\mathbf{y}}\right) }\right)$ .

定理6.5. 对于外层次查询${Q}_{\mathrm{y}}$和任意实例$\mathcal{R}$，存在算法可在$O\left( 1\right)$轮次内以$O\left( {\frac{\mathrm{{IN}}}{p} + {L}_{\text{instance }}\left( {p,\mathcal{R},\mathbf{y}}\right) }\right)$负载完成计算。

Note that the instance-optimal lower bound ${L}_{\text{instance }}$ for a join-aggregate query is defined with respect to the output attributes only,i.e., ${L}_{\text{instance }}\left( {p,\mathcal{R},\mathbf{y}}\right)  \mathrel{\text{:=}} \mathop{\max }\limits_{{S \subseteq  \mathcal{E}}}{\left( \frac{\left| {\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R},S\right) \right| }{p}\right) }^{\frac{1}{\left| S\right| }}$ , where ${\pi }_{\mathbf{y}}\mathcal{Q}\left( {\mathcal{R},S}\right)  = {\pi }_{\mathbf{y}}\left( {\left( {{ \bowtie  }_{e \in  S}R\left( e\right) }\right)  \ltimes  \mathcal{Q}\left( \mathcal{R}\right) }\right)$ .

请注意，连接聚合查询的实例最优下界${L}_{\text{instance }}$仅针对输出属性定义，即${L}_{\text{instance }}\left( {p,\mathcal{R},\mathbf{y}}\right)  \mathrel{\text{:=}} \mathop{\max }\limits_{{S \subseteq  \mathcal{E}}}{\left( \frac{\left| {\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R},S\right) \right| }{p}\right) }^{\frac{1}{\left| S\right| }}$，其中${\pi }_{\mathbf{y}}\mathcal{Q}\left( {\mathcal{R},S}\right)  = {\pi }_{\mathbf{y}}\left( {\left( {{ \bowtie  }_{e \in  S}R\left( e\right) }\right)  \ltimes  \mathcal{Q}\left( \mathcal{R}\right) }\right)$。

## 7 A LOWER BOUND ON TRIANGLE JOIN

## 7 三角形连接的下界

Finally, we look beyond acyclic joins. In particular, we give an output-sensitive lower bound on the triangle join ${Q}_{\bigtriangleup } =$ ${R}_{1}\left( {B,C}\right)  \bowtie  {R}_{2}\left( {A,C}\right)  \bowtie  {R}_{3}\left( {A,B}\right)$ . For ${Q}_{ \bigtriangleup  }$ ,a worst-case lower bound of $\Omega \left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$ is known,by the following argument: $\mathrm{A}$ server loading $L$ tuples can emit at most $O\left( {L}^{3/2}\right)$ join results by the AGM bound [3],while the join size of ${Q}_{ \bigtriangleup  }$ can be as large as $\Omega \left( {\mathrm{{IN}}}^{3/2}\right)$ . Then setting $p \cdot  {L}^{3/2} = \Omega \left( {\mathrm{{IN}}}^{3/2}\right)$ yields this lower bound. However, if OUT is used as a parameter, this argument only leads to a lower bound of $\Omega \left( {\left( \frac{\mathrm{{OUT}}1}{p}\right) }^{2/3}\right)$ . Below, we improve this lower bound to the following:

最后，我们探讨非循环连接之外的情形。特别地，我们给出了三角形连接${Q}_{\bigtriangleup } =$${R}_{1}\left( {B,C}\right)  \bowtie  {R}_{2}\left( {A,C}\right)  \bowtie  {R}_{3}\left( {A,B}\right)$的输出敏感下界。对于${Q}_{ \bigtriangleup  }$，已知最坏情况下界为$\Omega \left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$，论证如下：根据AGM界[3]，加载$L$元组的服务器最多只能生成$O\left( {L}^{3/2}\right)$个连接结果，而${Q}_{ \bigtriangleup  }$的连接结果集可能达到$\Omega \left( {\mathrm{{IN}}}^{3/2}\right)$的规模。设$p \cdot  {L}^{3/2} = \Omega \left( {\mathrm{{IN}}}^{3/2}\right)$即可得到该下界。但若以OUT作为参数，此论证仅能推导出$\Omega \left( {\left( \frac{\mathrm{{OUT}}1}{p}\right) }^{2/3}\right)$的下界。下文我们将该下界改进为：

THEOREM 7.1. For any $\mathrm{{IN}}/{\log }^{2}\mathrm{{IN}} \geq  3{p}^{3}$ ,OUT,there exists an instance $\mathcal{R}$ for ${Q}_{ \bigtriangleup  }$ with input size $\Theta \left( \mathrm{{IN}}\right)$ and output size $\Theta$ (OUT) such that any tuple-based algorithm computing it in $O\left( 1\right)$ rounds must have a load of $\Omega \left( {\min \left\{  {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p\log N},\frac{\mathrm{{IN}}}{{p}^{2/3}}}\right\}  }\right)$ .

定理7.1. 对于任意$\mathrm{{IN}}/{\log }^{2}\mathrm{{IN}} \geq  3{p}^{3}$、OUT，存在${Q}_{ \bigtriangleup  }$的实例$\mathcal{R}$，其输入规模为$\Theta \left( \mathrm{{IN}}\right)$且输出规模为$\Theta$(OUT)，使得任何基于元组的算法在$O\left( 1\right)$轮次内计算该实例时，必须具有$\Omega \left( {\min \left\{  {\frac{\mathrm{{IN}}}{p} + \frac{\mathrm{{OUT}}}{p\log N},\frac{\mathrm{{IN}}}{{p}^{2/3}}}\right\}  }\right)$的负载。

The proof, given in the full version [18], is quite technical,but the intuition is simple: When $\mathrm{{OUT}} = \Theta \left( {\mathrm{{IN}}}^{3/2}\right)$ ,the triangles are "dense" enough, so a server can achieve the maximum efficiency and emit $\Theta \left( {L}^{3/2}\right)$ triangles. However, for small OUT, we can construct an instance in which the triangles are "sparse" so that a server cannot be as efficient. In fact, an instance constructed randomly (in a certain way) would have this property with high probability.

完整版本[18]中给出的证明技术性较强，但其核心思想很简单：当$\mathrm{{OUT}} = \Theta \left( {\mathrm{{IN}}}^{3/2}\right)$时，三角形足够"稠密"，服务器可实现最高效率并输出$\Theta \left( {L}^{3/2}\right)$个三角形。然而对于较小的OUT值，我们可以构造三角形"稀疏"的实例，使得服务器无法保持高效。事实上，以特定方式随机构造的实例大概率会具备该特性。

Our lower bound has the following consequences:

我们的下界结果具有以下推论：

(1) When OUT $\geq$ IN $\cdot  {p}^{1/3}$ ,the lower bound becomes $\widetilde{\Omega }\left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$ ,which means that the worst-case optimal algorithm of [23] is actually also output-optimal in this parameter range. Finding $\widetilde{\Omega }\left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$ triangles is as difficult as finding $\Theta \left( {\mathrm{{IN}}}^{3/2}\right)$ triangles.

(1) 当OUT$\geq$IN$\cdot  {p}^{1/3}$时，下界变为$\widetilde{\Omega }\left( \frac{\mathrm{{IN}}}{{p}^{2/3}}\right)$，这意味着[23]的最坏情况最优算法在此参数范围内同时也是输出最优的。寻找$\widetilde{\Omega }\left( {\mathrm{{IN}} \cdot  {p}^{1/3}}\right)$个三角形与寻找$\Theta \left( {\mathrm{{IN}}}^{3/2}\right)$个三角形难度相当。

(2) When $\mathrm{{IN}} \leq  \mathrm{{OUT}} \leq  \mathrm{{IN}} \cdot  {p}^{1/3}$ ,the lower bound becomes $\widetilde{\Omega }\left( \frac{\mathrm{{OUT}}}{p}\right)$ while we do not have a matching upper bound yet. Nevertheless, this already exhibits a separation from acyclic joins, which can be done with load $O\left( \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}\right)$ . The gap is at least $\widetilde{\Omega }\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$ .

(2) 当$\mathrm{{IN}} \leq  \mathrm{{OUT}} \leq  \mathrm{{IN}} \cdot  {p}^{1/3}$时，下界变为$\widetilde{\Omega }\left( \frac{\mathrm{{OUT}}}{p}\right)$，而我们尚未找到匹配的上界。尽管如此，这已经显示出与无环连接查询的差异——后者可在$O\left( \frac{\sqrt{\mathrm{{IN}} \cdot  \mathrm{{OUT}}}}{p}\right)$负载下完成，两者差距至少为$\widetilde{\Omega }\left( \sqrt{\frac{\mathrm{{OUT}}}{\mathrm{{IN}}}}\right)$。
