## ABSTRACT

## 摘要

In this paper, we design massively parallel algorithms for sparse matrix multiplication, as well as more general join-aggregate queries, where the join hypergraph is a tree with arbitrary output attributes. For each case, we obtain asymptotic improvement over existing algorithms. In particular, our matrix multiplication algorithm is shown to be optimal in the semiring model.

本文设计了针对稀疏矩阵乘法及更广义的连接-聚合查询的大规模并行算法，其中连接超图是具有任意输出属性的树结构。针对每种情况，我们的算法都实现了对现有算法的渐进式改进。特别地，我们证明了所提出的矩阵乘法算法在半环模型下的最优性。

## 1 INTRODUCTION

## 1 引言

Over the span of half of a century, the running time for multiplying two $U \times  U$ matrices has progressively improved from $O\left( {U}^{2.807}\right)$ [22] to $O\left( {U}^{2.373}\right)$ [20]. However,all these fast matrix multiplication algorithms rely on the algebraic properties of the ring, in particular the existence of additive inverses.

半个世纪以来，两个$U \times  U$矩阵相乘的运行时间已从$O\left( {U}^{2.807}\right)$[22]逐步优化至$O\left( {U}^{2.373}\right)$[20]。然而这些快速矩阵乘法算法都依赖于环的代数特性，特别是加法逆元的存在性。

Consider the multiplication of two matrices $\left( {a}_{ij}\right)$ and $\left( {b}_{jk}\right)$ . By treating each nonzero entry ${a}_{ij}$ as a tuple $\left( {i,j,{a}_{ij}}\right)$ (and similarly for ${b}_{ij}$ ),matrix multiplication can be written as a join-aggregate query over two relations (formal definition given below). However, join-aggregate queries posed on a relational database often have the following additional requirements: (1) The "multiplication" and "addition" operations over the matrix elements may not conform to

考虑两个矩阵$\left( {a}_{ij}\right)$与$\left( {b}_{jk}\right)$的乘法。通过将每个非零元素${a}_{ij}$视为元组$\left( {i,j,{a}_{ij}}\right)$(对${b}_{ij}$同理)，矩阵乘法可表示为两个关系上的连接-聚合查询(正式定义如下)。但关系数据库中的连接-聚合查询通常有以下额外要求：(1)矩阵元素的"乘法"与"加法"运算可能不符合

those in a ring. In general, we would like to process such queries over any semiring $\left\lbrack  {{11},{15}}\right\rbrack$ ,which does not have additive inverses. (2) The matrices, both input and output, are sparse, i.e., the number of nonzero entries can be much smaller than ${U}^{2}$ . In other words, denoting the number of nonzero entries in the input and output matrices as $N$ and OUT,respectively,we would like running times that depend on $N$ and OUT,but not $U$ . In fact,if the matrices are dense, namely $N = \Theta \left( {U}^{2}\right)$ ,then the standard $O\left( {U}^{3}\right)$ -time algorithm is already optimal under the semiring model $\left\lbrack  {{12},{21}}\right\rbrack$ . In the semiring model, the only way to create new semiring elements is by multiplying or adding existing semiring elements. Thus, as argued in $\left\lbrack  {{12},{21}}\right\rbrack$ ,the algorithm must compute all the ${U}^{3}$ elementary products, namely ${a}_{ij}{b}_{jk}$ for all $1 \leq  i,j,k \leq  U$ .

环运算性质。我们期望能在任意半环$\left\lbrack  {{11},{15}}\right\rbrack$上处理此类查询，而半环不要求存在加法逆元。(2)输入输出矩阵均为稀疏矩阵，即非零元素数量可能远小于${U}^{2}$。记输入输出矩阵的非零元素数分别为$N$和OUT，我们期望算法时间复杂度仅与$N$和OUT相关，而与$U$无关。事实上当矩阵稠密(即$N = \Theta \left( {U}^{2}\right)$)时，标准$O\left( {U}^{3}\right)$时间复杂度算法在半环模型$\left\lbrack  {{12},{21}}\right\rbrack$下已是最优解。该模型规定生成新半环元素的唯一途径是通过现有元素的乘法或加法运算，因此如$\left\lbrack  {{12},{21}}\right\rbrack$所述，算法必须计算所有${U}^{3}$个基本乘积项，即对所有$1 \leq  i,j,k \leq  U$计算${a}_{ij}{b}_{jk}$。

### 1.1 Join-aggregate queries

### 1.1 连接-聚合查询

We now formally define the class of queries studied in this paper. A (natural) join is defined as a hypergraph $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$ ,where the vertices $\mathcal{V} = \left\{  {{x}_{1},\ldots ,{x}_{m}}\right\}$ model the attributes and the hyperedges $\mathcal{E} = \left\{  {{e}_{1},\ldots ,{e}_{n}}\right\}   \subseteq  {2}^{\mathcal{V}}$ model the relations. We restrict our study to joins defined by an acyclic hypergraph where each ${e}_{i}$ consists of two attributes,i.e., $Q$ is a tree.

本文正式定义所研究的查询类别。自然连接被定义为超图$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E}}\right)$，其中顶点$\mathcal{V} = \left\{  {{x}_{1},\ldots ,{x}_{m}}\right\}$表示属性，超边$\mathcal{E} = \left\{  {{e}_{1},\ldots ,{e}_{n}}\right\}   \subseteq  {2}^{\mathcal{V}}$表示关系。我们限定研究范围为由无环超图定义的连接，其中每个${e}_{i}$仅包含两个属性，即$Q$为树状结构。

Let $\operatorname{dom}\left( x\right)$ be the domain of attribute $x \in  \mathcal{V}$ . An instance of $Q$ is a set of relations $\mathcal{R} = \left\{  {{R}_{e} : e \in  \mathcal{E}}\right\}$ . Each relation ${R}_{e}$ consists a set of tuples, where each tuple is an assignment that assigns a value from $\operatorname{dom}\left( x\right)$ to $x$ for every $x \in  e$ . The full join results of $\mathcal{Q}$ on $\mathcal{R}$ , denoted as $\mathcal{Q}\left( \mathcal{R}\right)$ ,consist of all combinations of tuples,one from each ${R}_{e}$ ,such that they share common values on their common attributes.

设$\operatorname{dom}\left( x\right)$为属性$x \in  \mathcal{V}$的域。$Q$的实例是关系集合$\mathcal{R} = \left\{  {{R}_{e} : e \in  \mathcal{E}}\right\}$。每个关系${R}_{e}$包含元组集合，其中每个元组是从$\operatorname{dom}\left( x\right)$到$x$的赋值，为每个$x \in  e$分配值。$\mathcal{Q}$在$\mathcal{R}$上的完全连接结果记为$\mathcal{Q}\left( \mathcal{R}\right)$，包含所有元组组合（每个${R}_{e}$贡献一个元组），这些元组在共有属性上具有相同值。

We consider join-aggregate queries over annotated relations $\left\lbrack  {{11},{15}}\right\rbrack$ . Let $\left( {\mathbb{R},\oplus , \otimes  }\right)$ be a commutative semiring. Every tuple $t$ is associated with an annotation $w\left( t\right)  \in  \mathbb{R}$ . The annotation of a join result $t \in  Q\left( \mathcal{R}\right)$ is

$$
w\left( t\right)  \mathrel{\text{:=}} \mathop{\prod }\limits_{{{t}^{\prime } \in  {R}_{e},{\pi }_{e}t = {t}^{\prime },e \in  \mathcal{E}}}w\left( {t}^{\prime }\right) ,
$$

where the multiplication is done using the $\otimes$ operator. 其中乘法运算采用$\otimes$算子。设$\mathbf{y} \subseteq  \mathcal{V}$为输出属性集，$\overline{\mathbf{y}} = \mathcal{V} - \mathbf{y}$为非输出属性集。连接-聚合查询${\mathcal{Q}}_{\mathbf{y}}\left( \mathcal{R}\right)$要求计算

Join-aggregate queries include many commonly seen database queries as special cases. For example, if we ignore the annotations, then it becomes a join-project query ${\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R}\right)$ ,also known as a conjunctive query. If we take $\mathbb{R}$ be the domain of integers and set $w\left( t\right)  = 1$ ,then it becomes the COUNT (*) GROUP BY y query; in particular,if $\mathbf{y} = \varnothing$ ,the query computes the full join size $\left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$ . If we take $\mathcal{V} = \{ A,B,C\}$ with $\mathbf{y} = \{ A,C\}$ ,and $\mathcal{E} = \left\{  {{e}_{1} = \{ A,B\} ,{e}_{2} = }\right.$ $\{ B,C\} \}$ ,then it degenerates to matrix multiplication.

连接-聚合查询涵盖了许多常见的数据库查询特例。例如，若忽略注解部分，则退化为连接-投影查询${\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R}\right)$（亦称合取查询）。若令$\mathbb{R}$为整数域且设定$w\left( t\right)  = 1$，则转化为COUNT(*) GROUP BY y查询；特别地，当$\mathbf{y} = \varnothing$时，该查询计算全连接规模$\left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$。若取$\mathcal{V} = \{ A,B,C\}$且$\mathbf{y} = \{ A,C\}$，同时$\mathcal{E} = \left\{  {{e}_{1} = \{ A,B\} ,{e}_{2} = }\right.$$\{ B,C\} \}$，则退化为矩阵乘法。

Let $\left\lbrack  n\right\rbrack$ stand for $\{ 1,2,\cdots ,n\}$ . We study the data complexity of algorithms,i.e., $n$ and $m$ are considered as constants.

我们用$N = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {R}_{e}\right|$表示输入规模，OUT$=$$\left| {{\pi }_{\mathbf{y}}\mathcal{Q}\left( \mathcal{R}\right) }\right|$表示输出规模。设$\left\lbrack  n\right\rbrack$代表$\{ 1,2,\cdots ,n\}$。我们研究算法的数据复杂度，即视$n$和$m$为常量。

### 1.2 The Yannakakis algorithm

### 1.2 Yannakakis算法

In the RAM model, there is essentially only one algorithm for computing such queries, known as the Yannakakis algorithm [25] dated back to 1981, which was originally designed for join-project queries. It first removes all the dangling tuples, namely tuples that will not appear in the full join results,in $O\left( N\right)$ time via a series of semijoins. Then,it picks an arbitrary attribute as the root of the query tree $Q$ , and performs joins and projections in a bottom-up fashion. Specifically,it takes two relation ${R}_{e}$ and ${R}_{{e}^{\prime }}$ such that $e$ is a leaf and ${e}^{\prime }$ is the parent of $e$ ,and replaces ${R}_{{e}^{\prime }}$ with ${\pi }_{\mathrm{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }{R}_{e} \bowtie  {R}_{{e}^{\prime }}$ ,where anc $\left( {e}^{\prime }\right)$ are the set of attributes in ${e}^{\prime }$ that appear in the ancestors of ${e}^{\prime }$ . Then ${R}_{e}$ is removed and the step repeats until only one relation remains. It has been noted that this algorithm can be easily modified to handle join-aggregate queries, by replacing the projection ${\pi }_{\mathbf{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }$ by an aggregation [15].

在RAM模型中，计算此类查询本质上只有一种算法——可追溯至1981年的Yannakakis算法[25]，该算法最初为连接-投影查询设计。它首先通过一系列半连接操作，在$O\left( N\right)$时间内移除所有悬空元组（即不会出现在全连接结果中的元组）。随后，任选一个属性作为查询树$Q$的根节点，以自底向上方式执行连接和投影操作。具体而言，算法选取两个关系${R}_{e}$和${R}_{{e}^{\prime }}$，其中$e$为叶节点且${e}^{\prime }$是$e$的父节点，将${R}_{{e}^{\prime }}$替换为${\pi }_{\mathrm{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }{R}_{e} \bowtie  {R}_{{e}^{\prime }}$（其中anc$\left( {e}^{\prime }\right)$表示${e}^{\prime }$中出现在其祖先节点的属性集合）。然后移除${R}_{e}$并重复该步骤，直至仅剩一个关系。值得注意的是，通过将投影${\pi }_{\mathbf{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }$替换为聚合操作[15]，该算法可轻松适配连接-聚合查询。

Note that when applied to matrix multiplication $\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)  \bowtie$ ${R}_{2}\left( {B,C}\right)$ ,this algorithm just computes the join $R = {R}_{1}\left( {A,B}\right)  \bowtie$ ${R}_{2}\left( {B,C}\right)$ and then does the aggregation $\mathop{\sum }\limits_{B}R$ .

需注意的是，当应用于矩阵乘法$\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)  \bowtie$${R}_{2}\left( {B,C}\right)$时，该算法仅计算连接结果$R = {R}_{1}\left( {A,B}\right)  \bowtie$${R}_{2}\left( {B,C}\right)$后再执行聚合操作$\mathop{\sum }\limits_{B}R$。

The running time of this algorithm (after dangling tuples have been removed) is proportional to the largest intermediate join size $\left| {{R}_{e} \bowtie  {R}_{{e}^{\prime }}}\right|$ . It is known that if the query is free-connex ${}^{1}$ ,then the maximum intermediate join size is $O\left( \mathrm{{OUT}}\right) \left\lbrack  {3,{15}}\right\rbrack$ . For non-free-connex queries,Yannakakis gave an upper bound of $O(N$ . OUT) in his original paper [25]. For matrix multiplication, which is the simplest non-free-connex query, this has been tightened to $O\left( {N\sqrt{\mathrm{{OUT}}}}\right) \left\lbrack  2\right\rbrack$ ,which is also shown to be optimal in the semiring model,as there are instances with $\Omega \left( {N\sqrt{\mathrm{{OUT}}}}\right)$ elementary products. This bound also extends to star queries (see Section 5 for formal definition),for which the bound becomes $O\left( {N \cdot  {\mathrm{{OUT}}}^{1 - 1/n}}\right)$ .

该算法的运行时间（在去除悬挂元组后）与最大中间连接规模$\left| {{R}_{e} \bowtie  {R}_{{e}^{\prime }}}\right|$成正比。已知若查询是自由连接（free-connex）${}^{1}$，则最大中间连接规模为$O\left( \mathrm{{OUT}}\right) \left\lbrack  {3,{15}}\right\rbrack$。对于非自由连接查询，Yannakakis在其原始论文[25]中给出了$O(N$的上界。对于最简单的非自由连接查询——矩阵乘法，该界已收紧至$O\left( {N\sqrt{\mathrm{{OUT}}}}\right) \left\lbrack  2\right\rbrack$，并在半环模型中被证明是最优的，因为存在需要$\Omega \left( {N\sqrt{\mathrm{{OUT}}}}\right)$次基本乘积的实例。该界限也适用于星型查询（正式定义见第5节），此时界限变为$O\left( {N \cdot  {\mathrm{{OUT}}}^{1 - 1/n}}\right)$。

### 1.3 Massively parallel computation

### 1.3 大规模并行计算

This paper is concerned with the Massively Parallel Computation (MPC) model $\left\lbrack  {5,6,{18},{19}}\right\rbrack$ . In the MPC model,there are $p$ servers connected by a complete communication network. Data is initially distributed across $p$ servers with each server holding $N/p$ tuples. Computation proceeds in terms of rounds. In each round, each server first receives messages from other servers (if there are any), performs some local computation, and then sends messages to other servers. The complexity of the algorithm is measured by the number of rounds and the load,denoted as $L$ ,which is the maximum message size received by any server in any round. We will only consider constant-round algorithms. In this case, whether a server is allowed to keep messages it has received from previous rounds is irrelevant: if not, it can just keep sending all these messages to itself over the rounds, increasing the load by a constant factor.

本文研究大规模并行计算（MPC）模型$\left\lbrack  {5,6,{18},{19}}\right\rbrack$。该模型包含$p$台通过全连接网络互连的服务器，数据初始分布在$p$台服务器上，每台持有$N/p$个元组。计算以轮次推进：每轮中，服务器先接收其他服务器的消息（如有），执行本地计算，再向其他服务器发送消息。算法复杂度通过轮次数量和负载（记为$L$，即单轮中任意服务器接收的最大消息量）衡量。我们仅考虑恒定轮次算法——此时服务器是否保留历史消息不影响结果，若不保留，可通过持续向自身转发消息实现，仅使负载增加常数倍。

The MPC model can be considered as a simplified version of the bulk synchronous parallel (BSP) model [24], but it has enjoyed more popularity in recent years. This is mostly because the BSP model takes too many measures into consideration, such as communication costs, local computation time, memory consumption, etc. The MPC model unifies all these costs with one parameter $L$ ,which makes the model much simpler. Meanwhile,although $L$ is defined as the maximum incoming message size of a server, it is also closely related with the local computation time and memory consumption, which are both increasing functions of $L$ . Thus, $L$ serves as a good surrogate of these other cost measures. This is also why the MPC model does not limit the outgoing message size of a server, which is less relevant to other costs.

MPC模型可视为批量同步并行（BSP）模型[24]的简化版，但近年更受青睐。主要因BSP模型需考量通信成本、本地计算时间、内存消耗等多重指标，而MPC模型用单一参数$L$统一这些成本，大幅简化模型。虽然$L$定义为服务器最大接收消息量，但其与本地计算时间及内存消耗（均为$L$的增函数）密切相关，故能有效替代其他成本指标。这也解释了为何MPC模型不限制服务器发送消息量——因其与其他成本关联较弱。

We will adopt the mild assumption $N \geq  {p}^{1 + \epsilon }$ where $\epsilon  > 0$ is any small constant. This assumption clearly holds on any reasonable values of $N$ and $p$ in practice; theoretically,this is the minimum requirement for the model to be able to compute some almost trivial functions,like the "or" of $N$ bits,in $O\left( 1\right)$ rounds [9]. When $N \geq  {p}^{1 + \epsilon }$ ,many basic operations (see Section 2.1) can be performed in $O\left( 1\right)$ rounds and $O\left( {N/p}\right)$ load,which is often called "linear load", as it is the load needed to shuffle all input data once.

我们采用$N \geq  {p}^{1 + \epsilon }$的温和假设，其中$\epsilon  > 0$为任意小常数。该假设显然适用于实践中$N$和$p$的合理取值；理论上，这是模型能计算$N$位"或"运算等近乎平凡函数的最低要求[9]。当$N \geq  {p}^{1 + \epsilon }$时，许多基本操作（见2.1节）可在$O\left( 1\right)$轮次和$O\left( {N/p}\right)$负载（常称"线性负载"，即单次全量数据混洗所需负载）内完成。

For upper bounds, we assume that every tuple, any semiring element,as well as any integer of $O\left( {\log N}\right)$ bits,consumes one unit of communication. For lower bounds, similar to [12], we require the algorithm to work over any semiring, and assume that the only way for a server to create new semiring elements is by multiplying and adding existing semiring elements currently residing on the same server. We call this model the semiring MPC model.

对于上界，我们假定每个元组、半环元素及$O\left( {\log N}\right)$位整数均消耗单位通信量。对于下界，类似[12]，要求算法适用于任意半环，且服务器仅能通过乘加当前驻留的同服务器半环元素来生成新元素。此模型称为半环MPC模型。

### 1.4 Previous MPC algorithms

### 1.4 现有MPC算法

For a two-way join ${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$ ,there is an optimal MPC algorithm with load $O\left( {\frac{N}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) \left\lbrack  {5,{13}}\right\rbrack$ . Plugging this algorithm into the Yannakakis algorithm, together with the MPC primitives for semijoin and aggregation (see Section 2.1), we can run the Yan-nakakis algorithm to compute join-project or join-aggregate queries in the MPC model. This is referred to as the distributed Yannakakis algorithm in $\left\lbrack  {1,{15}}\right\rbrack$ . The load of this algorithm is $O\left( {\frac{N}{p} + \frac{J}{p}}\right)$ ,where $J$ is the maximum intermediate join size ${}^{2}$ . Combined with the previously known bounds on $J\left\lbrack  {2,3,{15},{25}}\right\rbrack$ ,this implies that it can compute free-connex queries with load $O\left( {\frac{N}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ ,matrix multiplication with load $O\left( {\frac{N}{p} + \frac{N\sqrt{\mathrm{{OUT}}}}{p}}\right)$ ,star queries with load $O\left( {\frac{N}{p} + \frac{N \cdot  {\mathrm{{OUT}}}^{1 - 1/n}}{p}}\right)$ ,and general acyclic join-aggregate queries with load $O\left( {\frac{N}{p} + \frac{N \cdot  \mathrm{{OUT}}}{p}}\right)$ . The results are summarized in Table 1.

对于双向连接${R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$，存在一个负载为$O\left( {\frac{N}{p} + \sqrt{\frac{\mathrm{{OUT}}}{p}}}\right) \left\lbrack  {5,{13}}\right\rbrack$的最优MPC算法。将该算法与半连接和聚合的MPC原语（参见第2.1节）结合到Yannakakis算法中，我们可以在MPC模型中运行Yannakakis算法来计算连接-投影或连接-聚合查询。这在$\left\lbrack  {1,{15}}\right\rbrack$中被称为分布式Yannakakis算法。该算法的负载为$O\left( {\frac{N}{p} + \frac{J}{p}}\right)$，其中$J$表示最大中间连接规模${}^{2}$。结合先前已知的$J\left\lbrack  {2,3,{15},{25}}\right\rbrack$边界条件，这意味着该算法能以$O\left( {\frac{N}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$负载计算自由连接查询、$O\left( {\frac{N}{p} + \frac{N\sqrt{\mathrm{{OUT}}}}{p}}\right)$负载计算矩阵乘法、$O\left( {\frac{N}{p} + \frac{N \cdot  {\mathrm{{OUT}}}^{1 - 1/n}}{p}}\right)$负载计算星型查询、以及$O\left( {\frac{N}{p} + \frac{N \cdot  \mathrm{{OUT}}}{p}}\right)$负载计算一般的无环连接-聚合查询。结果总结见表1。

Interestingly,while the Yannakakis algorithm’s $O\left( {N + \mathrm{{OUT}}}\right)$ running time for free-connex queries is clearly optimal in the RAM model,its $O\left( {\frac{N}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$ load is not optimal in the MPC model. We recently designed an algorithm for free-connex queries with load $O\left( {\frac{N}{p} + \frac{\sqrt{N \cdot  \mathrm{{OUT}}}}{p}}\right) \left\lbrack  {14}\right\rbrack$ ,which is also shown to be optimal when OUT $\leq  c \cdot  p \cdot  N$ for some sufficiently large constant $c > 0$ .

值得注意的是，虽然Yannakakis算法在RAM模型中针对自由连接查询的$O\left( {N + \mathrm{{OUT}}}\right)$运行时间明显是最优的，但其在MPC模型中的$O\left( {\frac{N}{p} + \frac{\mathrm{{OUT}}}{p}}\right)$负载并非最优。我们最近设计了一个针对自由连接查询的算法，其负载为$O\left( {\frac{N}{p} + \frac{\sqrt{N \cdot  \mathrm{{OUT}}}}{p}}\right) \left\lbrack  {14}\right\rbrack$，当输出结果OUT$\leq  c \cdot  p \cdot  N$超过某个足够大的常数$c > 0$时，该负载也被证明是最优的。

There are also worst-case optimal MPC algorithms [16, 23] for computing full queries,i.e., $\mathbf{y} = \mathcal{V}$ . These algorithms have load $O\left( \frac{N}{{p}^{1/{\rho }^{ * }}}\right)$ ,where ${\rho }^{ * }$ is the fractional cover number of the join graph $Q$ . For join-aggregate queries,one can use their algorithms to compute the full join first, and then perform the aggregation. However, the aggregation step will become the bottleneck with a load of $O\left( \frac{{\mathrm{{OUT}}}_{f}}{p}\right)$ ,where ${\mathrm{{OUT}}}_{f}$ is the size of the full join results. This approach is thus no better than the Yannakakis algorithm since we always have ${\mathrm{{OUT}}}_{f} \geq  J$ .

针对完整查询（即$\mathbf{y} = \mathcal{V}$）还存在最坏情况下最优的MPC算法[16,23]。这些算法的负载为$O\left( \frac{N}{{p}^{1/{\rho }^{ * }}}\right)$，其中${\rho }^{ * }$表示连接图$Q$的分数覆盖数。对于连接-聚合查询，可以先使用这些算法计算完整连接，再执行聚合操作。然而聚合步骤会成为瓶颈，其负载高达$O\left( \frac{{\mathrm{{OUT}}}_{f}}{p}\right)$（${\mathrm{{OUT}}}_{f}$表示完整连接结果的大小）。由于我们始终满足${\mathrm{{OUT}}}_{f} \geq  J$，这种方法并不优于Yannakakis算法。

### 1.5 Our results

### 1.5 研究成果

In this paper, we study non-free-connex tree queries where the output attributes can be arbitrary. Table 1 summarizes our results, where the $\widetilde{O}$ notation hides polylogarithmic factors.

本文研究了输出属性可任意指定的非自由连接树型查询。表1总结了我们的研究成果，其中$\widetilde{O}$符号表示隐藏的多对数因子。

We start with the matrix multiplication problem,i.e., $\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)$ $\bowtie  {R}_{2}\left( {B,C}\right)$ ,which is the simplest non-free-connex query. Let ${N}_{1},{N}_{2}$ be the sizes of ${R}_{1},{R}_{2}$ respectively. First,if ${N}_{1} = 1$ (resp. ${N}_{2} = 1$ ), the problem can be trivially solved by simply broadcasting the only tuple in ${R}_{1}$ (resp. ${R}_{2}$ ). The load is just $O\left( 1\right)$ . Note that when ${N}_{1} = 1$ or ${N}_{2} = 1$ ,for each $\left( {a,c}\right)  \in  {\pi }_{A,C}{R}_{1} \bowtie  {R}_{2}$ ,there is only one $b$ such that $\left( {a,b}\right)  \in  {R}_{1},\left( {b,c}\right)  \in  {R}_{2}$ ,so there is no need to add semiring elements. Thus all query results can be computed locally after the broadcast.

我们从矩阵乘法问题开始，即$\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)$$\bowtie  {R}_{2}\left( {B,C}\right)$，这是最简单的非自由连接查询。设${N}_{1},{N}_{2}$分别为${R}_{1},{R}_{2}$的尺寸。首先，若${N}_{1} = 1$（相应地${N}_{2} = 1$），只需广播${R}_{1}$（相应地${R}_{2}$）中的唯一元组即可轻松解决问题，负载仅为$O\left( 1\right)$。注意当${N}_{1} = 1$或${N}_{2} = 1$时，对每个$\left( {a,c}\right)  \in  {\pi }_{A,C}{R}_{1} \bowtie  {R}_{2}$仅存在一个$b$满足$\left( {a,b}\right)  \in  {R}_{1},\left( {b,c}\right)  \in  {R}_{2}$，因此无需进行半环元素加法运算，所有查询结果在广播后均可本地计算得出。

For ${N}_{1},{N}_{2} \geq  2$ ,we design an MPC algorithm for matrix multiplication with load $\widetilde{O}\left( {\frac{{N}_{1} + {N}_{2}}{p} + \min \left\{  {\sqrt{\frac{{N}_{1}{N}_{2}}{p}},\frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right)$ , which simplifies to $\widetilde{O}\left( {\frac{N}{p} + \min \left\{  {\frac{N}{\sqrt{p}},\frac{{N}^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right)$ when ${N}_{1} =$ ${N}_{2} = N$ . One can verify that this presents an asymptotic improvement over the Yannakakis algorithm for any OUT $= \omega \left( 1\right)$ . In fact, our algorithm performs the same amount of computation as the Yannakakis algorithm and computes all the $O\left( {N\sqrt{\mathrm{{OUT}}}}\right)$ elementary products, which is unavoidable in the semiring model. The key to the reduction in load is locality, namely, we arrange these elementary products to be computed on the servers in such a way that most of them can be aggregated locally. The standard Yannakakis algorithm has no locality at all, and all the elementary products are shuffled around.

针对${N}_{1},{N}_{2} \geq  2$，我们设计了负载为$\widetilde{O}\left( {\frac{{N}_{1} + {N}_{2}}{p} + \min \left\{  {\sqrt{\frac{{N}_{1}{N}_{2}}{p}},\frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right)$的矩阵乘法MPC算法，当${N}_{1} =$${N}_{2} = N$时可简化为$\widetilde{O}\left( {\frac{N}{p} + \min \left\{  {\frac{N}{\sqrt{p}},\frac{{N}^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right)$。可以验证该算法对任意输出规模OUT$= \omega \left( 1\right)$均实现了对Yannakakis算法的渐进改进。实际上，我们的算法执行与Yannakakis算法相同的计算量，生成所有$O\left( {N\sqrt{\mathrm{{OUT}}}}\right)$个基本乘积——这在半环模型中不可避免。降低负载的关键在于局部性设计：我们通过服务器间的计算任务分配，使得大部分基本乘积能在本地完成聚合。而标准Yannakakis算法完全不考虑局部性，所有基本乘积都需要全局混洗。

Furthermore, we show that this bound is optimal in the semiring MPC model. Specifically,we show that for any ${N}_{1},{N}_{2} \geq  2$ and any $\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq  \mathrm{{OUT}} \leq  {N}_{1}{N}_{2}$ ,there is an instance with input size ${N}_{1},{N}_{2}$ and output size OUT,on which the load of any algorithm has to be at least this bound in the semiring MPC model. In fact, the lower bound holds even if the algorithm is only required to work over idempotent semirings,i.e., $a \oplus  a = a$ for any element $a$ in the semiring.

进一步地，我们证明该界限在半环MPC模型下是最优的。具体而言，对于任意${N}_{1},{N}_{2} \geq  2$和$\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq  \mathrm{{OUT}} \leq  {N}_{1}{N}_{2}$，存在输入规模为${N}_{1},{N}_{2}$、输出规模为OUT的实例，任何算法在半环MPC模型中的负载都必须至少达到该下限。事实上，即使算法仅需在幂等半环（即对半环中任意元素$a$满足$a \oplus  a = a$）上运行，该下界依然成立。

Next, we generalize our matrix multiplication algorithm to line queries and star queries, defined as follows.

接下来，我们将矩阵乘法算法推广至线型查询和星型查询，其定义如下。

(1) Line query: $\mathop{\sum }\limits_{{{A}_{2},{A}_{3},\cdots ,{A}_{n}}}{R}_{1}\left( {{A}_{1},{A}_{2}}\right)  \bowtie  {R}_{2}\left( {{A}_{2},{A}_{3}}\right)  \bowtie  \cdots  \bowtie$ ${R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right)$ ;

(1) 线型查询：$\mathop{\sum }\limits_{{{A}_{2},{A}_{3},\cdots ,{A}_{n}}}{R}_{1}\left( {{A}_{1},{A}_{2}}\right)  \bowtie  {R}_{2}\left( {{A}_{2},{A}_{3}}\right)  \bowtie  \cdots  \bowtie$${R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right)$；

(2) Star query: $\mathop{\sum }\limits_{B}{R}_{1}\left( {{A}_{1},B}\right)  \bowtie  {R}_{2}\left( {{A}_{2},B}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},B}\right)$ . Finally, we give an algorithm that can handle tree queries with arbitrary output attributes. As seen in Table 1, we have been able to obtain asymptotic improvement over the Yannakakis algorithm in each case, although we do not have matching lower bounds.

(2) 星型查询：$\mathop{\sum }\limits_{B}{R}_{1}\left( {{A}_{1},B}\right)  \bowtie  {R}_{2}\left( {{A}_{2},B}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},B}\right)$。最终我们提出一种能处理含任意输出属性的树形查询的算法。如表1所示，尽管未获得匹配的下界，但在每种情况下我们都实现了对Yannakakis算法的渐进性改进。

One major technical difficulty we had to overcome is that the value of OUT is not readily available. Although it is known that OUT can be computed for free-connex queries with linear load $\left\lbrack  {{14},{15}}\right\rbrack$ ,computing the query size for non-free-connex queries still remains an open problem, even in the RAM model. In fact, the only known method for computing the query size for non-free-connex queries is to find all the query results, which is exactly the problem we aim to solve. We get around this chicken-and-egg problem by two approaches: (1) For matrix multiplication and line queries, we are able to obtain a constant-factor approximation of OUT with linear load, which is sufficient for achieving the asymptotic bounds we claim. (2) For star and tree queries, even a constant-factor approximation looks difficult, so we try to make the algorithms oblivious to OUT, i.e., OUT is only used in the analysis but not needed by the algorithm itself.

需要克服的主要技术难点是OUT值无法直接获取。虽然已知线性负载下可计算free-connex查询的OUT值$\left\lbrack  {{14},{15}}\right\rbrack$，但非free-connex查询的规模计算即使在RAM模型中仍是未解难题。实际上，目前计算非free-connex查询规模的唯一方法是找出所有查询结果——而这正是我们试图解决的问题。我们通过两种方案解决这个先有鸡还是先有蛋的困境：(1)对于矩阵乘法和线性查询，能以线性负载获得OUT的常数因子近似值，这足以实现我们宣称的渐进边界；(2)对于星型和树形查询，即便常数因子近似也困难，因此我们尝试使算法不依赖OUT值，即OUT仅用于分析而算法本身无需知晓。

## 2 PRELIMINARIES

## 2 预备知识

### 2.1 MPC Primitives

### 2.1 MPC原语

We mention the following deterministic primitives in the MPC model,which can be computed with load $O\left( \frac{N}{p}\right)$ in $O\left( 1\right)$ rounds. Assume $N > {p}^{1 + \epsilon }$ where $\epsilon  > 0$ is any small constant.

列举MPC模型中以下确定性原语，它们可在$O\left( 1\right)$轮次内以$O\left( \frac{N}{p}\right)$负载完成计算。假设$N > {p}^{1 + \epsilon }$，其中$\epsilon  > 0$为任意小常数。

Sorting [10]. Assume all servers are labeled as $1,2,\cdots ,p$ . Given $N$ elements,redistribute them so that each server has $O\left( \frac{N}{p}\right)$ elements in the end,while any element on server $i$ is smaller than or equal to any element on server $j$ ,for any $i < j$ .

排序[10]。设所有服务器标记为$1,2,\cdots ,p$。给定$N$个元素，重新分配使最终每个服务器持有$O\left( \frac{N}{p}\right)$个元素，且对任意$i < j$，服务器$i$上的元素均小于等于服务器$j$上的元素。

Reduce-by-key [13]. Given $N$ pairs in terms of (key,value),compute the "sum" of values for each key, where the "sum" is defined by any associative operator. Note that an aggregation $\mathop{\sum }\limits_{\mathbf{y}}R$ can be computed as a reduce-by-key operation.

键值归约[13]。给定$N$个(key,value)键值对，计算每个key对应value的"和"（"和"可由任意结合运算符定义）。注意聚合操作$\mathop{\sum }\limits_{\mathbf{y}}R$可作为键值归约实现。

This primitive will also be frequently used to compute data statistics, for example the degree information. The degree of value $a \in  \operatorname{dom}\left( v\right)$ in relation ${R}_{e}$ is defined as the number of tuples in ${R}_{e}$ having this value in attribute $v$ ,i.e., $\left| {{\sigma }_{v = a}{R}_{e}}\right|$ . Each tuple $t \in  {R}_{e}$ is considered to have "key" ${\pi }_{v}t$ and "value" 1 .

该原语也常用于计算数据统计量，如度信息。关系${R}_{e}$中值$a \in  \operatorname{dom}\left( v\right)$的度定义为${R}_{e}$中在属性$v$上取该值的元组数量，即$\left| {{\sigma }_{v = a}{R}_{e}}\right|$。每个元组$t \in  {R}_{e}$被视为具有"键"${\pi }_{v}t$和"值"1。

Multi-search [13]. Given ${N}_{1}$ elements ${x}_{1},{x}_{2},\cdots ,{x}_{{N}_{1}}$ as set $X$ and ${N}_{2}$ elements ${y}_{1},{y}_{2},\cdots ,{y}_{{N}_{2}}$ as set $Y$ ,where all elements are drawn from an ordered domain. Set $N = {N}_{1} + {N}_{2}$ . For each ${x}_{i}$ ,find its predecessor in $Y$ ,i.e.,the largest element in $Y$ but smaller than ${x}_{i}$ . Note that a semijoin can also be computed by a multi-search.

多重搜索[13]。给定有序域中${N}_{1}$个元素${x}_{1},{x}_{2},\cdots ,{x}_{{N}_{1}}$作为集合$X$，及${N}_{2}$个元素${y}_{1},{y}_{2},\cdots ,{y}_{{N}_{2}}$作为集合$Y$。设$N = {N}_{1} + {N}_{2}$。对每个${x}_{i}$，找出其在$Y$中的前驱（即$Y$中小于${x}_{i}$的最大元素）。注意半连接也可通过多重搜索实现。

Remove dangling tuples [14, 25]. For any acyclic join, all dangling tuples, i.e., those that will not participate in the full join results, can be removed by a series of semijoins. Note that after dangling tuples are removed, we can determine whether the output of a query is empty or not.

剔除悬空元组[14,25]。对于任意无环连接，所有悬空元组（即不参与完整连接结果的元组）可通过系列半连接剔除。需注意剔除悬空元组后，可判定查询输出是否为空。

Parallel-packing [14]. Given $N$ numbers ${x}_{1},{x}_{2},\cdots ,{x}_{N}$ where $0 < {x}_{i} \leq  1$ for $i \in  \left\lbrack  N\right\rbrack$ ,group them into $m$ sets ${Y}_{1},{Y}_{2},\cdots ,{Y}_{m}$ such that $\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \leq  1$ for all $j$ ,and $\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \geq  \frac{1}{2}$ for all but one $j$ . Initially,the $N$ numbers are distributed arbitrarily across all servers, and the algorithm should produce all pairs(i,j)if $i \in  {Y}_{j}$ when done. Note that $m \leq  1 + 2\mathop{\sum }\limits_{i}{x}_{i}$ .

并行打包[14]。给定$N$个数字${x}_{1},{x}_{2},\cdots ,{x}_{N}$，其中$0 < {x}_{i} \leq  1$对于$i \in  \left\lbrack  N\right\rbrack$，将它们分组为$m$个集合${Y}_{1},{Y}_{2},\cdots ,{Y}_{m}$，使得$\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \leq  1$对所有$j$成立，且$\mathop{\sum }\limits_{{i \in  {Y}_{j}}}{x}_{i} \geq  \frac{1}{2}$对所有仅有一个例外$j$成立。初始时，$N$个数字任意分布在所有服务器上，算法完成时应输出所有满足$i \in  {Y}_{j}$的配对(i,j)。注意$m \leq  1 + 2\mathop{\sum }\limits_{i}{x}_{i}$。

### 2.2 Estimate OUT

### 2.2 OUT估算

We show how to obtain a constant-factor approximation of OUT for line queries (including matrix multiplication as a special case) in $O\left( 1\right)$ rounds with linear load. The similar idea has been used by [8] in the RAM model.

我们展示如何在$O\left( 1\right)$轮次内通过线性负载，为线性查询（包括作为特例的矩阵乘法）获得OUT的常数因子近似。类似思想曾被文献[8]在RAM模型中采用。

We borrow the technique of $k$ minimum values (KMV) [4,7], which is more commonly used to estimate the number of distinct elements in the streaming model. KMV works by applying a hash function to the input items,and keeping the $k$ minimum hash values, denoted as ${v}_{1},{v}_{2},\cdots ,{v}_{k}$ . It has been shown that,with $k = O\left( \frac{1}{{\epsilon }^{2}}\right)$ , the estimator $\frac{k - 1}{{v}_{k}}$ is an $\left( {1 + \epsilon }\right)$ -approximation of the number of distinct items in the data stream, with at least constant probability. Moreover, given the KMVs of two sets, the KMV of the union of the two sets can be computed by simply "merging" the two KMVs, i.e.,keeping the $k$ minimum values of the ${2k}$ values from the two KMVs, provided that they use the same hash function.

我们借鉴$k$最小哈希值(KMV)技术[4,7]，该技术更常用于流模型中估算不同元素数量。KMV通过对输入项应用哈希函数，保留$k$个最小哈希值（记为${v}_{1},{v}_{2},\cdots ,{v}_{k}$）实现。研究表明当$k = O\left( \frac{1}{{\epsilon }^{2}}\right)$时，估计量$\frac{k - 1}{{v}_{k}}$能以至少恒定概率，给出数据流中不同元素数量的$\left( {1 + \epsilon }\right)$近似。此外，若两个集合的KMV采用相同哈希函数，只需"合并"两者（即从${2k}$个值中保留$k$个最小值）即可计算并集的KMV。

On a line query,for each $a \in  \operatorname{dom}\left( {A}_{1}\right)$ ,we will obtain a constant-factor approximation of ${\mathrm{{OUT}}}_{a} =  \mid  {\pi }_{{A}_{n + 1}}{R}_{1}\left( {a,{A}_{2}}\right)  \bowtie  {R}_{2}\left( {{A}_{2},{A}_{3}}\right)  \bowtie$ $\cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right)  \mid$ . Note that $\mathrm{{OUT}} = \mathop{\sum }\limits_{{a \in  \operatorname{dom}\left( {A}_{1}\right) }}{\mathrm{{OUT}}}_{a}$ . To do so,we compute a hash value for each distinct value in $\operatorname{dom}\left( {A}_{n + 1}\right)$ . Then it suffices to compute,for each $a \in  \operatorname{dom}\left( {A}_{1}\right)$ ,a KMV (with a constant $k$ ) over all distinct values in $\operatorname{dom}\left( {A}_{n + 1}\right)$ that can join with $a$ . This can be done by calling the reduce-by-key primitive $n$ times using the merge operation above to compute the "sum". More precisely,for $i = n,n - 1,\ldots ,1$ ,we use reduce-by-key to compute the KMV for each $a \in  \operatorname{dom}\left( {A}_{i}\right)$ ,by merging all the KMVs for $b \in  \operatorname{dom}\left( {A}_{i + 1}\right)$ such that $\left( {a,b}\right)  \in  {R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right)$ .

对于线性查询，每个$a \in  \operatorname{dom}\left( {A}_{1}\right)$都将获得${\mathrm{{OUT}}}_{a} =  \mid  {\pi }_{{A}_{n + 1}}{R}_{1}\left( {a,{A}_{2}}\right)  \bowtie  {R}_{2}\left( {{A}_{2},{A}_{3}}\right)  \bowtie$$\cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right)  \mid$的常数因子近似。注意$\mathrm{{OUT}} = \mathop{\sum }\limits_{{a \in  \operatorname{dom}\left( {A}_{1}\right) }}{\mathrm{{OUT}}}_{a}$。为此，我们为$\operatorname{dom}\left( {A}_{n + 1}\right)$中每个不同值计算哈希值，然后对每个$a \in  \operatorname{dom}\left( {A}_{1}\right)$，只需在能与$a$连接的所有$\operatorname{dom}\left( {A}_{n + 1}\right)$不同值上计算KMV（使用常数$k$）。这可通过调用reduce-by-key原语$n$次，利用上述合并操作计算"总和"。具体而言，对于$i = n,n - 1,\ldots ,1$，我们使用reduce-by-key通过合并满足$\left( {a,b}\right)  \in  {R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right)$的所有$b \in  \operatorname{dom}\left( {A}_{i + 1}\right)$的KMV，来计算每个$a \in  \operatorname{dom}\left( {A}_{i}\right)$的KMV。

The KMV obtained from each $a \in  \operatorname{dom}\left( {A}_{1}\right)$ gives us a constant-factor approximation of ${\mathrm{{OUT}}}_{a}$ only with constant probability. To boost the success probability,we run $O\left( {\log N}\right)$ instances of this algorithm in parallel using independent random hash functions, and return the median estimator for each ${\mathrm{{OUT}}}_{a}$ . This boosts the success probability to $1 - 1/{N}^{O\left( 1\right) }$ for each ${\mathrm{{OUT}}}_{a}$ . By a union bound, the probability that all estimators are constant-factor approximations is also $1 - 1/{N}^{O\left( 1\right) }$ . Then,we also have a constant-factor approximation of OUT. The load of this algorithm is $\widetilde{O}\left( \frac{N}{p}\right)$ .

从每个$a \in  \operatorname{dom}\left( {A}_{1}\right)$获取的KMV值仅能以恒定概率为我们提供${\mathrm{{OUT}}}_{a}$的常数因子近似。为提高成功概率，我们使用独立随机哈希函数并行运行$O\left( {\log N}\right)$个该算法实例，并返回每个${\mathrm{{OUT}}}_{a}$的中位数估计量。这将每个${\mathrm{{OUT}}}_{a}$的成功概率提升至$1 - 1/{N}^{O\left( 1\right) }$。通过并集界，所有估计量均为常数因子近似的概率同样为$1 - 1/{N}^{O\left( 1\right) }$。由此，我们也得到了OUT的常数因子近似。该算法的负载为$\widetilde{O}\left( \frac{N}{p}\right)$。

## 3 MATRIX MULTIPLICATION

## 3 矩阵乘法

In this section, we study the matrix multiplication problem, i.e., the query $\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$ . Suppose ${R}_{1}$ and ${R}_{2}$ have ${N}_{1},{N}_{2}$ tuples respectively, and the query has output size OUT. As mentioned in Section 1.5,the problem is trivial if ${N}_{1} = 1$ or ${N}_{2} = 1$ . For ${N}_{1},{N}_{2} \geq  2$ ,we show the following result.

本节我们研究矩阵乘法问题，即查询$\mathop{\sum }\limits_{B}{R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right)$。假设${R}_{1}$和${R}_{2}$分别具有${N}_{1},{N}_{2}$个元组，查询输出规模为OUT。如第1.5节所述，当${N}_{1} = 1$或${N}_{2} = 1$时该问题无研究价值。针对${N}_{1},{N}_{2} \geq  2$的情况，我们展示以下结论。

THEOREM 1. Matrix multiplication can be computed in the MPC model in $O\left( 1\right)$ rounds with load w.h.p. ${}^{3}$

定理1. 矩阵乘法可在MPC模型中以$O\left( 1\right)$轮复杂度实现，负载高概率为${}^{3}$

$$
\widetilde{O}\left( {\frac{{N}_{1} + {N}_{2}}{p} + \min \left\{  {\sqrt{\frac{{N}_{1}{N}_{2}}{p}},\frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right) .
$$

First,note that if ${N}_{1}/{N}_{2} < 1/p$ or ${N}_{1}/{N}_{2} > p$ ,then $\frac{{N}_{1} + {N}_{2}}{p}$ asymptotically dominates $\sqrt{\frac{{N}_{1}{N}_{2}}{p}}$ ,so the bound simplifies to $\widetilde{O}\left( \frac{{N}_{1} + {N}_{2}}{p}\right)$ . For this case,we give a simple algorithm. Assume ${N}_{1}/{N}_{2} < 1/p$ (the other case is symmetric). We first remove the dangling tuples. Then sort ${R}_{2}$ by attribute $C$ . We note that after dangling tuples are removed,for any $c \in  \operatorname{dom}\left( C\right)$ ,we have $\left| {{R}_{2}\left( {B,c}\right) }\right|  \leq  \left| {{\pi }_{B}{R}_{1}\left( {A,B}\right) }\right|  \leq$ ${N}_{1} \leq  \frac{{N}_{2}}{p}$ . So after sorting,tuples in ${R}_{2}$ with the same value on attribute $C$ must land on the same server or two consecutive servers. In the latter case, we use another round to move them to the same server. Next,we broadcast ${R}_{1}$ to all servers,and ask each server to compute the query on its local data. No further aggregation is needed as tuples from different servers have disjoint $C$ values. This algorithm has a load of $O\left( {{N}_{1} + \frac{{N}_{2}}{p}}\right)  = O\left( \frac{{N}_{1} + {N}_{2}}{p}\right)$ . Below,we assume $1/p \leq  {N}_{1}/{N}_{2} \leq  p$ .

首先注意，若${N}_{1}/{N}_{2} < 1/p$或${N}_{1}/{N}_{2} > p$，则$\frac{{N}_{1} + {N}_{2}}{p}$将渐进主导$\sqrt{\frac{{N}_{1}{N}_{2}}{p}}$，此时边界简化为$\widetilde{O}\left( \frac{{N}_{1} + {N}_{2}}{p}\right)$。针对此情形，我们给出一个简单算法。假设${N}_{1}/{N}_{2} < 1/p$（另一种情况对称处理）。首先移除悬空元组，然后按属性$C$对${R}_{2}$排序。需注意移除悬空元组后，对于任意$c \in  \operatorname{dom}\left( C\right)$都存在$\left| {{R}_{2}\left( {B,c}\right) }\right|  \leq  \left| {{\pi }_{B}{R}_{1}\left( {A,B}\right) }\right|  \leq$${N}_{1} \leq  \frac{{N}_{2}}{p}$。因此排序后，${R}_{2}$中具有相同$C$属性值的元组必位于同一服务器或相邻服务器。后者情况下，我们额外使用一轮通信将其移至同一服务器。接着将${R}_{1}$广播至所有服务器，要求各服务器在本地数据上执行查询计算。由于不同服务器的元组具有互斥的$C$值，无需进一步聚合。该算法负载为$O\left( {{N}_{1} + \frac{{N}_{2}}{p}}\right)  = O\left( \frac{{N}_{1} + {N}_{2}}{p}\right)$。下文我们假设$1/p \leq  {N}_{1}/{N}_{2} \leq  p$。

In this part, we consider output-sensitive algorithms for computing sparse matrix multiplication. We first remove all dangling tuples with linear load. \mathop{\sum }\limits_{{i,j}}{p}_{i,j} = \mathop{\sum }\limits_{{i,j}}\left( {\frac{\left| {{\sigma }_{A \in  {A}_{i}}{R}_{1}\left( {A,B}\right) }\right|  + \left| {{\sigma }_{C \in  {C}_{j}^{i}}{R}_{2}\left( {B,C}\right) }\right| }{L} + 1}\right) 
$$

$$
 \leq  \frac{{N}_{1}}{L} \cdot  \sqrt{\frac{\mathrm{{OUT}}}{L}} \cdot  \sqrt{\frac{{N}_{2}}{{N}_{1}}} + \frac{{N}_{2}}{L} \cdot  \sqrt{\frac{\mathrm{{OUT}}}{L}} \cdot  \sqrt{\frac{{N}_{1}}{{N}_{2}}} + p = O\left( p\right) .
$$

Over all steps,this algorithm has a load of $O\left( L\right)$ .

整个算法的总负载为$O\left( L\right)$。

LEMMA 2. For any sparse matrix multiplication with input sizes ${N}_{1},{N}_{2} \geq  2$ and output size OUT,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $\widetilde{O}\left( {\frac{{N}_{1} + {N}_{2}}{p} + \frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right)$ w.h.p.

引理2. 对于输入规模为${N}_{1},{N}_{2} \geq  2$、输出规模为OUT的任何稀疏矩阵乘法，存在算法能以$O\left( 1\right)$轮次和$\widetilde{O}\left( {\frac{{N}_{1} + {N}_{2}}{p} + \frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right)$负载（高概率）完成计算。

Finally, depending on the value of OUT, we choose to run either the algorithm in Section 3.1 or the one in Section 3.2, thus obtaining the bound claimed in Theorem 1.

最终根据OUT的值，选择运行第3.1节或第3.2节的算法，从而获得定理1中所述边界。

### 3.3 Lower Bounds

### 3.3 下界证明

We prove the following two lower bounds, which together show that the bound in Theorem 1 is optimal. Both lower bounds hold over idempotent semirings, i.e., semirings with the property that $a \oplus  a = a$ for any semiring element $a$ .

我们证明以下两个下界，共同表明定理1中的边界是最优的。这两个下界在幂等半环（即满足对任意半环元素$a$都有$a \oplus  a = a$性质的半环）上都成立。

THEOREM 2. For any ${N}_{1},{N}_{2} \geq  2$ and $\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq$ OUT $\leq$ ${N}_{1}{N}_{2}$ ,there is an instance $\mathcal{R}$ with input sizes $\Theta \left( {N}_{1}\right) ,\Theta \left( {N}_{2}\right)$ and output size $\Theta \left( \mathrm{{OUT}}\right)$ ,such that any algorithm computing the matrix multiplication on $\mathcal{R}$ in $O\left( 1\right)$ rounds must incur a load of $\Omega \left( \frac{{N}_{1} + {N}_{2}}{p}\right)$ in the idempotent semiring MPC model.

定理2. 对于任意${N}_{1},{N}_{2} \geq  2$和$\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq$OUT$\leq$${N}_{1}{N}_{2}$，存在输入规模为$\Theta \left( {N}_{1}\right) ,\Theta \left( {N}_{2}\right)$、输出规模为$\Theta \left( \mathrm{{OUT}}\right)$的实例$\mathcal{R}$，使得在幂等半环MPC模型中，任何在$O\left( 1\right)$轮次内计算$\mathcal{R}$上矩阵乘法的算法都必须承受$\Omega \left( \frac{{N}_{1} + {N}_{2}}{p}\right)$的负载。

Proof. Without loss of generality,assume ${N}_{2} \geq  {N}_{1} \geq  2$ . The hard instance is constructed as follows. Set $\operatorname{dom}\left( A\right)  = \{ a\} ,\operatorname{dom}\left( B\right)  =$ $\left\{  {{b}_{i} : i \in  \left\lbrack  {N}_{1}\right\rbrack  }\right\}$ and $\operatorname{dom}\left( C\right)  = \left\{  {{c}_{j} : j \in  \left\lbrack  \frac{{N}_{2}}{2}\right\rbrack  }\right\}$ . Set the instance as ${R}_{1}\left( {A,B}\right)  = \{ a\}  \times  \operatorname{dom}\left( B\right)$ and ${R}_{2}\left( {B,C}\right)  = \left\{  {{b}_{1},{b}_{2}}\right\}   \times  \operatorname{dom}\left( C\right)$ . Note that the output size is $1 \times  2 \times  \frac{{N}_{2}}{2} = {N}_{2}$ . Then we add $O\left( {N}_{1}\right)$ dummy tuples to ${R}_{1}$ and $O\left( {N}_{2}\right)$ dummy tuples to ${R}_{2}$ so that the output size is $\Theta$ (OUT). The initial data distribution is a way such that no two tuples of ${R}_{2}$ with the same value $c \in  \operatorname{dom}\left( C\right)$ are on the same server.

证明。不失一般性，假设${N}_{2} \geq  {N}_{1} \geq  2$。构造困难实例的方法如下：设$\operatorname{dom}\left( A\right)  = \{ a\} ,\operatorname{dom}\left( B\right)  =$$\left\{  {{b}_{i} : i \in  \left\lbrack  {N}_{1}\right\rbrack  }\right\}$且$\operatorname{dom}\left( C\right)  = \left\{  {{c}_{j} : j \in  \left\lbrack  \frac{{N}_{2}}{2}\right\rbrack  }\right\}$。将该实例设为${R}_{1}\left( {A,B}\right)  = \{ a\}  \times  \operatorname{dom}\left( B\right)$和${R}_{2}\left( {B,C}\right)  = \left\{  {{b}_{1},{b}_{2}}\right\}   \times  \operatorname{dom}\left( C\right)$。注意输出规模为$1 \times  2 \times  \frac{{N}_{2}}{2} = {N}_{2}$。随后我们向${R}_{1}$添加$O\left( {N}_{1}\right)$个虚拟元组，并向${R}_{2}$添加$O\left( {N}_{2}\right)$个虚拟元组，使得输出规模达到$\Theta$（OUT）。初始数据分布需确保${R}_{2}$中具有相同值$c \in  \operatorname{dom}\left( C\right)$的两个元组不会位于同一服务器。

By the semiring model requirement,for each $c \in  \operatorname{dom}\left( C\right)$ ,the two tuples $\left( {{b}_{1},c}\right) ,\left( {{b}_{2},c}\right)$ in ${R}_{2}$ have to meet on at least one server to produce the aggregate for(a,c). Under the initial data distribution, at least ${N}_{2}/2$ tuples have to be sent to other servers for computing the aggregation,which incurs a load of at least ${N}_{2}/{2p}$ . So lower bound of the load is $\Omega \left( \frac{{N}_{2}}{p}\right)  = \Omega \left( \frac{{N}_{1} + {N}_{2}}{p}\right)$ .

根据半环模型要求，对于每个$c \in  \operatorname{dom}\left( C\right)$，${R}_{2}$中的两个元组$\left( {{b}_{1},c}\right) ,\left( {{b}_{2},c}\right)$必须在至少一台服务器上相遇以生成(a,c)的聚合结果。在初始数据分布下，至少需要传输${N}_{2}/2$个元组至其他服务器进行聚合计算，这将产生至少${N}_{2}/{2p}$的负载。因此负载下限为$\Omega \left( \frac{{N}_{2}}{p}\right)  = \Omega \left( \frac{{N}_{1} + {N}_{2}}{p}\right)$。

THEOREM 3. For any ${N}_{1},{N}_{2} \geq  2$ and $\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq$ OUT $\leq$ ${N}_{1}{N}_{2}$ ,there exists an instance $\mathcal{R}$ for sparse matrix multiplication with input sizes $\Theta \left( {N}_{1}\right) ,\Theta \left( {N}_{2}\right)$ and output size $\Theta \left( \mathrm{{OUT}}\right)$ ,such that any algorithm computing $\mathcal{R}$ in $O\left( 1\right)$ rounds in the idempotent semiring MPC model must incur a load of

定理3。对于任意${N}_{1},{N}_{2} \geq  2$和$\max \left\{  {{N}_{1},{N}_{2}}\right\}   \leq$OUT$\leq$${N}_{1}{N}_{2}$，存在输入规模为$\Theta \left( {N}_{1}\right) ,\Theta \left( {N}_{2}\right)$、输出规模为$\Theta \left( \mathrm{{OUT}}\right)$的稀疏矩阵乘法实例$\mathcal{R}$，使得在幂等半环MPC模型中通过$O\left( 1\right)$轮计算$\mathcal{R}$的任何算法都必须承担如下负载：

$$
\Omega \left( {\min \left\{  {\sqrt{\frac{{N}_{1}{N}_{2}}{p}},\frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}}\right\}  }\right) .
$$

Proof. First consider the case ${N}_{2}/{N}_{1} >$ OUT. In this case,it is sufficient to prove an $\Omega \left( {\left( \frac{{N}_{2}}{p}\right) }^{2/3}\right)$ lower bound,which is at least as large as the second term in the claimed lower bound. If ${N}_{2} < p$ ,this degenerates to the trivial bound $\Omega \left( 1\right)$ ; otherwise,we have ${\left( \frac{{N}_{2}}{p}\right) }^{2/3} < \frac{{N}_{2}}{p} \leq  \frac{{N}_{1} + {N}_{2}}{p}$ ,and we apply Theorem 2 . The case when ${N}_{1}/{N}_{2} >$ OUT can be argued similarly.

证明。首先考虑${N}_{2}/{N}_{1} >$OUT的情况。此时只需证明$\Omega \left( {\left( \frac{{N}_{2}}{p}\right) }^{2/3}\right)$的下界，该下界不小于所声称下界中的第二项。若${N}_{2} < p$，则退化为平凡下界$\Omega \left( 1\right)$；否则我们有${\left( \frac{{N}_{2}}{p}\right) }^{2/3} < \frac{{N}_{2}}{p} \leq  \frac{{N}_{1} + {N}_{2}}{p}$，此时应用定理2。当${N}_{1}/{N}_{2} >$OUT的情况可类似论证。

Below,we assume that $1/\mathrm{{OUT}} \leq  {N}_{1}/{N}_{2} \leq  \mathrm{{OUT}}$ . The hard instance is constructed as follows. There are $\sqrt{\frac{{N}_{1} \cdot  \mathrm{{OUT}}}{{N}_{2}}},\sqrt{\frac{{N}_{1}{N}_{2}}{\mathrm{{OUT}}}}$ , $\sqrt{\frac{{N}_{2} \cdot  \mathrm{{OUT}}}{{N}_{1}}}$ distinct values in $\operatorname{dom}\left( A\right) ,\operatorname{dom}\left( B\right) ,\operatorname{dom}\left( C\right)$ respectively. Note that all three numbers are at least 1 when $1/\mathrm{{OUT}} \leq  {N}_{1}/{N}_{2} \leq$ OUT; thus we can ignore rounding issues without affecting the asymptotic results. Set ${R}_{1}\left( {A,B}\right)  = \operatorname{dom}\left( A\right)  \times  \operatorname{dom}\left( B\right)$ and ${R}_{2}\left( {B,C}\right)  =$ $\operatorname{dom}\left( B\right)  \times  \operatorname{dom}\left( C\right)$ . In this constructed instance,there are ${N}_{1},{N}_{2}$ tuples in ${R}_{1}\left( {A,B}\right) ,{R}_{2}\left( {B,C}\right)$ ,respectively. Every value $a \in  \operatorname{dom}\left( A\right)$ can join with every value $c \in  \operatorname{dom}\left( C\right)$ ,so the output size is $\left| {\operatorname{dom}\left( A\right) }\right|$ . $\left| {\operatorname{dom}\left( C\right) }\right|  =$ OUT.

在下文中，我们假设$1/\mathrm{{OUT}} \leq  {N}_{1}/{N}_{2} \leq  \mathrm{{OUT}}$。该困难实例的构造方式如下：在$\operatorname{dom}\left( A\right) ,\operatorname{dom}\left( B\right) ,\operatorname{dom}\left( C\right)$中分别存在$\sqrt{\frac{{N}_{1} \cdot  \mathrm{{OUT}}}{{N}_{2}}},\sqrt{\frac{{N}_{1}{N}_{2}}{\mathrm{{OUT}}}}$和$\sqrt{\frac{{N}_{2} \cdot  \mathrm{{OUT}}}{{N}_{1}}}$个不同的取值。需要注意的是，当$1/\mathrm{{OUT}} \leq  {N}_{1}/{N}_{2} \leq$输出时，这三个数值均不小于1，因此我们可以忽略舍入问题而不影响渐近结果。设定${R}_{1}\left( {A,B}\right)  = \operatorname{dom}\left( A\right)  \times  \operatorname{dom}\left( B\right)$和${R}_{2}\left( {B,C}\right)  =$$\operatorname{dom}\left( B\right)  \times  \operatorname{dom}\left( C\right)$。在此构造的实例中，${R}_{1}\left( {A,B}\right) ,{R}_{2}\left( {B,C}\right)$分别包含${N}_{1},{N}_{2}$个元组。每个值$a \in  \operatorname{dom}\left( A\right)$可与每个值$c \in  \operatorname{dom}\left( C\right)$进行连接，因此输出规模为$\left| {\operatorname{dom}\left( A\right) }\right|$。$\left| {\operatorname{dom}\left( C\right) }\right|  =$输出。

There are two types of tuples in the semiring MPC model: (1) original tuples from ${R}_{1},{R}_{2}$ (or their copies); and (2) aggregate tuples (or their copies) in the form of $\left( {a,c,w,B\left( {ac}\right) }\right)$ where $B\left( {ac}\right)  \subseteq$ $\operatorname{dom}\left( B\right)$ and $w = \mathop{\sum }\limits_{{b \in  B\left( {ac}\right)  : \left( {a,b,c}\right)  \in  {R}_{1} \bowtie  {R}_{2}}}w\left( {a,b}\right)  \times  w\left( {b,c}\right)$ . Note that if $B\left( {ac}\right)  = \operatorname{dom}\left( B\right)$ ,the tuple is a final result. We will lower bound the load in terms of the number of type (1) and type (2) tuples received by any server,even assuming $B\left( {ac}\right)$ can be encoded by a constant-size message.

在半环MPC模型中存在两类元组：(1)来自${R}_{1},{R}_{2}$的原始元组（或其副本）；(2)聚合元组（或其副本），其形式为$\left( {a,c,w,B\left( {ac}\right) }\right)$，其中$B\left( {ac}\right)  \subseteq$$\operatorname{dom}\left( B\right)$且$w = \mathop{\sum }\limits_{{b \in  B\left( {ac}\right)  : \left( {a,b,c}\right)  \in  {R}_{1} \bowtie  {R}_{2}}}w\left( {a,b}\right)  \times  w\left( {b,c}\right)$。需注意若$B\left( {ac}\right)  = \operatorname{dom}\left( B\right)$，则该元组为最终结果。我们将通过限定任何服务器接收的类型(1)和类型(2)元组数量来下界负载，即使假设$B\left( {ac}\right)$可通过常量大小的消息编码。

The idempotent semiring model only allows the following two operations to produce new tuples:

幂等半环模型仅允许以下两种操作生成新元组：

(i) $\left( {a,b,w\left( {a,b}\right) }\right)  \otimes  \left( {b,c,w\left( {b,c}\right) }\right)  \rightarrow  \left( {a,c,w\left( {a,b}\right)  \otimes  w\left( {b,c}\right) ,\{ b\} }\right)$ ;

(ii) $\left( {a,c,{w}_{1},B\left( {ac}\right) }\right)  \oplus  \left( {a,c,{w}_{2},{B}^{\prime }\left( {ac}\right) }\right)  \rightarrow  \left( {a,c,{w}_{1} \oplus  {w}_{2},B\left( {ac}\right)  \cup  }\right.$ ${B}^{\prime }\left( {ac}\right) )$ .

(ii) $\left( {a,c,{w}_{1},B\left( {ac}\right) }\right)  \oplus  \left( {a,c,{w}_{2},{B}^{\prime }\left( {ac}\right) }\right)  \rightarrow  \left( {a,c,{w}_{1} \oplus  {w}_{2},B\left( {ac}\right)  \cup  }\right.$${B}^{\prime }\left( {ac}\right) )$。

Our hard instance is initially distributed in such a way that ${R}_{1}$ and ${R}_{2}$ are on disjoint servers. This means that initially,there are only type (1) tuples without any communication. We allow each server to store all tuples it has received from previous rounds, thus we may assume that they emit the final results only in the last round. We may assume w.l.o.g. that at the end of each round (i.e., after local computation and before sending messages to the next round), a server keeps at most one aggregate tuple for each (a,c)pair,because if there are two,they can be combined using operation (ii) to produce a more useful aggregate tuple. We call such an aggregate tuple a partial result for(a,c)if $B\left( {ac}\right)  \neq  \operatorname{dom}\left( B\right)$ . Each partial result must be later aggregated with another produced by some other server (otherwise there is no point in producing this partial result at all), so at least half of all partial results must be shuffled.

我们的困难实例初始分布方式使得${R}_{1}$和${R}_{2}$位于不同服务器上。这意味着初始阶段仅存在类型(1)元组且无需通信。允许每个服务器存储其从先前轮次接收的所有元组，因此可假定它们仅在最后一轮输出最终结果。不失一般性，可假设每轮结束时（即本地计算完成后、向下轮发送消息前），服务器对每个(a,c)键值对至多保留一个聚合元组——若存在两个，则可通过操作(ii)合并为更具价值的聚合元组。当$B\left( {ac}\right)  \neq  \operatorname{dom}\left( B\right)$时，我们称此类聚合元组为(a,c)的部分结果。每个部分结果后续必须与其他服务器生成的另一结果聚合（否则生成该部分结果毫无意义），因此至少半数部分结果需经混洗传输。

Consider the time point before the last round of shuffling. Let $\left( {a,c,{w}_{i},{B}^{i}\left( {ac}\right) }\right)$ be the aggregate tuple stored on server $i$ for(a,c) if it exists,and define ${B}^{i}\left( {ac}\right)  = \varnothing$ otherwise. We call an output pair(a,c)half-complete if $\left| {{ \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right) }\right|  > \frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$ ,otherwise half-incomplete. Consider the following two cases:

考虑最后一轮混洗前的时间点。若存在，令$\left( {a,c,{w}_{i},{B}^{i}\left( {ac}\right) }\right)$表示服务器$i$上存储的(a,c)聚合元组；否则定义${B}^{i}\left( {ac}\right)  = \varnothing$。当$\left| {{ \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right) }\right|  > \frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$时，我们称输出对(a,c)为半完成态，否则为半未完成态。以下分析两种情形：

Case 1: More than $\frac{\mathrm{{OUT}}}{2}$ pairs are half-incomplete. For each half-incomplete(a,c)pair,all the original tuples not aggregated so far must be brought to one server in the last round. There are at least $\frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$ such tuples in ${\sigma }_{A = a}{R}_{1}$ and also $\frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$ in ${\sigma }_{C = c}{R}_{2}$ . If the load is $L$ ,a server can load all such tuples for at most $\frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }$ different $a$ ’s and $\frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }$ different $c$ ’s. Thus,the server can complete at most ${\left( \frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }\right) }^{2} = O\left( \frac{{L}^{2} \cdot  \mathrm{{OUT}}}{{N}_{1}{N}_{2}}\right)$ half-incomplete pairs. Over $p$ servers,we must have $p \cdot  \frac{{L}^{2} \cdot  \mathrm{{OUT}}}{{N}_{1}{N}_{2}} \geq  \frac{\mathrm{{OUT}}}{2}$ ,thus $L = \Omega \left( \sqrt{\frac{{N}_{1}{N}_{2}}{p}}\right)$ .

情形1：超过$\frac{\mathrm{{OUT}}}{2}$个键值对处于半未完成态。对于每个半未完成态(a,c)对，所有未聚合的原始元组必须在末轮集中至同一服务器。${\sigma }_{A = a}{R}_{1}$中至少存在$\frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$个此类元组，${\sigma }_{C = c}{R}_{2}$中亦有$\frac{1}{2}\left| {\operatorname{dom}\left( B\right) }\right|$个。若负载为$L$，单个服务器最多可为$\frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }$个不同$a$和$\frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }$个不同$c$加载全部相关元组。因此，该服务器至多能完成${\left( \frac{2L}{\left| \operatorname{dom}\left( B\right) \right| }\right) }^{2} = O\left( \frac{{L}^{2} \cdot  \mathrm{{OUT}}}{{N}_{1}{N}_{2}}\right)$个半未完成态键值对。在$p$台服务器条件下，必有$p \cdot  \frac{{L}^{2} \cdot  \mathrm{{OUT}}}{{N}_{1}{N}_{2}} \geq  \frac{\mathrm{{OUT}}}{2}$，故$L = \Omega \left( \sqrt{\frac{{N}_{1}{N}_{2}}{p}}\right)$。

Case 2: More than $\frac{\mathrm{{OUT}}}{2}$ pairs are half-complete. Then the total "work" done so far is $\mathop{\sum }\limits_{\left( a,c\right) }\left| {{ \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right) }\right|  = \Omega \left( {\mathrm{{OUT}} \cdot  \left| {\operatorname{dom}\left( B\right) }\right| }\right)$ . Let ${x}_{i}$ be the number of partial results generated by server $i$ so far. As argued above, at least half of the partial results must be shuffled, so $\mathop{\sum }\limits_{i}{x}_{i} = O\left( {pL}\right)$ .

情况2：超过$\frac{\mathrm{{OUT}}}{2}$对数据处于半完成状态。此时已完成的总"工作量"为$\mathop{\sum }\limits_{\left( a,c\right) }\left| {{ \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right) }\right|  = \Omega \left( {\mathrm{{OUT}} \cdot  \left| {\operatorname{dom}\left( B\right) }\right| }\right)$。设${x}_{i}$表示服务器$i$迄今生成的局部结果数量。根据前述论证，至少半数局部结果需经过混洗处理，因此$\mathop{\sum }\limits_{i}{x}_{i} = O\left( {pL}\right)$。

Now, let's consider how much these partial results can contribute to the work done so far. The key is to interpret the work done as a subset of the full join ${R}_{1} \bowtie  {R}_{2}$ ,where a full join result (a,b,c)is "done" if $b \in  { \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right)$ . Note that a server contributes (a,b,c)to the work done in a round only if it has the original tuples $\left( {a,b,w\left( {a,b}\right) }\right) ,\left( {b,c,w\left( {b,c}\right) }\right)$ ,and it keeps the partial result for(a,c) at the end of the round. This becomes the triangle join problem, where the server has $O\left( L\right)$ tuples in ${R}_{1}\left( {A,B}\right) ,O\left( L\right)$ tuples in ${R}_{2}\left( {B,C}\right)$ , and ${x}_{i}$ tuples in an imaginary relation ${R}_{3}\left( {A,C}\right)$ that consists of all the(a,c)pairs for which the servers has ever kept a partial result. By the AGM bound, the total work contributed by the server is therefore at most $O\left( {L \cdot  \sqrt{{x}_{i}}}\right)$ . So,the maximum contribution made by $p$ servers is characterized by the following linear program.

现在分析这些局部结果对当前工作量的贡献度。关键在于将已完成工作解释为全连接${R}_{1} \bowtie  {R}_{2}$的子集，其中全连接结果(a,b,c)的"完成"条件为$b \in  { \cup  }_{i \in  \left\lbrack  p\right\rbrack  }{B}^{i}\left( {ac}\right)$。注意，服务器仅当持有原始元组$\left( {a,b,w\left( {a,b}\right) }\right) ,\left( {b,c,w\left( {b,c}\right) }\right)$且在本轮结束时保留(a,c)的局部结果时，才会将(a,b,c)计入该轮工作量。这就转化为三角连接问题：服务器在${R}_{1}\left( {A,B}\right) ,O\left( L\right)$中包含$O\left( L\right)$个元组，${R}_{2}\left( {B,C}\right)$中包含${x}_{i}$个元组，以及虚构关系${R}_{3}\left( {A,C}\right)$中存储所有曾保留局部结果的(a,c)对。根据AGM界，该服务器贡献的总工作量上限为$O\left( {L \cdot  \sqrt{{x}_{i}}}\right)$。因此，$p$台服务器的最大贡献度可由以下线性规划表征。

$$
\max \mathop{\sum }\limits_{{i = 1}}^{p}L \cdot  \sqrt{{x}_{i}}
$$

$$
\text{s.t.}{x}_{1} + {x}_{2} + \cdots  + {x}_{p} \leq  p \cdot  L
$$

$$
{x}_{i} \geq  0,i = 1,\ldots p\text{.}
$$

The optimal solution for the LP above is $p \cdot  {L}^{3/2}$ ,when all ${x}_{i}$ ’s take the same value $L$ . Thus,we must have

上述线性规划的最优解为$p \cdot  {L}^{3/2}$，当所有${x}_{i}$取相同值$L$时成立。因此必有：

$$
p \cdot  {L}^{3/2} = \Omega \left( {\mathrm{{OUT}} \cdot  \left| {\operatorname{dom}\left( B\right) }\right| }\right)  = \Omega \left( \sqrt{{N}_{1}{N}_{2}\mathrm{{OUT}}}\right) ,
$$

i.e., $L = \Omega \left( \frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}\right)$ .

即$L = \Omega \left( \frac{{N}_{1}^{1/3} \cdot  {N}_{2}^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}\right)$。

Taking the minimum of the two cases, we obtain the desired lower bound.

综合两种情形取最小值，即得所需下界。

Remark. We note that there is an $\Omega \left( {\min \left\{  {\frac{N}{B}\sqrt{\frac{\mathrm{{OUT}}}{M}},\frac{{N}^{2}}{MB}}\right\}  }\right)$ lower bound for this problem in the semiring external memory model when ${N}_{1} = {N}_{2} = N$ [21]. Meanwhile,there is an MPC-to-EM reduction [17], which states that any MPC algorithm running in $r$ rounds with load $L\left( {N,\mathrm{{OUT}},p}\right)$ can be converted to an external memory algorithm incurring $\widetilde{O}\left( {\frac{N}{B} + r{p}^{ * }\frac{M}{B}}\right)$ I/Os,where ${p}^{ * } = \mathop{\min }\limits_{p}\{ L\left( {N,\mathrm{{OUT}},p}\right)  \leq  M/r\}$ . Taking $M = \Theta \left( B\right)$ ,the external memory lower bound implies a lower bound for constant-round matrix multiplication algorithms in the semiring MPC model as $\widetilde{\Omega }\left( {\min \left\{  {{\left( \frac{N}{p}\right) }^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3},\frac{N}{\sqrt{p}}}\right\}  }\right)$ . However,our lower bound holds for unequal matrix sizes ${N}_{1},{N}_{2}$ as well. Moreover,since our proof is conducted in the MPC model directly, it avoids the poly-logarithmic factors introduced during the MPC-to-EM reduction.

注记。我们注意到当${N}_{1} = {N}_{2} = N$时，半环外存模型中该问题存在$\Omega \left( {\min \left\{  {\frac{N}{B}\sqrt{\frac{\mathrm{{OUT}}}{M}},\frac{{N}^{2}}{MB}}\right\}  }\right)$下界[21]。同时存在MPC到EM的归约[17]，该归约表明任何在$r$轮次运行且负载为$L\left( {N,\mathrm{{OUT}},p}\right)$的MPC算法，都可转换为引发$\widetilde{O}\left( {\frac{N}{B} + r{p}^{ * }\frac{M}{B}}\right)$次I/O操作的外存算法，其中${p}^{ * } = \mathop{\min }\limits_{p}\{ L\left( {N,\mathrm{{OUT}},p}\right)  \leq  M/r\}$。取$M = \Theta \left( B\right)$时，外存下界意味着半环MPC模型中恒定轮次矩阵乘法算法的下界为$\widetilde{\Omega }\left( {\min \left\{  {{\left( \frac{N}{p}\right) }^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3},\frac{N}{\sqrt{p}}}\right\}  }\right)$。然而，我们的下界对于不等尺寸矩阵${N}_{1},{N}_{2}$同样成立。此外，由于我们的证明直接在MPC模型中进行，避免了MPC到EM归约过程中引入的多对数因子。

## 4 LINE QUERIES

## 4 线性查询

In this section, we investigate the chain matrix multiplication problem, which is equivalent to a line query with the two "boundary" attributes being the output attributes:

本节研究链式矩阵乘法问题，该问题等价于以两个"边界"属性作为输出属性的线性查询：

$$
\mathop{\sum }\limits_{{{A}_{2},{A}_{3},\cdots ,{A}_{n}}}{R}_{1}\left( {{A}_{1},{A}_{2}}\right)  \bowtie  {R}_{2}\left( {{A}_{2},{A}_{3}}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) .
$$

We will design a recursive algorithm for handling such a line query over $n$ relations,with the base $n = 2$ being just matrix multiplication. We will assume that all $n$ relations have the same size $N$ , but during the recursion, we will actually need the matrix multiplication algorithm for unequal matrix sizes as described in Section 3.

我们将设计递归算法处理$n$个关系上的此类线性查询，其基础$n = 2$就是矩阵乘法。假设所有$n$个关系都具有相同尺寸$N$，但在递归过程中实际需要第3节所述适用于不等尺寸矩阵的乘法算法。

### 4.1 The algorithm

### 4.1 算法

We first remove all dangling tuples and then obtain a constant-factor approximation of OUT using the primitive described in Section 2.2.

首先移除所有悬空元组，然后使用第2.2节描述的基元获得OUT的常数因子近似。

Step 1: Compute data statistics. We first compute for each value $a \in  \operatorname{dom}\left( {A}_{2}\right)$ its degree in relation ${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$ using the reduce-by-key primitive. The value $a \in  \operatorname{dom}\left( {A}_{2}\right)$ is heavy if its degree in relation ${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$ is greater than $\sqrt{\mathrm{{OUT}}}$ and light otherwise. The set of heavy values in $\operatorname{dom}\left( {A}_{2}\right)$ is denoted as

步骤1：计算数据统计量。首先使用键值归约基元计算每个值$a \in  \operatorname{dom}\left( {A}_{2}\right)$在关系${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$中的度。若值$a \in  \operatorname{dom}\left( {A}_{2}\right)$在关系${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$中的度大于$\sqrt{\mathrm{{OUT}}}$则判定为重度值，否则为轻度值。$\operatorname{dom}\left( {A}_{2}\right)$中的重度值集合记为

$$
{A}_{2}^{\text{heavy }} = \left\{  {a \in  \operatorname{dom}\left( {A}_{2}\right)  : \left| {{\sigma }_{{A}_{2} = a}{R}_{1}\left( {{A}_{1},{A}_{2}}\right) }\right|  \geq  \sqrt{\mathrm{{OUT}}}}\right\}  
$$

and the set of light values in $\operatorname{dom}\left( {A}_{2}\right)$ is ${A}_{2}^{\text{light }} = \operatorname{dom}\left( {A}_{2}\right)  - {A}_{2}^{\text{heavy }}$ . The tuples in ${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$ and ${R}_{2}\left( {{A}_{2},{A}_{3}}\right)$ are also identified as heavy or light correspondingly,depending on their values in attribute ${A}_{2}$ .

而$\operatorname{dom}\left( {A}_{2}\right)$中的轻度值集合为${A}_{2}^{\text{light }} = \operatorname{dom}\left( {A}_{2}\right)  - {A}_{2}^{\text{heavy }}$。${R}_{1}\left( {{A}_{1},{A}_{2}}\right)$和${R}_{2}\left( {{A}_{2},{A}_{3}}\right)$中的元组也根据其在属性${A}_{2}$上的值相应标记为重度或轻度。

In this way, we decompose the original query into the following two subqueries:

通过这种方式，我们将原始查询分解为以下两个子查询：

$$
{Q}^{X} = \mathop{\sum }\limits_{{{A}_{2},\cdots ,{A}_{n}}}{R}_{1}\left( {{A}_{1},{A}_{2}^{X}}\right)  \bowtie  {R}_{2}\left( {{A}_{2}^{X},{A}_{3}}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) 
$$

where $X$ can be either heavy or light.

其中$X$可为重度或轻度值。

Step 2: Handling ${Q}^{\text{heavy }}$ . We first remove all dangling tuples in the heavy subquery. On the reduced subquery, our strategy is to (2.1) compute $R\left( {{A}_{2},{A}_{n + 1}}\right)  =$

步骤2：处理${Q}^{\text{heavy }}$。首先移除重度子查询中所有悬空元组。在归约后的子查询上，我们的策略是(2.1)计算$R\left( {{A}_{2},{A}_{n + 1}}\right)  =$

$$
\mathop{\sum }\limits_{{{A}_{3},{A}_{4},\cdots ,{A}_{n}}}{R}_{2}\left( {{A}_{2}^{\text{heavy }},{A}_{3}}\right)  \bowtie  {R}_{3}\left( {{A}_{3},{A}_{4}}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) 
$$

using the Yannakakis algorithm; and (2.2) reduce ${Q}^{\text{heavy }}$ to a matrix multiplication as $\mathop{\sum }\limits_{{A}_{2}}{R}_{1}\left( {{A}_{1},{A}_{2}^{\text{heavy }}}\right)  \bowtie  R\left( {{A}_{2}^{\text{heavy }},{A}_{n + 1}}\right)$ and compute it by the output-sensitive algorithm in Section 3.2. More precisely, when using the Yannakakis algorithm in step (2.1), we compute the query from right to left,i.e.,for $i = n - 1,n - 2,\cdots ,2$ , we compute $R\left( {{A}_{i},{A}_{n + 1}}\right)  = \mathop{\sum }\limits_{{A}_{i + 1}}{R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right)$ .

使用Yannakakis算法；以及(2.2)将${Q}^{\text{heavy }}$转化为矩阵乘法形式如$\mathop{\sum }\limits_{{A}_{2}}{R}_{1}\left( {{A}_{1},{A}_{2}^{\text{heavy }}}\right)  \bowtie  R\left( {{A}_{2}^{\text{heavy }},{A}_{n + 1}}\right)$，并通过第3.2节中的输出敏感算法进行计算。具体而言，在步骤(2.1)应用Yannakakis算法时，我们采用从右至左的查询计算顺序，即对于$i = n - 1,n - 2,\cdots ,2$，先计算$R\left( {{A}_{i},{A}_{n + 1}}\right)  = \mathop{\sum }\limits_{{A}_{i + 1}}{R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right)$。

Step 3: Handling ${Q}^{\text{light }}$ . In this case,our strategy is to (3.1) compute $R\left( {{A}_{1},{A}_{3}}\right)  = \mathop{\sum }\limits_{{A}_{2}}{R}_{1}\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)  \bowtie  {R}_{2}\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$ using the Yan-nakakis algorithm (i.e., just compute the join and then the aggregation); and (3.2) reduce ${Q}^{\text{light }}$ to a shorter line query as

步骤3：处理${Q}^{\text{light }}$。此时我们的策略是：(3.1)使用Yannakakis算法计算$R\left( {{A}_{1},{A}_{3}}\right)  = \mathop{\sum }\limits_{{A}_{2}}{R}_{1}\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)  \bowtie  {R}_{2}\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$（即先计算连接再执行聚合）；(3.2)将${Q}^{\text{light }}$转化为更短的链式查询

$$
\mathop{\sum }\limits_{{{A}_{3},{A}_{4},\cdots ,{A}_{n}}}R\left( {{A}_{1},{A}_{3}}\right)  \bowtie  {R}_{3}\left( {{A}_{3},{A}_{4}}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) 
$$

and compute it recursively.

并通过递归方式完成计算。

Step 4: Aggregate the two queries. Note that the two queries ${Q}^{\text{heavy }}$ and ${Q}^{\text{light }}$ may produce results with common values on ${A}_{1},{A}_{n + 1}$ ,so finally we need to aggregate all the results by ${A}_{1},{A}_{n + 1}$ using reduce-by-key.

步骤4：聚合两个查询结果。注意查询${Q}^{\text{heavy }}$和${Q}^{\text{light }}$可能在${A}_{1},{A}_{n + 1}$上产生重复值，因此最终需要使用reduce-by-key操作按${A}_{1},{A}_{n + 1}$聚合所有结果。

### 4.2 The analysis

### 4.2 分析

To facilitate the induction proof, we will actually prove a slightly tighter bound of our algorithm, as stated in the following lemma.

为便于归纳证明，我们将实际证明算法的一个更严格上界，如下述引理所述。

LEMMA 3. For a length-n line query with ${N}_{1} = \left| {{R}_{1}\left( {{A}_{1},{A}_{2}}\right) }\right| ,{N}_{n} =$ $\left| {{R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) }\right| ,N = \mathop{\max }\limits_{{i \in  \{ 2,3,\cdots ,n - 1\} }}\left| {{R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right) }\right|$ and output size as OUT,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $\widetilde{O}\left( L\right)$ w.h.p.,where $L = \frac{{\left( N \cdot  {N}_{1}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{\left( {N}_{1}{N}_{n}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}} +$ $\frac{{N}^{2/3} \cdot  {\mathrm{{OUT}}}^{2/3}}{{p}^{2/3}} + \frac{N \cdot  {\mathrm{{OUT}}}^{1/2} + N + {N}_{1} + {N}_{n} + \mathrm{{OUT}}}{p}.$

引理3. 对于长度为n的链式查询（其中${N}_{1} = \left| {{R}_{1}\left( {{A}_{1},{A}_{2}}\right) }\right| ,{N}_{n} =$$\left| {{R}_{n}\left( {{A}_{n},{A}_{n + 1}}\right) }\right| ,N = \mathop{\max }\limits_{{i \in  \{ 2,3,\cdots ,n - 1\} }}\left| {{R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right) }\right|$且输出规模为OUT），存在算法能以$O\left( 1\right)$轮次和$\widetilde{O}\left( L\right)$负载（高概率）完成计算，其中$L = \frac{{\left( N \cdot  {N}_{1}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{\left( {N}_{1}{N}_{n}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}} +$$\frac{{N}^{2/3} \cdot  {\mathrm{{OUT}}}^{2/3}}{{p}^{2/3}} + \frac{N \cdot  {\mathrm{{OUT}}}^{1/2} + N + {N}_{1} + {N}_{n} + \mathrm{{OUT}}}{p}.$

By setting ${N}_{1} = {N}_{n} = N$ in Lemma 3,we obtain the following theorem, as claimed in Table 1.

通过在引理3中设定${N}_{1} = {N}_{n} = N$参数，我们得到如表1所述的下述定理。

THEOREM 4. For a line query with input size $N$ and output size OUT,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $O\left( {\frac{N \cdot  {\mathrm{{OUT}}}^{1/2}}{p} + {\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N + \mathrm{{OUT}}}{p}}\right)$ .

定理4. 对于输入规模为$N$、输出规模为OUT的线性查询，存在一种算法可在$O\left( 1\right)$轮次内完成计算，其负载为$O\left( {\frac{N \cdot  {\mathrm{{OUT}}}^{1/2}}{p} + {\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N + \mathrm{{OUT}}}{p}}\right)$。

We prove Lemma 3 in the rest of this section. Note that the base case $n = 2$ is just Lemma 2 . For a line query with $n \geq  3$ ,we consider the load of our algorithm in each of the four steps.

我们将在本节剩余部分证明引理3。注意基本情况$n = 2$即为引理2。对于具有$n \geq  3$的线性查询，我们分四个步骤分析算法的负载。

Step 1 has linear load $O\left( \frac{N + {N}_{1} + {N}_{n}}{p}\right)$ ,since it only involves primitives. Step 4 incurs a load of $O\left( \frac{\text{ OUT }}{p}\right)$ since each subquery produces at most OUT results, which are the input for the reduce-by-key primitive. Before analyzing the load complexity for Step 2, we point out one important property of ${Q}^{\text{heavy }}$ :

步骤1的负载为线性$O\left( \frac{N + {N}_{1} + {N}_{n}}{p}\right)$，因其仅涉及基本操作。步骤4产生$O\left( \frac{\text{ OUT }}{p}\right)$的负载，因为每个子查询最多生成OUT个结果，这些结果将作为键值归约操作的输入。在分析步骤2的负载复杂度前，我们指出${Q}^{\text{heavy }}$的一个重要特性：

LEMMA 4. In ${Q}^{\text{heavy }}$ ,for any $i \geq  2$ ,each value $b \in  \operatorname{dom}\left( {A}_{i}\right)$ can join with at least $\sqrt{\mathrm{{OUT}}}$ disjoint values in $\operatorname{dom}\left( {A}_{1}\right)$ .

引理4. 在${Q}^{\text{heavy }}$中，对于任意$i \geq  2$，每个值$b \in  \operatorname{dom}\left( {A}_{i}\right)$至少能与$\operatorname{dom}\left( {A}_{1}\right)$中的$\sqrt{\mathrm{{OUT}}}$个互异值进行连接。

Proof. We prove it by induction on $i$ . The lemma holds for $i = 2$ by the definition of heavy values in attribute ${A}_{2}$ . Now assume that the lemma holds for $i$ . Consider an arbitrary value $b \in  \operatorname{dom}\left( {A}_{i + 1}\right)$ . Recall that all dangling tuples have been removed, so there must exist a tuple $\left( {{b}^{\prime },b}\right)  \in  R\left( {{A}_{i},{A}_{i + 1}}\right)$ . By the induction hypothesis, ${b}^{\prime }$ can join with at least $\sqrt{\mathrm{{OUT}}}$ distinct values in attribute ${A}_{1}$ ,thus $b$ can also join with at least $\sqrt{\mathrm{{OUT}}}$ distinct values in attribute ${A}_{1}$ .

证明. 我们通过对$i$的归纳来证明。根据属性${A}_{2}$中重值的定义，引理在$i = 2$时成立。现假设引理对$i$成立。考虑任意值$b \in  \operatorname{dom}\left( {A}_{i + 1}\right)$。由于所有悬空元组已被移除，故必存在元组$\left( {{b}^{\prime },b}\right)  \in  R\left( {{A}_{i},{A}_{i + 1}}\right)$。根据归纳假设，${b}^{\prime }$至少能与属性${A}_{1}$中的$\sqrt{\mathrm{{OUT}}}$个不同值连接，因此$b$同样至少能与属性${A}_{1}$中的$\sqrt{\mathrm{{OUT}}}$个不同值连接。

In Step (2.1), we claim that the size of any intermediate join $R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right)$ during the Yannakakis algorithm is at most $N \cdot  \sqrt{\mathrm{{OUT}}}$ . Consider any $i \in  \{ 2,3,\cdots ,n - 1\}$ . To relate the intermediate join size with OUT, we introduce an additional relation $R\left( {{A}_{1},{A}_{i}}\right)  =$

在步骤(2.1)中，我们断言Yannakakis算法过程中任何中间连接$R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right)$的大小至多为$N \cdot  \sqrt{\mathrm{{OUT}}}$。考虑任意$i \in  \{ 2,3,\cdots ,n - 1\}$。为建立中间连接规模与OUT的关联，我们引入额外关系$R\left( {{A}_{1},{A}_{i}}\right)  =$

$$
\mathop{\sum }\limits_{{{A}_{2},\cdots ,{A}_{i - 1}}}R\left( {{A}_{1},{A}_{2}^{\text{heavy }}}\right)  \bowtie  R\left( {{A}_{2}^{\text{heavy }},{A}_{3}}\right)  \bowtie  \cdots  \bowtie  R\left( {{A}_{i - 1},{A}_{i}}\right) .
$$

Note that this relation is only used in the analysis but not computed by our algorithm. We can bound $\left| {R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right) }\right|$ by $N \cdot  \sqrt{\mathrm{{OUT}}}$ since

请注意此关系仅用于分析而未被算法计算。我们可以用$N \cdot  \sqrt{\mathrm{{OUT}}}$来界定$\left| {R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right) }\right|$的范围，因为

$$
N \cdot  \mathrm{{OUT}} = \left| {R\left( {{A}_{1},{A}_{n + 1}}\right) }\right|  \cdot  \left| {R\left( {{A}_{i},{A}_{i + 1}}\right) }\right| 
$$

$$
 \geq  \left| {R\left( {{A}_{1},{A}_{i}}\right)  \bowtie  {R}_{i}\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right) }\right| 
$$

$$
 \geq  \left| {R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right) }\right|  \cdot  \mathop{\min }\limits_{b}\left| {{\sigma }_{{A}_{i} = b}R\left( {{A}_{1},{A}_{i}}\right) }\right| 
$$

$$
 \geq  \left| {R\left( {{A}_{i},{A}_{i + 1}}\right)  \bowtie  R\left( {{A}_{i + 1},{A}_{n + 1}}\right) }\right|  \cdot  \sqrt{\mathrm{{OUT}}}\text{,}
$$

where the last inequality follows from Lemma 4. So this step has a load of $O\left( {\frac{N}{p} + \frac{N \cdot  \sqrt{\text{OUT}}}{p}}\right)$ . In Step (2.2),the input relations of matrix multiplication problem have their sizes bounded by ${N}_{1}$ and $N \cdot  \sqrt{\mathrm{{OUT}}}$ respectively. Plugging to Lemma 2,it can be computed with load $O\left( {\frac{{\left( N{N}_{1}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)  = O\left( L\right)$ .

其中最后一个不等式由引理4得出。因此该步骤的负载为$O\left( {\frac{N}{p} + \frac{N \cdot  \sqrt{\text{OUT}}}{p}}\right)$。在步骤(2.2)中，矩阵乘法问题的输入关系其大小分别受${N}_{1}$和$N \cdot  \sqrt{\mathrm{{OUT}}}$限制。代入引理2后，可用负载$O\left( {\frac{{\left( N{N}_{1}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p} + \frac{\mathrm{{OUT}}}{p}}\right)  = O\left( L\right)$完成计算。

In Step (3.1),the size of full join $R\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)  \bowtie  R\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$ is at most $N \cdot  \sqrt{\mathrm{{OUT}}}$ ,since each tuple in $R\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$ can join with at most $\sqrt{\mathrm{{OUT}}}$ tuples in $R\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)$ ,implied by the definition of light values in ${A}_{2}$ . So this step has load $O\left( {\frac{N + {N}_{1}}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  = O\left( L\right)$ . Moreover,the size of $R\left( {{A}_{1},{A}_{3}}\right)$ is also bounded by $N \cdot  \sqrt{\mathrm{{OUT}}}$ . For Step (3.2),we invoke the induction hypothesis with ${N}_{1} = N \cdot  \sqrt{\mathrm{{OUT}}}$ , hence bounding its load by (the big-Oh of)

在步骤(3.1)中，全连接$R\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)  \bowtie  R\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$的大小至多为$N \cdot  \sqrt{\mathrm{{OUT}}}$，因为根据${A}_{2}$中轻值定义，$R\left( {{A}_{2}^{\text{light }},{A}_{3}}\right)$中的每个元组最多可与$R\left( {{A}_{1},{A}_{2}^{\text{light }}}\right)$中的$\sqrt{\mathrm{{OUT}}}$个元组连接。故此步骤负载为$O\left( {\frac{N + {N}_{1}}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  = O\left( L\right)$。此外，$R\left( {{A}_{1},{A}_{3}}\right)$的大小同样受$N \cdot  \sqrt{\mathrm{{OUT}}}$限制。对于步骤(3.2)，我们使用${N}_{1} = N \cdot  \sqrt{\mathrm{{OUT}}}$调用归纳假设，从而将其负载限定为(大O记号表示的)

$$
\frac{{\left( N \cdot  N \cdot  \sqrt{\mathrm{{OUT}}}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{\left( N \cdot  \sqrt{\mathrm{{OUT}}} \cdot  {N}_{n}\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}}
$$

$$
 + \frac{{N}^{2/3} \cdot  {\mathrm{{OUT}}}^{2/3}}{{p}^{2/3}} + \frac{N + N \cdot  {\mathrm{{OUT}}}^{1/2} + {N}_{n} + \mathrm{{OUT}}}{p} \leq  L.
$$

Summing over all steps, we conclude the proof of Lemma 3.

综合所有步骤，我们完成引理3的证明。

## 5 STAR QUERIES

## 5 星型查询

In this section, we study the star query

本节我们将研究星型查询

$$
\mathop{\sum }\limits_{B}{R}_{1}\left( {{A}_{1},B}\right)  \bowtie  {R}_{2}\left( {{A}_{2},B}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},B}\right) ,
$$

which can be considered as another way to generalize the matrix multiplication problem.

这可以视为矩阵乘法问题的另一种推广形式。

As with the line query, the basic idea of handling a star query is to recursively reduce $n$ until $n = 2$ . However,an inherent difficulty for the star query is that it is not known how to compute a constant-factor approximation of OUT without actually computing all the query results. One standard technique to repeatedly double a guess of OUT and try to run the algorithm, until the guess is correct (i.e., within a constant factor of the true value). This would work in a sequential model, since the running times of the successive guesses will form a geometric series, increasing the total running time by only a constant factor. However, in the parallel model like the MPC, although the total load can still be bounded, but the repeated guesses would lead to $O\left( {\log N}\right)$ rounds of computation.

与链式查询类似，处理星型查询的基本思路是递归缩减$n$直至$n = 2$。但星型查询的固有难点在于：若不实际计算所有查询结果，就无法确定OUT值的常数倍近似解。标准做法是不断加倍OUT的估计值并运行算法，直到估值正确（即处于真实值的常数倍范围内）。这在串行模型中可行，因为连续估值的运行时间会形成几何级数，仅以常数倍增加总运行时间。但在MPC这类并行模型中，虽然总负载仍可界定，重复估值会导致$O\left( {\log N}\right)$轮计算。

Below, we design a constant-round MPC algorithm whose load can be bounded by (a function of) OUT. The idea is to make the algorithm oblivious to the value of OUT, i.e., the value of OUT is not needed by the algorithm but only used in the analysis.

下文我们将设计恒定轮次的MPC算法，其负载可由OUT（的函数）界定。核心思路是使算法不依赖OUT的具体数值——该值仅用于分析而非法案执行过程。

As before, we first remove all dangling tuples. Then we compute the query in the following 3 steps.

如前所述，我们首先移除所有悬空元组，随后通过以下3个步骤执行查询。

Step 1: Compute data statistics. We first compute for each value $b \in  \operatorname{dom}\left( B\right)$ its degree in relation ${R}_{i}\left( {{A}_{i},B}\right)$ for $i \in  \left\lbrack  n\right\rbrack$ ,denoted as ${d}_{i}\left( b\right)$ ,using reduce-by-key primitive. For each $b \in  \operatorname{dom}\left( B\right)$ ,we compute a permutation ${\phi }_{b} : \left\lbrack  n\right\rbrack   \rightarrow  \left\lbrack  n\right\rbrack$ such that ${d}_{{\phi }_{b}\left( i\right) }\left( b\right)  \leq  {d}_{{\phi }_{b}\left( j\right) }\left( b\right)$ for any $1 \leq  i < j \leq  n$ . Note that we can determine ${\phi }_{b}$ for all $b$ ’s by sorting all values in $\operatorname{dom}\left( B\right)$ ,breaking ties by ${d}_{i}\left( b\right)$ .

步骤1：计算数据统计量。首先针对关系${R}_{i}\left( {{A}_{i},B}\right)$中的每个值$b \in  \operatorname{dom}\left( B\right)$，计算其在$i \in  \left\lbrack  n\right\rbrack$中的度数（记为${d}_{i}\left( b\right)$），使用reduce-by-key原语。对每个$b \in  \operatorname{dom}\left( B\right)$，计算排列${\phi }_{b} : \left\lbrack  n\right\rbrack   \rightarrow  \left\lbrack  n\right\rbrack$使得对任意$1 \leq  i < j \leq  n$满足${d}_{{\phi }_{b}\left( i\right) }\left( b\right)  \leq  {d}_{{\phi }_{b}\left( j\right) }\left( b\right)$。注意可通过排序$\operatorname{dom}\left( B\right)$中所有值（按${d}_{i}\left( b\right)$打破平局）来确定所有$b$对应的${\phi }_{b}$。

For a permutation $\phi$ of $\left\lbrack  n\right\rbrack$ ,let ${B}_{\phi } = \left\{  {b \in  \operatorname{dom}\left( B\right)  : {\phi }_{b} = \phi }\right\}$ . This decomposes $\operatorname{dom}\left( B\right)$ into $n$ ! subsets,which leads to $n$ ! subqueries, each defined by a distinct permutation $\phi$ :

对于$\left\lbrack  n\right\rbrack$的排列$\phi$，令${B}_{\phi } = \left\{  {b \in  \operatorname{dom}\left( B\right)  : {\phi }_{b} = \phi }\right\}$。这将$\operatorname{dom}\left( B\right)$分解为$n$!个子集，对应生成$n$!个子查询，每个子查询由唯一排列$\phi$定义：

$$
{Q}_{\phi } = \mathop{\sum }\limits_{B}{\sigma }_{B \in  {B}_{\phi }}{R}_{1}\left( {{A}_{1},B}\right)  \bowtie  {R}_{2}\left( {{A}_{2},B}\right)  \bowtie  \cdots  \bowtie  {R}_{n}\left( {{A}_{n},B}\right) .
$$

We handle each subquery separately by applying the steps below.

我们通过以下步骤分别处理每个子查询。

Step 2: Reduce to matrix multiplication. Note that we can allocate $p$ servers for each subquery. As the number of subqueries is a constant,the number of servers used in this step is $O\left( p\right)$ .

步骤2：归约为矩阵乘法。注意到可为每个子查询分配$p$台服务器。由于子查询数量为常数，本步骤使用的服务器总数是$O\left( p\right)$。

Consider ${Q}_{\phi }$ defined by some permutation $\phi$ . We first compute the following two intermediate joins by the Yannakakis algorithm:

考虑由排列$\phi$定义的${Q}_{\phi }$。首先通过Yannakakis算法计算以下两个中间连接：

$$
{R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)  = { \bowtie  }_{i \in  \left\lbrack  n\right\rbrack   : i\text{ is odd }}{\sigma }_{B \in  {B}_{\phi }}R\left( {{A}_{\phi \left( i\right) },B}\right) 
$$

$$
{R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)  = { \bowtie  }_{j \in  \left\lbrack  n\right\rbrack   : j\text{ is even }}{\sigma }_{B \in  {B}_{\phi }}R\left( {{A}_{\phi \left( j\right) },B}\right) 
$$

where ${\mathcal{A}}^{\text{odd }} = \left\{  {{A}_{\phi \left( i\right) } : i \in  \left\lbrack  n\right\rbrack  ,i\text{ is odd }}\right\}$ and ${\mathcal{A}}^{\text{even }} = \left\{  {A}_{\phi \left( j\right) }\right.$ : $j \in  \left\lbrack  n\right\rbrack  ,j$ is even $\}$ partitions the output attributes $\left\{  {{A}_{1},{A}_{2},\ldots ,{A}_{n}}\right\}$ . Then,we reduce the subquery ${\mathcal{Q}}_{\phi }$ into a matrix multiplication

其中${\mathcal{A}}^{\text{odd }} = \left\{  {{A}_{\phi \left( i\right) } : i \in  \left\lbrack  n\right\rbrack  ,i\text{ is odd }}\right\}$与${\mathcal{A}}^{\text{even }} = \left\{  {A}_{\phi \left( j\right) }\right.$：当$j \in  \left\lbrack  n\right\rbrack  ,j$为偶数时，$\}$划分输出属性$\left\{  {{A}_{1},{A}_{2},\ldots ,{A}_{n}}\right\}$。随后将子查询${\mathcal{Q}}_{\phi }$归约为矩阵乘法

$$
\mathop{\sum }\limits_{B}{R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)  \bowtie  {R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right) ,
$$

and compute it by invoking the output-sensitive algorithm in Section 3.2.

并通过调用第3.2节的输出敏感算法进行计算。

Now we analyze the load of this step. The key is to bound the sizes of ${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$ and ${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$ . We first state the following two facts:

现分析本步骤负载。关键在于界定${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$和${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$的规模上限。首先陈述以下两个事实：

LEMMA 5. For any $b \in  \operatorname{dom}\left( B\right) ,\mathop{\prod }\limits_{{j = 1}}^{n}{d}_{j}\left( b\right)  \leq$ OUT .

引理5. 对于任意$b \in  \operatorname{dom}\left( B\right) ,\mathop{\prod }\limits_{{j = 1}}^{n}{d}_{j}\left( b\right)  \leq$ OUT。

This lemma follows immediately from the fact that for each value $b \in  \operatorname{dom}\left( B\right) ,{ \bowtie  }_{i \in  \left\lbrack  n\right\rbrack  }{\sigma }_{B = b}{R}_{i}\left( {{A}_{i},B}\right)$ is a subset of final output result.

该引理直接源于：每个值$b \in  \operatorname{dom}\left( B\right) ,{ \bowtie  }_{i \in  \left\lbrack  n\right\rbrack  }{\sigma }_{B = b}{R}_{i}\left( {{A}_{i},B}\right)$都是最终输出结果的子集。

LEMMA 6. Let ${d}_{1} \leq  {d}_{2} \leq  \cdots  \leq  {d}_{n}$ be a set of positive integers with $\mathop{\prod }\limits_{{i = 1}}^{n}{d}_{i} = \lambda$ . Then $\max \left\{  {\mathop{\prod }\limits_{{i \in  I}}{d}_{i},\mathop{\prod }\limits_{{j \in  J}}{d}_{j}}\right\}   \leq  \sqrt{\lambda }$ where $I =$ $\{ i \in  \left\lbrack  {n - 2}\right\rbrack   : i$ is odd $\}$ and $J = \{ j \in  \left\lbrack  {n - 2}\right\rbrack   : j$ is even $\} .$

引理6. 设${d}_{1} \leq  {d}_{2} \leq  \cdots  \leq  {d}_{n}$为一组正整数集合且满足$\mathop{\prod }\limits_{{i = 1}}^{n}{d}_{i} = \lambda$。则有$\max \left\{  {\mathop{\prod }\limits_{{i \in  I}}{d}_{i},\mathop{\prod }\limits_{{j \in  J}}{d}_{j}}\right\}   \leq  \sqrt{\lambda }$，其中$I =$$\{ i \in  \left\lbrack  {n - 2}\right\rbrack   : i$为奇数$\}$，而$J = \{ j \in  \left\lbrack  {n - 2}\right\rbrack   : j$为偶数$\} .$

Proof. If $n$ is odd. It suffices to show $\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i} \leq  \sqrt{\lambda }$ since the other term derived on even-index elements is dominated. Observe that

证明. 若$n$为奇数。只需证$\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i} \leq  \sqrt{\lambda }$，因为由偶数索引元素导出的另一项已被支配。观察到

$$
\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i} \leq  {N}_{n - 1} \cdot  \mathop{\prod }\limits_{{j \in  \left\lbrack  {n - 2}\right\rbrack   : j\text{ is even }}}{d}_{j}
$$

Moreover, $\left( {\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i}}\right)  \cdot  \left( {{N}_{n - 1} \cdot  \mathop{\prod }\limits_{{j \in  \left\lbrack  {n - 2}\right\rbrack   : j\text{ is even }}}{d}_{j}}\right)  =$ $\mathop{\prod }\limits_{{i = 1}}^{{n - 1}}{d}_{i} \leq  \lambda$ ,so there must be $\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i} \leq  \sqrt{\lambda }$ . The case with even $n$ can be proved symmetrically.

此外，$\left( {\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i}}\right)  \cdot  \left( {{N}_{n - 1} \cdot  \mathop{\prod }\limits_{{j \in  \left\lbrack  {n - 2}\right\rbrack   : j\text{ is even }}}{d}_{j}}\right)  =$$\mathop{\prod }\limits_{{i = 1}}^{{n - 1}}{d}_{i} \leq  \lambda$，故必然存在$\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{i} \leq  \sqrt{\lambda }$。当$n$为偶数的情况可对称地证明。

Assume $n$ is odd (and case of even $n$ is simpler). We can bound the size of ${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$ as follows (the size of ${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$ can be bounded similarly):

假设$n$为奇数（偶数情形更简单）。我们可如下界定${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$的规模（${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$的规模可类似界定）：

$$
\left| {{R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right) }\right|  = \mathop{\sum }\limits_{{b \in  {B}_{\phi }}}\mathop{\prod }\limits_{{i \in  \left\lbrack  n\right\rbrack   : i\text{ is odd }}}{d}_{\phi \left( i\right) }\left( b\right) 
$$

$$
 \leq  \left( {\mathop{\max }\limits_{{b \in  {B}_{\phi }}}\mathop{\prod }\limits_{{i \in  \left\lbrack  {n - 2}\right\rbrack   : i\text{ is odd }}}{d}_{\phi \left( i\right) }\left( b\right) }\right)  \cdot  \mathop{\sum }\limits_{{b \in  {B}_{\phi }}}{d}_{\phi \left( n\right) }\left( b\right) 
$$

$$
 \leq  \mathop{\max }\limits_{{b \in  {B}_{\phi }}}\sqrt{\mathop{\prod }\limits_{{i \in  \left\lbrack  n\right\rbrack  }}{d}_{\phi \left( i\right) }\left( b\right) } \cdot  \left| {R\left( {{A}_{\phi \left( n\right) },B}\right) }\right|  \leq  \sqrt{\mathrm{{OUT}}} \cdot  N,
$$

where the second inequality is implied by Lemma 6 and the last one is implied by Lemma 5.

其中第二个不等式由引理6推出，最后一个不等式由引理5推出。

Thus,the load of computing ${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$ and ${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$ is bounded by $O\left( {\frac{N}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)$ . Plugging ${N}_{1} = {N}_{2} = N \cdot  \sqrt{\mathrm{{OUT}}}$ to Lemma 2, the load of computing the matrix multiplication is $O\left( {{\left( \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}\right) }^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  = O\left( {{\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right) .$

因此，计算${R}_{\phi }\left( {{\mathcal{A}}^{\text{odd }},B}\right)$与${R}_{\phi }\left( {{\mathcal{A}}^{\text{even }},B}\right)$的负载被$O\left( {\frac{N}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)$限定。将${N}_{1} = {N}_{2} = N \cdot  \sqrt{\mathrm{{OUT}}}$代入引理2，矩阵乘法的计算负载为$O\left( {{\left( \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}\right) }^{2/3} \cdot  {\mathrm{{OUT}}}^{1/3} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  = O\left( {{\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right) .$

Step 3: Aggregate all subqueries. Finally, as with the line query, the $n$ ! subqueries from the star query may produce results with the same value on the output attributes, so we need to run the reduce-by-key primitive to aggregate all the results. As each subquery produces at most OUT results, the total number of results is still $O\left( \mathrm{{OUT}}\right)$ . So this step has a load of $O\left( \frac{\mathrm{{OUT}}}{p}\right)$ .

步骤3：聚合所有子查询。最后，与线性查询类似，星型查询中的$n$！子查询可能在输出属性上产生相同值的结果，因此需要运行按键归约原语来聚合所有结果。由于每个子查询最多产生OUT个结果，结果总数仍为$O\left( \mathrm{{OUT}}\right)$。故此步骤负载为$O\left( \frac{\mathrm{{OUT}}}{p}\right)$。

Summing up the costs of all the steps above, we obtain the following result.

综合上述所有步骤的成本，我们得到以下结果。

THEOREM 5. For a star query with input size $N$ and output size OUT,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $O\left( {{\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N \cdot  {\mathrm{{OUT}}}^{1/2}}{p} + \frac{N + \mathrm{{OUT}}}{p}}\right) .$

定理5. 对于输入规模为$N$、输出规模为OUT的星型查询，存在一种算法可在$O\left( 1\right)$轮次内完成计算，负载为$O\left( {{\left( \frac{N \cdot  \mathrm{{OUT}}}{p}\right) }^{2/3} + \frac{N \cdot  {\mathrm{{OUT}}}^{1/2}}{p} + \frac{N + \mathrm{{OUT}}}{p}}\right) .$

## 6 类星型查询

Before tackling general tree queries, in this section we investigate star-like queries, which can be seen as a combination of line and star queries. Star-like queries will be the building block of tree queries studies in Section 7. A star-like query is shown in Figure 1. More precisely,a star-like query consists of $n$ line queries that share a common non-output attribute $B$ . We call these line queries the arms of the query. Let ${\mathcal{T}}_{i} = \left( {{\mathcal{V}}_{i},{\mathcal{E}}_{i}}\right)$ be the $i$ -th arm. One end of the arm must be $B$ ,while the other end is denoted as ${A}_{i}$ ,which must be an output attribute. The remaining attributes are denoted as ${C}_{i1},{C}_{i2},\ldots$ ,which are non-output attributes. Note that a star-like query degenerates to a line query if $n = 2$ ,and to a star query if each arm contains only one relation.

在研究通用树状查询前，本节将探讨类星型查询——可视为线性查询与星型查询的组合。类星型查询将成为第7节树状查询研究的基础构件。如图1所示，具体而言，类星型查询由共享一个共同非输出属性$B$的$n$条线性查询组成，这些线性查询称为查询的臂。设${\mathcal{T}}_{i} = \left( {{\mathcal{V}}_{i},{\mathcal{E}}_{i}}\right)$为第$i$条臂，其一端必须是$B$，另一端记为输出属性${A}_{i}$，其余非输出属性记为${C}_{i1},{C}_{i2},\ldots$。注意：当$n = 2$时，类星型查询退化为线性查询；当每条臂仅含一个关系时，则退化为星型查询。

As with star queries, we will design an algorithm that is oblivious to OUT. We first remove all dangling tuples. Then we carry out the following steps.

与星型查询类似，我们将设计不依赖OUT的算法。首先移除所有悬空元组，然后执行以下步骤。

Step 1: Compute data statistics. Consider any $i \in  \left\lbrack  n\right\rbrack$ . In the algorithm for star queries,we first computed ${d}_{i}\left( b\right)$ for each value $b \in  \operatorname{dom}\left( B\right)$ ,which is the number of values in $\operatorname{dom}\left( {A}_{i}\right)$ that can join with $b$ . When the arm ${\mathcal{T}}_{i}$ has more than one relation,we cannot obtain ${d}_{i}\left( b\right)$ accurately,but this can be estimated within a constant factor by applying the primitive in Section 2.2 to the arm. Below, we will not distinguish between ${d}_{i}\left( b\right)$ and its approximation,which will not affect our asymptotic analysis.

步骤1：计算数据统计量。考虑任意$i \in  \left\lbrack  n\right\rbrack$。在星型查询算法中，我们首先为每个值$b \in  \operatorname{dom}\left( B\right)$计算${d}_{i}\left( b\right)$（即$\operatorname{dom}\left( {A}_{i}\right)$中能与$b$连接的值数量）。当臂${\mathcal{T}}_{i}$包含多个关系时，虽无法精确获取${d}_{i}\left( b\right)$，但可通过第2.2节的原语对其进行常数倍估计。下文将不区分${d}_{i}\left( b\right)$与其近似值，这不会影响渐近分析。

Similar as star queries,for each $b \in  \operatorname{dom}\left( B\right)$ ,we compute a permutation ${\phi }_{b}$ such that ${d}_{{\phi }_{b}\left( i\right) }\left( b\right)  \leq  {d}_{{\phi }_{b}\left( j\right) }\left( b\right)$ for any $1 \leq  i \leq$ $j \leq  n$ . Each permutation $\phi$ defines a subset of $\operatorname{dom}\left( B\right)$ as ${B}_{\phi } =$ $\left\{  {b \in  \operatorname{dom}\left( B\right)  : {\phi }_{b} = \phi }\right\}$ . Here,we further divide each ${B}_{\phi }$ into two subsets:

类似于星型查询，对每个$b \in  \operatorname{dom}\left( B\right)$计算排列${\phi }_{b}$，使得对任意$1 \leq  i \leq$$j \leq  n$满足${d}_{{\phi }_{b}\left( i\right) }\left( b\right)  \leq  {d}_{{\phi }_{b}\left( j\right) }\left( b\right)$。每个排列$\phi$将$\operatorname{dom}\left( B\right)$的子集定义为${B}_{\phi } =$$\left\{  {b \in  \operatorname{dom}\left( B\right)  : {\phi }_{b} = \phi }\right\}$。此处我们进一步将每个${B}_{\phi }$划分为两个子集：

$$
{B}_{\phi }^{\text{small }} = \left\{  {b \in  {B}_{\phi } : \mathop{\prod }\limits_{{i = 1}}^{{n - 1}}{d}_{\phi \left( i\right) }\left( b\right)  \leq  {d}_{\phi \left( n\right) }\left( b\right) }\right\}

LEMMA 7. For a star-like query ${Q}_{\mathbf{y}}\left( \mathcal{R}\right)$ ,let $N = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathbf{y} = \varnothing }}\left| {R}_{e}\right|$ , ${N}^{\prime } = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathrm{y} \neq  \varnothing }}\left| {R}_{e}\right|$ ,and OUT be the output size. 引理7. 对于星型查询${Q}_{\mathbf{y}}\left( \mathcal{R}\right)$，设$N = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathbf{y} = \varnothing }}\left| {R}_{e}\right|$、${N}^{\prime } = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathrm{y} \neq  \varnothing }}\left| {R}_{e}\right|$及OUT为输出规模。存在算法在$O\left( 1\right)$轮次内以$\widetilde{O}\left( L\right)$的负载高概率计算该查询，其中$L = \frac{{\left( N{N}^{\prime }\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{N}^{\prime 2/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}} + \frac{N \cdot  {\mathrm{{OUT}}}^{2/3}}{p} + \frac{N + {N}^{\prime } + \mathrm{{OUT}}}{p}.$

We prove the lemma by induction on $n$ . Note that the base case $n = 2$ is just Lemma 3 . For a star-like query with $n > 2$ ,we consider the load of our algorithm in each of the four steps separately.

通过对$n$进行归纳来证明该引理。注意基例$n = 2$即为引理3。对于具有$n > 2$的星型查询，我们分别分析算法四个步骤的负载。

Step 1 has linear load, since it only involves primitives. In Step 4, the input size of reduce-by-key can be bounded by $\widetilde{O}\left( \mathrm{{OUT}}\right)$ since there are $O\left( {\log N}\right)$ subqueries in total and each subquery produces at most OUT results. So this step has a load of $\widetilde{O}\left( \frac{\mathrm{{OUT}}}{p}\right)$ . Before analysing the cost of Step 2 and Step 3, we mention some important observations as below.

LEMMA 8. For every $b \in  \operatorname{dom}\left( B\right) ,\mathop{\prod }\limits_{{j = 1}}^{n}{d}_{j}\left( b\right)  \leq$ OUT .

引理8. 对于每个$b \in  \operatorname{dom}\left( B\right) ,\mathop{\prod }\limits_{{j = 1}}^{n}{d}_{j}\left( b\right)  \leq$ OUT。

LEMMA 9. For any permutation $\phi$ of $\left\lbrack  n\right\rbrack$ ,and every $b \in  \operatorname{dom}\left( B\right)$ ,

(1) if $b \in  {B}_{\phi }^{\text{small }}$ ,then $\mathop{\prod }\limits_{{i = 1}}^{{n - 1}}{d}_{\phi \left( i\right) }\left( b\right)  \leq  \sqrt{\mathrm{{OUT}}}$ ;

## 7 TREE QUERIES

## 7 树形查询

Finally, we are ready to tackle general tree queries with arbitrary output attributes, by building upon our algorithm for star-like queries.

基于星型查询算法，我们最终得以处理具有任意输出属性的通用树形查询。

As a preprocessing step, we remove all dangling tuples. Then we reduce the tree by iteratively removing a relation ${R}_{e}$ if (1) $e$ contains a single attribute; or (2) there is a non-output attribute $v$ that appears only in $e$ . Let ${e}^{\prime }$ be any relation such that $e \cap  {e}^{\prime } \neq  \varnothing$ . We can remove ${R}_{e}$ by attaching annotations of ${R}_{e}$ to ${R}_{{e}^{\prime }}$ ,i.e.,for each tuple ${t}^{\prime } \in  {R}_{{e}^{\prime }}$ ,apply the update $w\left( {t}^{\prime }\right)  \leftarrow  w\left( {t}^{\prime }\right)  \cdot  \mathop{\sum }\limits_{{t \in  {R}_{e} : {\pi }_{e \cap  {e}^{\prime }}t = {\pi }_{e \cap  {e}^{\prime }}{t}^{\prime }}}w\left( t\right)$ , which can be done by the reduce-by-key and multi-search primitives. All these operations incur linear load. It should be clear that after all such ${R}_{e}$ ’s have been removed,every leaf attribute is an output attribute. Please see Figure 2 for an example.

预处理阶段首先消除所有悬空元组。随后通过迭代方式缩减树结构：若关系${R}_{e}$满足(1)$e$仅含单个属性，或(2)存在仅出现在$e$中的非输出属性$v$，则移除该关系。设${e}^{\prime }$为满足$e \cap  {e}^{\prime } \neq  \varnothing$的任意关系，可通过将${R}_{e}$的注解附加到${R}_{{e}^{\prime }}$来实现移除——即对每个元组${t}^{\prime } \in  {R}_{{e}^{\prime }}$执行$w\left( {t}^{\prime }\right)  \leftarrow  w\left( {t}^{\prime }\right)  \cdot  \mathop{\sum }\limits_{{t \in  {R}_{e} : {\pi }_{e \cap  {e}^{\prime }}t = {\pi }_{e \cap  {e}^{\prime }}{t}^{\prime }}}w\left( t\right)$更新，这可通过键值归约和多搜索原语实现。所有操作均产生线性负载。值得注意的是，当所有此类${R}_{e}$被移除后，每个叶节点属性都将成为输出属性（示例见图2）。

Next, we break the query at every non-leaf output attribute. This decomposes the tree into a number of twigs. Observe that in each twig, all the output attributes are exactly the leaves (see Figure 2).

接着在每个非叶输出属性处分解查询，将树结构划分为若干分支。可见每个分支中的输出属性恰好都是叶节点（如图2所示）。

Note that it is sufficient to show how to compute a twig. After computing all the twigs, the remaining attributes are all output attributes, so we can just use the standard Yannakakis algorithm to compute the full join of all the twigs,which has load $O\left( \frac{\mathrm{{OUT}}}{p}\right)$ .

需要说明的是，只需展示如何计算单个分支即可。完成所有分支计算后，剩余属性均为输出属性，此时直接应用标准Yannakakis算法计算全连接，其负载为$O\left( \frac{\mathrm{{OUT}}}{p}\right)$。

### 7.1 The algorithm

### 7.1 算法实现

Note that twig queries are generalizations of star-like queries, which in turn are generalizations of line and star queries. Figure 2 shows some example of twig queries, among which twig 4 is in a form more general than star-like queries. Our idea is for tackling such twig queries is to remove the non-output attributes recursively until it becomes a star-like query.

需注意分支查询是星型查询的泛化形式，而星型查询又是线型与星型查询的泛化。图2展示了几种分支查询实例，其中分支4是比星型查询更通用的形式。我们的解决思路是通过递归移除非输出属性，直至查询退化为星型查询。

For a twig but non-star-like query $\mathcal{T} = \left( {\mathcal{V},\mathcal{E}}\right)$ ,we introduce the notion of skeleton. Let ${\mathcal{V}}^{ * } \varsubsetneq  \mathcal{V}$ be the set of attributes appearing in more than 2 relations. Note that ${\mathcal{V}}^{ * } \subseteq  \overline{\mathbf{y}}$ . Moreover, $\left| {\mathcal{V}}^{ * }\right|  \geq  2$ ; otherwise, $\mathcal{T}$ is a star-like query. Consider the subtree derived by ${\mathcal{V}}^{ * }$ ,denoted as ${\mathcal{T}}_{{\mathcal{V}}^{ * }}$ ,such that $v \in  \mathcal{V}$ or $e \in  \mathcal{E}$ is included by ${\mathcal{T}}_{{\mathcal{V}}^{ * }}$ if it lies on the path between any pair of $B,{B}^{\prime } \in  {\mathcal{V}}^{ * }$ . For each leaf $B \in  {\mathcal{V}}^{ * }$ ,let ${e}_{B}$ be the edge incident to $B$ in ${\mathcal{T}}_{{\mathcal{V}}^{ * }}$ . Removing ${e}_{B}$ will separate $\mathcal{T}$ into two connected subtrees. The one containing $B$ is exactly a star-like query since only $B$ may appear in more than 2 relations,denoted as ${\mathcal{T}}_{B} = \left( {{\mathcal{V}}_{B},{\mathcal{E}}_{B}}\right)$ . We just replace ${\mathcal{T}}_{B}$ by $B$ . Note that this procedure can be applied to all leaves in ${\mathcal{T}}_{V}^{ * }$ independently since the subtrees to be removed have no intersection. ### 7.2 The analysis

### 7.2 分析

For the load analysis, we will actually prove a slightly tighter bound of our algorithm, as stated in the following lemma.

LEMMA 14. For a twig query ${\mathcal{Q}}_{\mathbf{y}}\left( \mathcal{R}\right)$ ,let $N = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathbf{y} = \varnothing }}\left| {R}_{e}\right|$ , ${N}^{\prime } = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathrm{y} \neq  \varnothing }}\left| {R}_{e}\right|$ ,and OUT be the output size. Our algorithm can compute it in $O\left( 1\right)$ rounds with load $\widetilde{O}\left( L\right)$ w.h.p.,where $L =$ $\frac{{\left( N{N}^{\prime }\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{N}^{\prime 2/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}} + \frac{N \cdot  {\mathrm{{OUT}}}^{2/3}}{p} + \frac{N + {N}^{\prime } + \mathrm{{OUT}}}{p}.$

引理14. 对于枝状查询${\mathcal{Q}}_{\mathbf{y}}\left( \mathcal{R}\right)$，设$N = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathbf{y} = \varnothing }}\left| {R}_{e}\right|$、${N}^{\prime } = \mathop{\max }\limits_{{e \in  \mathcal{E} : e \cap  \mathrm{y} \neq  \varnothing }}\left| {R}_{e}\right|$及OUT为输出规模。我们的算法能以$O\left( 1\right)$轮次和高概率$\widetilde{O}\left( L\right)$的负载完成计算，其中$L =$$\frac{{\left( N{N}^{\prime }\right) }^{1/3} \cdot  {\mathrm{{OUT}}}^{1/2}}{{p}^{2/3}} + \frac{{N}^{\prime 2/3} \cdot  {\mathrm{{OUT}}}^{1/3}}{{p}^{2/3}} + \frac{N \cdot  {\mathrm{{OUT}}}^{2/3}}{p} + \frac{N + {N}^{\prime } + \mathrm{{OUT}}}{p}.$

通过对$n$的归纳法证明该引理。当$\mathcal{T}$为关系型或星型查询时的基础情形由引理7给出。对于一般枝状查询，我们逐步分析上述各步骤的算法负载。

引理15. 对于任意子查询，在移除悬空元组后，若$B \in  \mathcal{S}$为轻量值，则对每个值$b \in  \operatorname{dom}\left( B\right)$有$x\left( b\right)  \leq  \sqrt{\mathrm{{OUT}}}$。

Proof. For each $b \in  \operatorname{dom}\left( B\right) ,x\left( b\right)  \cdot  y\left( b\right)  \leq$ OUT since ${\pi }_{\mathbf{y}}{ \bowtie  }_{e \in  \mathcal{E}}$ ${\sigma }_{B = b}{R}_{e}$ is a subset of final result. By the definition of light values, i.e., $x\left( b\right)  \leq  y\left( b\right)$ ,we have $x\left( b\right)  \leq  \sqrt{\mathrm{{OUT}}}$ .

证明. 因${\pi }_{\mathbf{y}}{ \bowtie  }_{e \in  \mathcal{E}}$${\sigma }_{B = b}{R}_{e}$是最终结果的子集，故每个$b \in  \operatorname{dom}\left( B\right) ,x\left( b\right)  \cdot  y\left( b\right)  \leq$ OUT。根据轻量值的定义（即$x\left( b\right)  \leq  y\left( b\right)$），可得$x\left( b\right)  \leq  \sqrt{\mathrm{{OUT}}}$。

Consider an arbitrary subquery in Step 2. With Lemma 15, we can bound the size of $R\left( {B,{\mathcal{V}}_{B} \cap  \mathbf{y}}\right)$ by $N \cdot  \sqrt{\mathrm{{OUT}}}$ for each light attribute $B \in  \mathcal{S} \cap  \overline{\mathbf{y}}$ ,since there are at most $N$ values in $\operatorname{dom}\left( B\right)$ and each one can be joined with at most $\sqrt{\mathrm{{OUT}}}$ distinct combinations over ${\mathcal{V}}_{B} \cap  \mathbf{y}$ . So the Yannakakis algorithm has a load of $O\left( {\frac{N + {N}^{\prime }}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  =$ $O\left( L\right)$ . On the residual query,by plugging $N,\max \left\{  {{N}^{\prime },N \cdot  \sqrt{\mathrm{{OUT}}}}\right\}$ to hypothesis induction, it can be easily checked that its load is still bounded by $O\left( L\right)$ .

考虑步骤2中的任意子查询。根据引理15，对于每个轻量属性$B \in  \mathcal{S} \cap  \overline{\mathbf{y}}$，我们可以将$R\left( {B,{\mathcal{V}}_{B} \cap  \mathbf{y}}\right)$的大小限制在$N \cdot  \sqrt{\mathrm{{OUT}}}$以内，因为$\operatorname{dom}\left( B\right)$中最多有$N$个值，且每个值最多能与${\mathcal{V}}_{B} \cap  \mathbf{y}$上的$\sqrt{\mathrm{{OUT}}}$种不同组合进行连接。因此Yannakakis算法的负载为$O\left( {\frac{N + {N}^{\prime }}{p} + \frac{N \cdot  \sqrt{\mathrm{{OUT}}}}{p}}\right)  =$$O\left( L\right)$。在剩余查询中，通过将$N,\max \left\{  {{N}^{\prime },N \cdot  \sqrt{\mathrm{{OUT}}}}\right\}$代入归纳假设，可以轻松验证其负载仍受$O\left( L\right)$限制。

This completes the induction proof for Lemma 14. By setting ${N}^{\prime } = N$ ,we obtain the following result.

至此完成了引理14的归纳证明。设${N}^{\prime } = N$后，我们得到以下结果。

THEOREM 6. For an arbitrary tree join-aggregate query with input size $N$ and output size OUT,there is an algorithm computing it in $O\left( 1\right)$ rounds with load $\widetilde{O}\left( {\frac{N \cdot  {\mathrm{{OUT}}}^{2/3}}{p} + \frac{N + \mathrm{{OUT}}}{p}}\right)$ w.h.p.

定理6. 对于输入规模为$N$、输出规模为OUT的任意树形连接-聚合查询，存在一个算法能以$O\left( 1\right)$轮次和高概率$\widetilde{O}\left( {\frac{N \cdot  {\mathrm{{OUT}}}^{2/3}}{p} + \frac{N + \mathrm{{OUT}}}{p}}\right)$的负载完成计算。

## 8 OPEN PROBLEMS

## 8 开放性问题

While our matrix multiplication algorithm is optimal, we do not have any lower bounds for more general queries. The major difficulty in proving lower bounds for queries that involve more than two relations is that it is not clear which "elementary products" must be computed. For these queries, one can use the distributive law of the semiring to save computation and communication costs, as our algorithms have done. In fact, it is due to the same reason that there is no lower bound for such queries even in the (sequential) RAM model. Note that the distributive law does not help with matrix multiplication, and one can argue that all the elementary products must be computed.

虽然我们的矩阵乘法算法是最优的，但对于更一般的查询尚无任何下界证明。涉及两个以上关系的查询下界证明主要困难在于：无法明确哪些"基本乘积"必须被计算。对此类查询，可如我们的算法所示，利用半环的分配律来节省计算和通信成本。事实上，正是由于相同原因，即使在（顺序）RAM模型中也无此类查询的下界。需注意分配律对矩阵乘法并无助益，可以论证所有基本乘积都必须计算。

Other open problems include join-aggregate and join-project queries over relations of arity more than two, or when the query is cyclic.

其他开放性问题包括：针对元数大于二的关系进行连接-聚合和连接-投影查询，或处理循环查询的情况。
