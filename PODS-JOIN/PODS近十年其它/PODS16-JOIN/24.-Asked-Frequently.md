## Abstract

## 摘要

We define and study the Functional Aggregate Query (FAQ) problem, which encompasses many frequently asked questions in constraint satisfaction, databases, matrix operations, probabilistic graphical models and logic. This is our main conceptual contribution.

我们定义并研究了功能聚合查询(FAQ)问题，该问题涵盖约束满足、数据库、矩阵运算、概率图模型和逻辑学中许多常见问题。这是我们的主要概念贡献。

We then present a simple algorithm called InsideOut to solve this general problem. InsideOut is a variation of the traditional dynamic programming approach for constraint programming based on variable elimination. Our variation adds a couple of simple twists to basic variable elimination in order to deal with the generality of FAQ, to take full advantage of Grohe and Marx's fractional edge cover framework, and of the analysis of recent worst-case optimal relational join algorithms.

随后我们提出名为InsideOut的简单算法来解决这一通用问题。该算法是基于变量消除的传统动态规划方法在约束编程领域的变体。我们通过添加几个简单调整来处理FAQ的通用性，充分利用Grohe和Marx的分数边覆盖框架，并借鉴近期最坏情况最优关系连接算法的分析。

As is the case with constraint programming and graphical model inference, to make InsideOut run efficiently we need to solve an optimization problem to compute an appropriate variable ordering. The main technical contribution of this work is a precise characterization of when a variable ordering is 'semantically equivalent' to the variable ordering given by the input FAQ expression. Then, we design an approximation algorithm to find an equivalent variable ordering that has the best 'fractional FAQ-width'. Our results imply a host of known and a few new results in graphical model inference, matrix operations, relational joins, and logic.

与约束编程和图模型推理类似，要使InsideOut高效运行，需要先通过优化问题计算合适的变量顺序。本工作的主要技术贡献是精确描述了变量顺序何时与输入FAQ表达式给出的顺序"语义等价"。进而我们设计近似算法来寻找具有最佳"分数FAQ宽度"的等价变量顺序。这些结果衍生出图模型推理、矩阵运算、关系连接和逻辑学领域诸多已知及若干新结论。

We also briefly explain how recent algorithms on beyond worst-case analysis for joins and those for solving SAT and #SAT can be viewed as variable elimination to solve FAQ over compactly represented input functions.

我们还简要说明，近期关于连接问题超最坏情况分析算法以及求解SAT和#SAT的算法，如何可视为通过变量消除来解决紧凑表示输入函数的FAQ问题。

### 1.2 The FAQ problem

### 1.2 FAQ问题

Throughout the paper, we use the following convention. Uppercase ${X}_{i}$ denotes a variable,and lowercase ${x}_{i}$ denotes a value in the domain $\operatorname{Dom}\left( {X}_{i}\right)$ of the variable. Furthermore, for any subset $S \subseteq  \left\lbrack  n\right\rbrack$ ,define

本文采用以下约定：大写字母${X}_{i}$表示变量，小写字母${x}_{i}$表示该变量定义域$\operatorname{Dom}\left( {X}_{i}\right)$中的某个值。对于任意子集$S \subseteq  \left\lbrack  n\right\rbrack$，定义

$$
{\mathbf{X}}_{S} = {\left( {X}_{i}\right) }_{i \in  S},\;{\mathbf{x}}_{S} = {\left( {x}_{i}\right) }_{i \in  S} \in  \mathop{\prod }\limits_{{i \in  S}}\operatorname{Dom}\left( {X}_{i}\right) .
$$

In particular, ${\mathbf{X}}_{S}$ is a tuple of variables and ${\mathbf{x}}_{S}$ is a tuple of specific values with support $S$ . The input to FAQ is a set of functions and the output is a function computed using a series of aggregates over the variables and input functions. More specifically,for each $i \in  \left\lbrack  n\right\rbrack$ ,let ${X}_{i}$ be a variable on some discrete domain $\operatorname{Dom}\left( {X}_{i}\right)$ ,where $\left| {\operatorname{Dom}\left( {X}_{i}\right) }\right|  \geq  2$ . The FAQ problem is to compute the following function

特别地，${\mathbf{X}}_{S}$是变量元组，${\mathbf{x}}_{S}$是具有支撑集$S$的特定值元组。FAQ问题的输入是一组函数，输出是通过对变量和输入函数进行系列聚合计算得到的函数。具体而言，对于每个$i \in  \left\lbrack  n\right\rbrack$，令${X}_{i}$为定义在离散域$\operatorname{Dom}\left( {X}_{i}\right)$上的变量（其中$\left| {\operatorname{Dom}\left( {X}_{i}\right) }\right|  \geq  2$），FAQ问题即计算以下函数

$$
\varphi \left( {\mathbf{x}}_{\left\lbrack  f\right\rbrack  }\right)  = {\bigoplus }_{{x}_{f + 1} \in  \operatorname{Dom}\left( {X}_{f + 1}\right) }^{\left( f + 1\right) }\cdots {\bigoplus }_{{x}_{n} \in  \operatorname{Dom}\left( {X}_{n}\right) }^{\left( n\right) }{\bigotimes }_{S \in  \mathcal{E}}{\psi }_{S}\left( {\mathbf{x}}_{S}\right) , \tag{1}
$$

where

其中

- $\mathcal{H} = \left( {\mathcal{V},\mathcal{E}}\right)$ is a multi-hypergraph. $\mathcal{V} = \left\lbrack  n\right\rbrack$ is the index set of the variables ${X}_{i},i \in  \left\lbrack  n\right\rbrack$ . Overloading notation, $\mathcal{V}$ is also referred to as the set of variables.

- $\mathcal{H} = \left( {\mathcal{V},\mathcal{E}}\right)$是多超图。$\mathcal{V} = \left\lbrack  n\right\rbrack$是变量${X}_{i},i \in  \left\lbrack  n\right\rbrack$的索引集。通过符号重载，$\mathcal{V}$也可直接称为变量集合

- The set $F = \left\lbrack  f\right\rbrack$ is the set of free variables for some integer $0 \leq  f \leq  n$ . Variables in $\mathcal{V} - F$ are called bound variables.

- 集合$F = \left\lbrack  f\right\rbrack$是自由变量集（其中$0 \leq  f \leq  n$为整数），$\mathcal{V} - F$中的变量称为约束变量

- $\mathbf{D}$ is a fixed domain,such as $\{ 0,1\}$ or ${\mathbb{R}}^{ + }$ .

- $\mathbf{D}$是固定域，例如$\{ 0,1\}$或${\mathbb{R}}^{ + }$

- For every hyperedge $S \in  \mathcal{E},{\psi }_{S} : \mathop{\prod }\limits_{{i \in  S}}\operatorname{Dom}\left( {X}_{i}\right)  \rightarrow  \mathbf{D}$ is an input function (also called a factor).

- 对于每条超边$S \in  \mathcal{E},{\psi }_{S} : \mathop{\prod }\limits_{{i \in  S}}\operatorname{Dom}\left( {X}_{i}\right)  \rightarrow  \mathbf{D}$，都存在一个输入函数（也称为因子）

- For every bound variable $i > f,{ \oplus  }^{\left( i\right) }$ is a binary (aggregate) operator on the domain $\mathbf{D}$ .

- 对于每个约束变量$i > f,{ \oplus  }^{\left( i\right) }$，在域$\mathbf{D}$上定义了一个二元（聚合）运算符

## 2. SUMMARY OF CONTRIBUTIONS

## 2. 主要贡献

### 2.1 Conceptual contribution

### 2.1 理论贡献

The formulation of FAQ has its roots in the SumProd problem formulated by Dechter [20] who solved it using variable elimination. The SumProd problem is exactly FAQ-SS. A later work by Aji and McEliece [5] also addressed SumProd, which they renamed marginalization over semirings.

FAQ的构建源于Dechter[20]提出的SumProd问题（即FAQ-SS），其通过变量消解法求解。Aji与McEliece[5]后续研究也涉及该问题，并将其重命名为"半环边际化"。

FAQ substantially generalizes FAQ-SS, as FAQ can now capture problems in logic such as QCQ (quantified conjunctive query) or #QCQ (sharp quantified conjunctive query). We argue that FAQ is a very powerful way of thinking about these problems and related issues. FAQ can be thought of as a declarative query language over functions. For example, we show in [3] how different input representations can vastly affect the landscape of tractability of the problem, and how the output representation is related to the notion of factorized databases [43].

FAQ极大拓展了FAQ-SS的范畴，现可刻画逻辑领域问题如量化合取查询(QCQ)或#QCQ（计数型量化合取查询）。我们认为FAQ是思考此类问题的强有力范式，可视为面向函数的声明式查询语言。例如文献[3]展示了不同输入表示如何显著影响问题可处理性，以及输出表示与因子化数据库概念的关联[43]。

### 2.2 Algorithmic contribution

### 2.2 算法贡献

We present a single algorithm, called InsideOut, to solve FAQ. InsideOut is a variation of the variable elimination algorithm $\left\lbrack  {{20},{54},{53}}\right\rbrack$ . In PGM,variable elimination was first proposed by Zhang and Poole [53]. Then Dechter [20] observed that this strategy can be applied to problems on other semirings such as constraint satisfaction and SAT solving. In the database literature, Yannakakis' algorithm [52] can also be cast as variable elimination under the set semiring or Boolean semiring. ${}^{2}$

InsideOut adds three minor twists to the basic variable elimination strategy. First, we use a backtracking-search strategy called OutsideIn to compute the intermediate results. This strategy allows us to use the analysis of recent worst-case optimal join algorithms $\left\lbrack  {{51},{40},{41}}\right\rbrack$ to bound the time it takes to compute the intermediate results using the fractional edge cover bound $\left\lbrack  {7,{28}}\right\rbrack$ . Second,we introduce the idea of a 01-projection of a function onto a support to obtain the fractional hypertree width style of runtime guarantee [29]. Third, in addition to making use of the distributive law to 'fold' common factors [5] when we face a semiring aggregate, we apply a swap between an aggregate and the inside product when that aggregate is also a product.

InsideOut算法为基础变量消除策略添加了三处精妙改进。首先，我们采用名为OutsideIn的回溯搜索策略计算中间结果，该策略允许运用最新最坏情况最优连接算法$\left\lbrack  {{51},{40},{41}}\right\rbrack$的分析，通过分数边覆盖界$\left\lbrack  {7,{28}}\right\rbrack$来约束中间结果计算时间。其次，我们提出函数在支撑集上的01投影概念，以获得类似分数超树宽度的运行时保证[29]。第三，面对半环聚合运算时，除利用分配律对公共因子进行"折叠"[5]外，当聚合运算本身也是乘积时，我们还会实施聚合与内积的交换操作。

We show that InsideOut runs in time $\widetilde{O}\left( {{N}^{\text{faqw }\left( \sigma \right) } + Z}\right)$ , where $\sigma$ is a variable ordering that we choose to run the algorithm on, $N$ is the input size,and $Z$ is the output size (under the 'listing representation' of input and output factors), and faqw $\left( \sigma \right)$ is a parameter called the (fractional) FAQ-width of $\sigma$ . FAQ-width is the FAQ-analog of the induced fractional edge cover width of a variable ordering. (See Definition 2.)

我们证明InsideOut算法在$\widetilde{O}\left( {{N}^{\text{faqw }\left( \sigma \right) } + Z}\right)$时间内运行，其中$\sigma$是算法执行选择的变量排序，$N$为输入规模，$Z$为输出规模(基于输入输出因子的列表表示法)，faqw$\left( \sigma \right)$是称为$\sigma$的(分数)FAQ宽度参数。FAQ宽度是变量排序诱导分数边覆盖宽度的FAQ类比量(参见定义2)。

In fact, we show (in [3]) that the variable elimination framework is still powerful in cases when the fractional hy-pertree width bounds are no longer applicable. These are special cases of FAQ where the input functions are compactly represented. In particular, we explain how - with a suitable modification - InsideOut can be used to recover recently known beyond worst-case results in join algorithms (Minesweeper [39], and Tetris [2]), and results on the tractability of SAT and #SAT for $\beta$ -acyclic formulas [44,11].

事实上，我们在文献[3]中证明：当分数超树宽度界限不再适用时，变量消除框架仍具强大效力。这些是FAQ中输入函数被紧凑表示的特殊案例。特别地，我们阐述了如何通过适当修改使InsideOut算法能够重现连接算法中超越最坏情况的结果(Minesweeper[39]和Tetris[2])，以及$\beta$非循环公式的SAT与#SAT可解性研究成果[44,11]。

On the practical side, preliminary implementations of join algorithms based on fractional hypertree width for counting graph patterns have been very encouraging, as they are faster than existing commercial systems by at least an order of magnitude $\left\lbrack  {1,{42}}\right\rbrack$ for selected queries. Far beyond graph patterns, we have implemented InsideOut within the Log-icBlox database system [6] with great performance results.

实践方面，基于分数超树宽度的图模式计数连接算法初步实现已取得显著成效，在选定查询上比现有商业系统快至少一个数量级$\left\lbrack  {1,{42}}\right\rbrack$。远超图模式范畴的是，我们已在LogicBlox数据库系统[6]中实现InsideOut并取得卓越性能。

### 2.3 Main technical contributions

### 2.3 主要技术贡献

The key technical problem is choosing a $\sigma$ that minimizes faqw $\left( \sigma \right)$ . This is where the generality of FAQ requires new ideas. Traditional variable elimination for CSPs or PGM inference also requires computing a good variable ordering to minimize the treewidth [35] or fractional hypertree width [29] of the variable ordering. However, in those cases all variable orderings are valid. Hence, all we have to do in this traditional setting is to compute a tree decomposition whose maximum bag size (or maximum fractional edge cover number over the bags) is minimized, then the GYO-elimination procedure will produce a good variable ordering (see [3]). In the general setting of FAQ, just like in logic where there are alternating quantifiers, the set of semantically equivalent variable orderings depends on both the input query expression and the structure of the query hypergraph.

关键技术问题在于选择一个$\sigma$以最小化faqw$\left( \sigma \right)$。这正是FAQ的通用性需要新思路之处。传统CSP变量消元或PGM推理同样需要计算优质变量序以最小化树宽[35]或分数超树宽[29]。但在那些场景中所有变量序均有效。因此传统做法只需计算最大包尺寸（或包间最大分数边覆盖数）最小的树分解，GYO消元程序自会生成优质变量序（参见[3]）。而在FAQ通用框架下，如同逻辑学中存在交替量词的情形，语义等价变量序集合既取决于输入查询表达式，也受查询超图结构影响。

- Given an FAQ-query $\varphi$ we define the set $\operatorname{EVO}\left( \varphi \right)$ of all variable orderings semantically equivalent to $\varphi$ . Roughly, for any $\sigma  \in  \operatorname{EVO}\left( \varphi \right)$ ,if we rewrite the expression for $\varphi$ using the ordering $\sigma$ (with all aggregates permuted along),then we obtain a function identical to $\varphi$ ,no matter what the input factors are. The FAQ-width of $\varphi$ is $\operatorname{faqw}\left( \varphi \right)  = \mathop{\min }\limits_{{\sigma  \in  \operatorname{EVO}\left( \varphi \right) }}\operatorname{faqw}\left( \sigma \right)$ .

- 给定FAQ查询$\varphi$，我们定义语义等价于$\varphi$的所有变量序集合$\operatorname{EVO}\left( \varphi \right)$。简言之，对任意$\sigma  \in  \operatorname{EVO}\left( \varphi \right)$，若按序$\sigma$重写表达式（同步置换所有聚合算子），则无论输入因子如何都将得到与$\varphi$完全相同的函数。$\varphi$的FAQ宽度为$\operatorname{faqw}\left( \varphi \right)  = \mathop{\min }\limits_{{\sigma  \in  \operatorname{EVO}\left( \varphi \right) }}\operatorname{faqw}\left( \sigma \right)$。

- We describe how to (in poly-time, query complexity) construct an expression tree for the input FAQ-query. The expression tree induces a partially ordered set on the variables called the precedence poset. By defining a notion called component-wise equivalence, we completely characterize $\operatorname{EVO}\left( \varphi \right)  : \sigma  \in  \operatorname{EVO}\left( \varphi \right)$ if and only if it is component-wise equivalent to some linear extension of the precedence poset.

- 我们阐述如何（多项式时间、查询复杂度）为输入FAQ查询构建表达式树。该树会诱导出称为前序偏序集的变量部分序。通过定义分量等价概念，当且仅当某排序是前序偏序集的线性扩展且分量等价时，我们完全刻画了$\operatorname{EVO}\left( \varphi \right)  : \sigma  \in  \operatorname{EVO}\left( \varphi \right)$。

- To prepare for the approximation algorithm for faqw $\left( \varphi \right)$ , we show that going through all orderings in $\operatorname{EVO}\left( \varphi \right)$ is not necessary. The set of linear extensions of the precedence poset is sufficient for this purpose: every linear extension of the precedence poset is semantically equivalent to $\varphi$ ,and every $\sigma  \in  \operatorname{EVO}\left( \varphi \right)$ has the same FAQ-width as some linear extension of this poset.

- 为设计faqw$\left( \varphi \right)$近似算法做准备，我们证明无需遍历$\operatorname{EVO}\left( \varphi \right)$中所有排序。前序偏序集的线性扩展集已足够：该偏序集的每个线性扩展均语义等价于$\varphi$，且每个$\sigma  \in  \operatorname{EVO}\left( \varphi \right)$的FAQ宽度都与该偏序集的某个线性扩展相同。

- Finally, using an approximation algorithm for the fractional hypertree width (fhtw) with approximation ratio $g\left( \text{ fhtw }\right)$ as a blackbox, ${}^{3}$ and using the expression tree as a guide, we give an approximation algorithm computing an ordering $\sigma$ such that $\operatorname{faqw}\left( \sigma \right)  \leq  \operatorname{faqw}\left( \varphi \right)  +$ $g\left( {\operatorname{faqw}\left( \varphi \right) }\right)$ .

### 3.1 Problems on one semiring

As was mentioned in the introduction, the FAQ-SS problem was explicitly defined by Aji and McEliece [5] who called it the MPF problem (for Marginalize the product function). They presented a message passing algorithm for FAQ-SS and essentially showed that their algorithm meets the treewidth bound. Their paper also lists a number of problems that are FAQ-SS instances, including Matrix Chain Multiplication (less specific than our result, they just argue that essentially different variable orderings give rise to different ways of parenthesizing the matrix chain multiplication) and Matrix Vector Multiplication. They showed that their general algorithm contains FFT as a special case. We re-phrase their interpretation of the FFT using InsideOut. They also showed that many basic decoding problems in coding theory can be cast as FAQ-SS instances.

如引言所述，Aji和McEliece[5]明确定义了FAQ-SS问题（称为MPF问题，即乘积函数边缘化），提出了消息传递算法并证明其满足树宽度界。该论文列举了多个FAQ-SS实例，包括矩阵链乘法（比我们的结果更泛化，仅指出不同变量排序导致不同的矩阵链括号化方式）和矩阵向量乘法，并表明其通用算法包含FFT作为特例。我们使用InsideOut重新诠释了他们对FFT的理解。他们还证明编码理论中许多基本解码问题可转化为FAQ-SS实例。

Kohlas and Wilson [34] presented even more applications of the FAQ-SS problem. The paper categorized various existing message passing algorithms depending on what extra properties they need beyond $\left( {\mathbf{D},\oplus , \otimes  }\right)$ being a commutative semiring. Their paper also explored algorithms for approximate computations (while in this work we solely deal with exact computation). Approximate computations in PGMs have been explored under the semiring framework [48].

Kohlas和Wilson[34]提出了更多FAQ-SS应用案例，根据所需交换半环$\left( {\mathbf{D},\oplus , \otimes  }\right)$之外的额外性质对现有消息传递算法进行分类，并探索了近似计算算法（而本研究仅处理精确计算）。PGM中的近似计算已在半环框架下有所探索[48]。

### 3.2 Factorized databases

### 3.2 因子化数据库

Bakibayev et al. [9] and Olteanu and Závodný [43] introduced the notion of factorized databases, and showed how one can efficiently compute join and aggregates over factorized databases. In hindsight there is much in common between their approach and InsideOut applied to the single semiring case of FAQ-SS. Both approaches have the same runtime complexity, because both are dynamic programming algorithms, InsideOut is bottom-up, and factorized database computation is top-down (memoized).

Bakibayev等[9]与Olteanu、Závodný[43]提出了因子化数据库概念，并展示了如何高效计算因子化数据库上的连接与聚合操作。回溯可见，其方法与应用于FAQ-SS单半环情形的InsideOut算法存在诸多共性。两种方法具有相同的时间复杂度，均采用动态规划策略——InsideOut为自底向上，而因子化数据库计算则为自顶向下（带备忘录）。

The FAQ framework is more general in that it can handle multiple aggregate types. Our contribution also involves the characterization of EVO and an approximation algorithm for faqw. On the other hand, aspects of factorized database that FAQ does not handle include the evaluation of SQL queries and output size bounds on the factorized representations.

FAQ框架更具通用性，可处理多种聚合类型。我们的贡献还包括对EVO特性的描述及faqw近似算法的提出。而因子化数据库涉及的SQL查询评估与因子化表示输出规模界限等问题，FAQ框架尚未涵盖。

### 3.3 Notions of widths

### 3.3 宽度概念

Various notions of hypergraph 'widths' have been developed over the years in PGM, CSP, and database theory. In particular, two often-used properties of the input query are acyclicity and bounded width.

PGM、CSP及数据库理论领域已发展出多种超图"宽度"概念。其中查询输入的两个常用特性是无环性与有界宽度。

When the query is acyclic, the classic algorithm of Yan-nakakis [52] for relational joins (and CSPs) runs in time linear in the input plus output size, modulo a log factor. Similarly, Pearl's belief propagation algorithm [45] works well for acyclic graphical models. As we briefly touch upon in [3], Yannakakis' algorithm is essentially belief propagation on the Boolean semiring or set semiring. The algorithm can also be reinterpreted using InsideOut.

当查询无环时，Yannakakis[52]提出的经典关系连接（及CSP）算法能以输入输出规模线性时间运行（对数因子除外）。类似地，Pearl的置信传播算法[45]在无环图模型中表现良好。如我们在[3]中简述，Yannakakis算法本质上是布尔半环或集合半环上的置信传播。该算法亦可借助InsideOut重新诠释。

Subsequent works on databases and CSPs further expand the classes of queries that can be evaluated in polynomial time. These works define progressively more general notions of width for a query, which intuitively measure how far a query is from being acyclic. Roughly, these results state that if the corresponding notion of 'width' is bounded by a constant, then the query is 'tractable,' i.e. there is a polynomial-time algorithm to evaluate it. For example, Gyssens et al. $\left\lbrack  {{30},{31}}\right\rbrack$ showed that queries with bounded degree of acyclicity are tractable. Then came query width (qw) from Chekuri and Rajaraman [12], hypertree width and generalized hypertree width (ghw) from Gottlob et al. [50, 26], and fractional hypertree width from Grohe and Marx [29]. More recently, Marx developed the most general width notions known to date, called adaptive width and submodular width $\left\lbrack  {{37},{38}}\right\rbrack$ .

后续数据库与CSP研究进一步扩展了可多项式时间求解的查询类别。这些工作定义了渐趋通用的查询宽度概念，直观衡量查询偏离无环性的程度。简言之，若相应"宽度"概念有常数界，则查询是"易处理的"，即存在多项式时间算法。例如Gyssens等$\left\lbrack  {{30},{31}}\right\rbrack$证明有界无环度查询可高效处理。随后出现Chekuri与Rajaraman[12]的查询宽度(qw)、Gottlob等[50,26]的超树宽度与广义超树宽度(ghw)，以及Grohe与Marx[29]的分数超树宽度。最近Marx提出了迄今最通用的宽度概念——自适应宽度与次模宽度$\left\lbrack  {{37},{38}}\right\rbrack$。

In the PGM literature, the most common notion is treewidth as the textbook variable elimination and message passing algorithms are often stated to run in time $O\left( {N}^{w + 1}\right)$ where $w$ is the tree width of the model [35]. Freuder [24] and Dechter and Pearl [22] showed in late 1980s that CSP instances with bounded treewidth are tractable.

PGM领域最常用的是树宽概念，经典教材所述变量消元与消息传递算法的运行时间通常记为$O\left( {N}^{w + 1}\right)$，其中$w$为模型树宽[35]。Freuder[24]与Dechter、Pearl[22]在1980年代末即证明树宽有界的CSP实例可高效求解。

In the logic/finite model theory literature, several notions of widths were also developed $\left\lbrack  {4,{23},{14}}\right\rbrack$ . We describe them in the relevant sections of the full version [3].

逻辑学/有限模型理论文献中也发展出若干宽度概念$\left\lbrack  {4,{23},{14}}\right\rbrack$，我们将在完整版[3]相关章节详述。

### 3.4 Finite model theory

### 3.4 有限模型理论

In [47], Pichler and Skritek studied the #CQ problem in the special case where the query is acyclic. We refer to this special case as $\# \mathrm{{ACQ}}$ . In particular,they showed that #ACQ is tractable in data complexity (i.e. when the number of variables that we are counting over is a constant) and in query complexity (i.e. when all relations have constant sizes) but not in combined complexity where the problem turns out to be $\# \mathbf{P}$ -complete.

Pichler与Skritek[47]研究了#CQ问题在查询无环时的特例，称此情形为$\# \mathrm{{ACQ}}$。他们证明#ACQ在数据复杂度（计数变量数为常数时）与查询复杂度（所有关系规模为常数时）下可高效处理，但在组合复杂度下该问题具有$\# \mathbf{P}$完全性。

In [23], Durand and Mengel introduced a new parameter for $\# \mathrm{{CQ}}$ called the quantified star size. It is basically a measure of how free variables are connected in the query's hypergraph. Along with bounded generalized hyper-tree width (or fractional hypertree width), bounded quantified star size characterizes the classes of $\# \mathrm{{CQ}}$ instances that are tractable in the bounded arity (or bounded generalized hypertree width) case.

在文献[23]中，Durand和Mengel引入了一个称为量化星尺寸的新参数，用于衡量查询超图中自由变量的连接程度。该参数与有界广义超树宽度（或分数超树宽度）共同界定了在有限元数（或有界广义超树宽度）情况下可高效求解的$\# \mathrm{{CQ}}$实例类别。

The quantified star size idea has been expanded later by applying it to the core of the query instead of the original query [27]. The core is a minimal subquery that is homomorphic to the original query. Because homomorphism does not preserve counts (i.e. it is not a one-to-one mapping), free variables have to be explicitly preserved by taking the core of the color query of the original query. Further development along with new lower bounds appeared in [16].

后续研究将量化星尺寸概念应用于查询核心而非原始查询[27]，实现了理论拓展。查询核心是指与原始查询存在同态关系的最小子查询。由于同态不保持计数关系（即非一一映射），必须通过获取原始查询着色查询的核心来显式保留自由变量。文献[16]进一步提出了新的下界理论。

QCQ (second row of Table 1) has its own long line of research. An early and interesting result was the tractability of QCQ when the domain size, treewidth, and number of quantifier alternations are all constants [13]. More recently, Chen and Dalmau introduced a notion of width for QCQ based on elimination orderings [14]. In particular, they take the minimum width over some variable orderings that are equivalent to the original query. They showed the tractability of QCQ when their width is bounded.

QCQ（表1第二行）已形成独立的研究体系。早期重要成果证明：当域大小、树宽和量词交替次数均为常数时，QCQ具有可高效求解性[13]。近期Chen与Dalmau基于消元序提出了QCQ的宽度概念[14]，通过计算与原始查询等价的变量序最小宽度，证明了宽度有界时QCQ的可高效求解性。

The runtime of InsideOut for $\mathrm{{CQ}},\# \mathrm{{CQ}}$ ,and $\mathrm{{QCQ}}$ are unboundedly better than the above results as shown in Table 1. Our result on $\# \mathrm{{QCQ}}$ is new: to the best of our knowledge no non-trivial efficient algorithms for $\# \mathrm{{QCQ}}$ were known prior to our work. Essentially, InsideOut is able to unify the above results under the same umbrella.

如表1所示，InsideOut算法在$\mathrm{{CQ}},\# \mathrm{{CQ}}$和$\mathrm{{QCQ}}$上的运行时间显著优于上述结果。关于$\# \mathrm{{QCQ}}$的研究成果属首次提出：据我们所知，此前该领域尚未出现非平凡的高效算法。本质上，InsideOut实现了上述成果的理论框架统一。

$$

OutsideIn is backtracking search $\left\lbrack  {{19},{25}}\right\rbrack$ which was known 50 years ago in the AI and constraint programming world. In the PGM literature, the method of conditioning search is similar, but the main theoretical objective is so that the conditioning graph is acyclic [46]. The main advantage of backtracking search is that it requires very little extra space. The main disadvantage is that it might have to resolve the same subproblem multiple times. The duality between backtracking search and dynamic programming is well-known in the constraint programming literature [49]. Next section explores the other side of this duality: the dynamic programming side.

OutsideIn本质上是回溯搜索$\left\lbrack  {{19},{25}}\right\rbrack$，这种算法50年前就已在人工智能和约束规划领域为人所知。在概率图模型研究中，条件搜索方法虽类似，但其主要理论目标是使条件图成为无环结构[46]。回溯搜索的主要优势是所需额外存储空间极少，主要缺陷是可能需多次重复求解相同子问题。回溯搜索与动态规划的对偶性在约束规划文献[49]中已有充分论述。下一节将探讨这对偶性的另一面：动态规划方向

While correct, basic variable elimination as described above is potentially not very efficient for sparse input factors, i.e. factors whose sizes are smaller than the product of the domain sizes. The main reason is that the product that was factored out might annihilate many entries of the intermediate result ${\psi }_{{U}_{n}-\{ n\} }$ ,while we have spent so much time computing ${\psi }_{{U}_{n}-\{ n\} }$ . #### 4.3.2 The general case

#### 4.3.2 一般情况

The above strategy does not care if the variable aggregates where the same or different: As long as $\left( {\mathbf{D},{ \oplus  }^{\left( n\right) }, \otimes  }\right)$ is a semiring, we can fold the common factors. Thus, InsideOut works almost as is for a general FAQ instance (as opposed to FAQ-SS).

上述策略不区分变量聚合是否相同：只要$\left( {\mathbf{D},{ \oplus  }^{\left( n\right) }, \otimes  }\right)$是半环结构，我们就能合并公共因子。因此，InsideOut几乎可以直接应用于一般FAQ实例（而非FAQ-SS）。

We are left to describe how InsideOut deals with the case when ${ \oplus  }^{\left( n\right) } =  \otimes$ . In this case,the simple idea is to swap the two (identical) operators:

#### 4.3.4 Runtime analysis

#### 4.3.4 运行时分析

The runtime of InsideOut is the sum of the runtimes of $n$ variable elimination steps plus the time needed to report the output at the end. For $k = n,\ldots ,1$ ,the cost of the $k$ th step is analyzed as follows. If $k > f$ and the aggregate ${\bigoplus }^{\left( k\right) }$ is a semiring aggregate,or if $k \leq  f$ ,then the runtime is dominated by the OutsideIn algorithm's runtime to compute the intermediate factor ${\psi }_{{U}_{k}-\{ k\} }$ . We derive a complete characterization of EVO, based on a combinatorial concept of component-wise equivalence. However, to facilitate the approximation algorithm for the FAQ-width we show that one does not need the complete characterization.

Our approach is as follows. In the most general case, we will define a class of variable orderings for a given input FAQ-query $\varphi$ . This class will be precisely the set of linear extensions $\operatorname{LinEx}\left( P\right)$ of a partially ordered set (poset) on variables called the precedence poset $P$ . This is the ’soundness’ of the variable ordering class.

我们的方法如下：在最一般情况下，将为给定FAQ查询$\varphi$定义一类变量序。该类恰好是变量偏序集（称为优先序$P$）的线性扩展$\operatorname{LinEx}\left( P\right)$集合。优先序建立在输入查询$\varphi$的表达式树之上。该类中每个变量序都将被证明是$\varphi$等价的，此即变量序类的"健全性"。

Then, we prove that this class of variable orderings is all we need to consider to compute/approximate faqw $\left( \varphi \right)$ ,because every $\varphi$ -equivalent variable ordering $\sigma$ either belongs to $\operatorname{LinEx}\left( P\right)$ or is component-wise equivalent to $\pi$ (which implies that $\operatorname{faqw}\left( \sigma \right)  = \operatorname{faqw}\left( \pi \right)$ ) for some $\pi  \in  \operatorname{LinEx}\left( P\right)$ . (Even this simple statement needs a technical clarification, which is done in Proposition 5.1.)

接着，我们证明在计算/近似faqw$\left( \varphi \right)$时，只需考虑这类变量序关系，因为每个$\varphi$等价变量序$\sigma$要么属于$\operatorname{LinEx}\left( P\right)$，要么在分量等价意义上等同于$\pi$（这意味着$\operatorname{faqw}\left( \sigma \right)  = \operatorname{faqw}\left( \pi \right)$）对于某些$\pi  \in  \operatorname{LinEx}\left( P\right)$。这展示了$\operatorname{LinEx}\left( P\right)$的"完备性"。该完备性结论基于不同变量聚合不可交换的假设。（即便是这个简单陈述也需要技术性澄清，详见命题5.1。）

Because the final result is a bit technically involved, we shall present in the next section a special case that illustrates many of our main ideas. It should be noted, however, that in the end there is only one theorem and one approximation algorithm for all FAQ instances.

由于最终结果涉及较多技术细节，我们将在下节通过特例展示核心思想。但需注意，最终所有FAQ实例都共享同一个定理和近似算法。

### 5.1 Expression tree and and precedence poset

### 5.1 表达式树与优先偏序集

The expression tree is defined on a sequence of tagged variables along with a hypergraph. In such a sequence, every vertex $i$ (or equivalently variable ${X}_{i}$ ) is tagged with its corresponding operator ${ \oplus  }^{\left( i\right) }$ ; or,if the variable is a free variable then its tag is free. Given a sequence $\sigma$ of tagged variables,a tag block is a maximal subsequence of consecutive variables in $\sigma$ with the same tag. The first tag block of a sequence $\sigma$ of tagged variables is the longest prefix of $\sigma$ consisting of variables of the same tag.

表达式树定义在一系列带标记变量及超图结构上。在此类序列中，每个顶点$i$（或等价变量${X}_{i}$）都被标记其对应运算符${ \oplus  }^{\left( i\right) }$；若变量为自由变量，则标记为free。给定带标记变量序列$\sigma$，标记块是指$\sigma$中具有相同标记的连续变量构成的最大子序列。带标记变量序列$\sigma$的首个标记块，是由相同标记变量组成的最长前缀。

Definition 4. (Expression tree) The expression tree for $\varphi$ is a rooted tree $P$ . Every node of the tree is a set of variables. We construct the expression tree using two steps: the compartmentalization step and the compression step. In the compartmentalization step, we construct the expression tree based on the connected component structures of the FAQ-query relative to the hypergraph structure $\mathcal{H}$ . In the compression step we collapse the tree to make it shorter whenever possible.

定义4.（表达式树）表达式树$P$是为$\varphi$构建的根树。树中每个节点均为变量集合。构建过程分为两步：分区步骤与压缩步骤。分区步骤中，基于FAQ查询相对于超图结构$\mathcal{H}$的连通分量结构构建表达式树；压缩步骤则尽可能对树进行坍缩以缩短高度。

For technical reasons,we add a dummy variable ${X}_{0}$ to the beginning of the sequence with a free tag too. So the sequence we start off with is the following
