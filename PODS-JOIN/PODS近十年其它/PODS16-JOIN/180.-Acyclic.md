## ABSTRACT

## 摘要

Nested-loop join is a worst-case I/O-optimal algorithm for 2 relations. Recently, a lot of efforts have been devoted to the "triangle query", for which an I/O-optimal algorithm is known. This paper extends these results to a fairly large class of acyclic joins. Acyclic joins can be computed optimally in internal memory using Yannakakis' algorithm from 1981, which simply performs a series of pairwise joins. However, no pairwise join algorithm can be I/O-optimal beyond 2 relations. To achieve I/O-optimality, the algorithm has to handle all the intermediate results carefully without writing them to disk. Unlike the optimal internal memory join algorithm which has a nice tight bound (the AGM bound), the I/O-complexity of joins turns out to be quite complex or even unknown. Yet, we are able to prove that our algorithm is I/O-optimal for certain classes of acyclic joins without deriving its bound explicitly.

嵌套循环连接是针对两个关系表的最坏情况I/O最优算法。近期大量研究聚焦于"三角查询"，该领域已存在I/O最优算法。本文将这些成果扩展至更广泛的无环连接类型。1981年Yannakakis提出的算法可在内存中通过一系列两两连接实现无环连接的最优计算，但超过两个关系表时，任何两两连接算法都无法实现I/O最优性。为实现I/O最优，算法必须谨慎处理所有中间结果而不写入磁盘。与内存最优连接算法具有明确紧界（AGM界）不同，连接操作的I/O复杂度往往极为复杂甚至未知。尽管如此，我们仍能证明所提算法对特定无环连接类具有I/O最优性，而无需显式推导其复杂度边界。

## 1. INTRODUCTION

## 1. 引言

Evaluating join queries is one of the most central problems in relational databases, both in theory and practice. Yet surprisingly, the worst-case complexity of join evaluation has started to be unraveled just recently, largely thanks to the work of Atserials, Grohe, and Marx [2], who gave a worst-case bound on the join size. This then led to worst-case optimal ${}^{1}$ join algorithms [9,13]. Ngo,Ré,and Rudra [10] presented a nice survey of these results, and also gave a simpler and unified proof for both the AGM bound and the running time of the algorithm.

连接查询评估是关系数据库理论和实践中最核心的问题之一。令人惊讶的是，连接评估的最坏情况复杂度直到近年才被揭示，这主要归功于Atserials、Grohe和Marx的研究[2]，他们给出了连接规模的最坏情况边界。该成果进而催生了最坏情况最优${}^{1}$连接算法[9,13]。Ngo、Ré和Rudra[10]对这些成果进行了精辟综述，并为AGM界及算法时间复杂度提供了更简洁的统一证明。

These new optimal join algorithms crucially rely on retrieving tuples from a hash table, so they do not work well in external memory. On the other hand, most standard join algorithms used in existing database systems, like nested-loop join or sort-merge join, are specifically designed for limited main memory. Indeed, they achieve I/O-optimality for 2-table joins (more details to follow). Naturally, the intriguing question is if we can extend these algorithms to a broader class of joins in the external memory model.

这些新型最优连接算法本质上依赖哈希表元组检索，因此在外存环境中表现欠佳。而现有数据库系统采用的标准连接算法（如嵌套循环连接或排序合并连接）专为有限主内存设计，确实能实现两表连接的I/O最优性（后续详述）。自然引出的问题是：能否在外存模型中将这些算法扩展至更广泛的连接类型？

### 1.1 Problem definition

### 1.1 问题定义

Formally,a (natural) join is a triple $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$ ,where $\mathcal{V}$ is a set of attributes, $\mathcal{E} \subseteq  {2}^{\mathcal{V}}$ is a set of relations,and $N$ is a function mapping each relation $e \in  \mathcal{E}$ to a positive integer $N\left( e\right)$ . Let $\operatorname{dom}\left( v\right)$ be the domain of attribute $v \in  \mathcal{V}$ . An instance of $\mathcal{Q}$ is a function $R$ that maps each $e \in  \mathcal{E}$ to a set of tuples $R\left( e\right)$ with $\left| {R\left( e\right) }\right|  \leq  N\left( e\right)$ ,where each tuple $t \in  R\left( e\right)$ specifies a value in $\operatorname{dom}\left( v\right)$ for every attribute $v \in  e$ . The join results of $\mathcal{Q}$ on $R$ ,denoted by $\mathcal{Q}\left( R\right)$ ,consist of all combinations of tuples,one from each $R\left( e\right)$ ,that share common values for their common attributes. In this paper we assume that the query has constant size, namely, we consider the data complexity of computing the join. Indeed, the problem is intractable in terms of query size since $\left| {\mathcal{Q}\left( R\right) }\right|$ is exponential in $\left| \mathcal{E}\right|$ in the worst case. When the relations have subscripts as ${e}_{1},{e}_{2},\ldots$ ,we use ${N}_{i},{R}_{i},{x}_{i}$ ,etc., as shorthands for $N\left( {e}_{i}\right) ,R\left( {e}_{i}\right) ,x\left( {e}_{i}\right)$ ,etc.

形式上，(自然)连接是一个三元组$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$，其中$\mathcal{V}$是属性集合，$\mathcal{E} \subseteq  {2}^{\mathcal{V}}$是关系集合，$N$是将每个关系$e \in  \mathcal{E}$映射到正整数$N\left( e\right)$的函数。设$\operatorname{dom}\left( v\right)$为属性$v \in  \mathcal{V}$的域。$\mathcal{Q}$的实例是一个函数$R$，它将每个$e \in  \mathcal{E}$映射到具有$\left| {R\left( e\right) }\right|  \leq  N\left( e\right)$的元组集合$R\left( e\right)$，其中每个元组$t \in  R\left( e\right)$为每个属性$v \in  e$指定$\operatorname{dom}\left( v\right)$中的值。$\mathcal{Q}$在$R$上的连接结果（记作$\mathcal{Q}\left( R\right)$）包含所有元组的组合，每个组合从各$R\left( e\right)$中取一个元组，这些元组在其共有属性上具有相同值。本文假设查询具有恒定大小，即我们考虑计算连接的数据复杂度。实际上，就查询大小而言该问题是难解的，因为最坏情况下$\left| {\mathcal{Q}\left( R\right) }\right|$相对于$\left| \mathcal{E}\right|$呈指数级增长。当关系带有<b17></b7>等下标时，我们使用${N}_{i},{R}_{i},{x}_{i}$等作为$N\left( {e}_{i}\right) ,R\left( {e}_{i}\right) ,x\left( {e}_{i}\right)$等的简写。

We use the standard external memory model [1], which has a main memory of size $M$ with disk block size $B$ . For simpler presentation, we will assume that the memory size is $c \cdot  M$ for a sufficiently large constant $c$ ,which will not change our results by more than a constant factor. Note that since we assume a constant query size, the sizes of the tuples do not matter asymptotically,and we may assume $O\left( M\right)$ tuples from any relation fit in memory. Here are some standard bounds in this model: scanning $N$ tuples needs $O\left( \frac{N}{B}\right) \mathrm{I}/\mathrm{{Os}}$ , and sorting $N$ tuples can be done in $O\left( {\frac{N}{B}{\log }_{\frac{M}{B}}\frac{\widetilde{N}}{B}}\right)$ I/Os. In this paper, we will ignore this log factor, and simply say that both can be done in $\widetilde{O}\left( \frac{N}{B}\right) \mathrm{I}/\mathrm{{Os}}$ ,where the $\widetilde{O}$ notation suppresses possibly one ${\log }_{\frac{M}{B}}\frac{N}{B}$ factor. For simplicity,we will assume $N\left( e\right)  \geq  M$ for every $e$ ; otherwise proper ceiling will have to be carefully added to the I/O bounds.

我们采用标准外部存储模型[1]，其主存大小为$M$，磁盘块大小为$B$。为简化表述，假设内存大小为足够大常数$c$的$c \cdot  M$倍，这不会使我们的结果产生超过常数倍的变化。注意由于假设查询大小恒定，元组大小在渐近意义上无关紧要，可假定任何关系的$O\left( M\right)$个元组都能装入内存。该模型下一些标准界限为：扫描$N$个元组需要$O\left( \frac{N}{B}\right) \mathrm{I}/\mathrm{{Os}}$次I/O，排序$N$个元组可在$O\left( {\frac{N}{B}{\log }_{\frac{M}{B}}\frac{\widetilde{N}}{B}}\right)$次I/O内完成。本文将忽略对数因子，简记两者均为$\widetilde{O}\left( \frac{N}{B}\right) \mathrm{I}/\mathrm{{Os}}$次，其中$\widetilde{O}$记号可能隐含一个${\log }_{\frac{M}{B}}\frac{N}{B}$因子。为简化起见，假设对每个$e$都有$N\left( e\right)  \geq  M$；否则需在I/O界限中谨慎添加适当上限取整。

For each join result, the algorithm should call an emit function with all the participating tuples, which must reside in memory at the time of the call, but does not have to write the result to disk. This agrees with most prior work on I/O-efficient join algorithms $\left\lbrack  {6,7,{12}}\right\rbrack$ ,and also reflects how join results are usually consumed in real database systems: they are often directly fed to a process down in the pipeline; sometimes the user just wants to apply an aggregation function (standard or an UDF) on the join results in a streaming fashion. For lower bounds, we apply the same emit requirement, and assume that the tuples are indivisible, which is a standard assumption in the external memory model. The indivisibility assumption is often justified by the fact that the user may be interested in the tuples as a whole entity, e.g., the user may need the tuples' other attributes that do not participate in the join.

对于每个连接结果，算法需调用emit函数处理所有参与元组——这些元组在调用时必须驻留内存，但无需将结果写入磁盘。这与大多数I/O高效连接算法的前期研究$\left\lbrack  {6,7,{12}}\right\rbrack$一致，也反映了真实数据库系统中连接结果的典型消费方式：它们通常直接馈送给流水线下游处理；有时用户仅需以流式方式对连接结果应用聚合函数（标准函数或UDF）。对于下界分析，我们采用相同的emit要求，并假设元组不可分割——这是外部存储模型的标准假设。该不可分割假设的合理性在于：用户可能将元组视为完整实体，例如需要访问未参与连接的其他属性。

As with prior work on acyclic joins $\left\lbrack  {{14},{11}}\right\rbrack$ ,we assume that the relations are fully reduced, i.e., there are no "dangling" tuples. More precisely,for any relation $R\left( e\right)$ and any attribute $v \in  e$ ,for each value $a \in  \operatorname{dom}\left( v\right)$ ,there is at least one tuple $t \in  R\left( e\right)$ such that $t$ has value $a$ on attribute $v$ . For acyclic joins, the relations can be fully reduced in linear time and linear I/Os (ignoring a log factor) in external memory, using a series of semijoins, as described in [14]. In the rest of the paper, we omit the linear term when stating the running time or I/O cost of algorithms for brevity.

如同无环连接的前期研究$\left\lbrack  {{14},{11}}\right\rbrack$，我们假设关系已完全约简，即不存在"悬空"元组。具体而言，对于任意关系$R\left( e\right)$和属性$v \in  e$，每个值$a \in  \operatorname{dom}\left( v\right)$至少对应一个元组$t \in  R\left( e\right)$，使得该元组在属性$v$上的值为$a$。如文献[14]所述，在外部存储中，通过系列半连接操作，可在线性时间和线性I/O（忽略对数因子）内完成无环连接的完全约简。后文为简洁起见，在陈述算法运行时间或I/O成本时将省略该线性项。

### 1.2 Previous results

### 1.2 先前研究成果

In internal memory, there is a unified optimal algorithm $\left\lbrack  {9,{13}}\right\rbrack$ ,based on the AGM bound $\left\lbrack  2\right\rbrack$ ,for all join queries. The AGM bound is based on the optimal fractional edge cover of the query hypergraph (details given in Section 2.1). It can be simplified when considering specific join queries, as listed in Table 1.

内存环境中存在基于AGM界$\left\lbrack  2\right\rbrack$的统一最优算法$\left\lbrack  {9,{13}}\right\rbrack$，适用于所有连接查询。AGM界建立在查询超图的最优分数边覆盖基础上（详见2.1节）。针对特定连接查询时可简化，如表1所列。

However, the situation is much more complicated in external memory. We know that nested-loop join uses $O\left( \frac{{N}_{1}{N}_{2}}{MB}\right)$ $\mathrm{I}/\mathrm{{Os}}$ to join two relations of sizes ${N}_{1}$ and ${N}_{2}$ . Since $\left| {\mathcal{Q}\left( R\right) }\right|  =$ ${N}_{1}{N}_{2}$ in the worst case,and the $B$ tuples brought in by one disk I/O can join with at most $O\left( M\right)$ tuples that are currently in memory, this bound is optimal.

然而外部存储中的情况更为复杂。已知嵌套循环连接使用$O\left( \frac{{N}_{1}{N}_{2}}{MB}\right)$$\mathrm{I}/\mathrm{{Os}}$来连接大小为${N}_{1}$和${N}_{2}$的两个关系。由于最坏情况下$\left| {\mathcal{Q}\left( R\right) }\right|  =$${N}_{1}{N}_{2}$，且单次磁盘I/O载入的$B$个元组最多只能与内存中的$O\left( M\right)$个元组连接，故此边界是最优的。

The triangle query has received particular attention [7, 12],where $\mathcal{V} = \left\{  {{v}_{1},{v}_{2},{v}_{3}}\right\}  ,{e}_{1} = \left\{  {{v}_{1},{v}_{2}}\right\}  ,{e}_{2} = \left\{  {{v}_{1},{v}_{3}}\right\}  ,{e}_{3} =$ $\left\{  {{v}_{2},{v}_{3}}\right\}$ . An I/O-optimal algorithm is known,but only when ${N}_{1} = {N}_{2} = {N}_{3}$ . Hu,Qiao,and Tao [6] extended this algorithm to Loomis-Whitney joins, a very special class of cyclic joins, but its optimality is still unclear, even when all relations have equal size.

三角形查询受到了特别关注[7,12]，其中$\mathcal{V} = \left\{  {{v}_{1},{v}_{2},{v}_{3}}\right\}  ,{e}_{1} = \left\{  {{v}_{1},{v}_{2}}\right\}  ,{e}_{2} = \left\{  {{v}_{1},{v}_{3}}\right\}  ,{e}_{3} =$$\left\{  {{v}_{2},{v}_{3}}\right\}$。已知存在I/O最优算法，但仅当${N}_{1} = {N}_{2} = {N}_{3}$时适用。胡、乔和陶[6]将该算法扩展至Loomis-Whitney连接（一类特殊的循环连接），但即使所有关系大小相同，其最优性仍不明确。

Most database schemas are acyclic, due to its many desirable properties [3]. Indeed, in as early as 1981, Yannakakis [14] already gave an internal memory algorithm that evaluates any acyclic join in $O\left( \left| {\mathcal{Q}\left( R\right) }\right| \right)$ time,which is clearly optimal (in fact, instance optimal). This algorithm easily extends to external memory, as observed in [11], yielding an algorithm with $\widetilde{O}\left( \frac{\left| \mathcal{Q}\left( R\right) \right| }{B}\right)$ I/Os. This bound,however,is only optimal when the join results have to be written out to disk. In the emit model, it is even worse than a simple nested-loop join by a factor of $M$ in the worst case for a 2- relation join, and the optimality gap gets even larger when more relations are joined, as we will see shortly.

由于具备诸多优良特性[3]，大多数数据库模式都是无环的。事实上早在1981年，Yannakakis[14]就提出了能在$O\left( \left| {\mathcal{Q}\left( R\right) }\right| \right)$时间内计算任何无环连接的内存算法（显然是最优的，甚至是实例最优的）。如文献[11]所述，该算法可扩展至外存，产生$\widetilde{O}\left( \frac{\left| \mathcal{Q}\left( R\right) \right| }{B}\right)$次I/O的算法。但这个界仅在连接结果需写入磁盘时最优。在发射模型中，对于2-关系连接，最坏情况下甚至比简单嵌套循环连接差$M$倍，随着连接关系增多，最优性差距会进一步扩大。

After the relations have been fully reduced, Yannakakis' algorithm simply performs a series of pairwise joins between two relations sharing a common attribute, as in standard join processing in a database system. In internal memory, this works because these intermediate join sizes are no larger than the full join size. In external memory, however, we cannot afford to write any intermediate results in full to disk, so we will have to depart from this pairwise framework in order to achieve I/O-optimality. Note that simply pipelining the intermediate results to the next join operator will not work, as that join operator may use a nested-loop join, which requires reading one of its input relations multiple times. Thus, careful handling of the intermediate results with limited memory is a key challenge for an external memory algorithm.

关系完全约简后，Yannakakis算法仅执行共享共同属性的两个关系间的成对连接，如同数据库系统中的标准连接处理。在内存中可行是因为这些中间连接规模不超过完整连接规模。但在外存中，我们无法承受将中间结果完整写入磁盘，因此必须脱离这种成对框架以实现I/O最优性。需注意简单地将中间结果流水传递给下一连接运算符不可行，因为该运算符可能采用需要多次读取输入关系的嵌套循环连接。因此，有限内存下对中间结果的谨慎处理是外存算法的关键挑战。

### 1.3 Acyclicity

### 1.3 无环性

The acyclicity of the join $\mathcal{Q}$ is defined with respect to the hypergraph(V,E). Unlike ordinary acyclic graphs (i.e., trees or forests), there are several notions of acyclicity for hypergraphs. We adopt the most natural definition, given by Berge [4]. Consider the bipartite graph $G$ ,in which $\mathcal{V}$ corresponds to vertices on one side and $\mathcal{E}$ to vertices on the other side. There is an edge between $v \in  \mathcal{V}$ and $e \in  \mathcal{E}$ if $v \in  e$ . Then the hypergraph(V,E)is said to be acyclic if this bipartite graph is acyclic. This notion of acyclicity preserves many natural properties in ordinary acyclic graphs. For example, there is only one path between any two vertices $u,v \in  \mathcal{V}$ ,and any subgraph of(V,E)is still acyclic. Note that this definition of acyclicity does not allow two relations to have two or more common attributes. But if these attributes always appear together in any relation, then they can be simply considered as one "combined" attribute.

连接$\mathcal{Q}$的无环性是针对超图(V,E)定义的。不同于普通无环图（即树或森林），超图无环性有多个定义标准。我们采用Berge[4]提出的最自然定义。考虑二分图$G$，其中$\mathcal{V}$对应一侧顶点，$\mathcal{E}$对应另一侧顶点。若$v \in  e$，则$v \in  \mathcal{V}$与$e \in  \mathcal{E}$间存在边。当该二分图无环时，称超图(V,E)无环。这种无环性保留了普通无环图的许多自然特性，例如任意两顶点$u,v \in  \mathcal{V}$间只有一条路径，且(V,E)的任何子图仍无环。需注意此定义不允许两个关系拥有两个及以上共同属性，但若这些属性在任何关系中总同时出现，可将其视为一个"组合"属性。

We do point out that earlier work on acyclic queries, including Yannakakis' algorithm, has adopted a more relaxed notion of acyclicity,known as $\alpha$ -acyclicity. However, $\alpha$ - acyclicity does not preserve the two properties above. In particular,removing a hyperedge from an $\alpha$ -acyclic hyper-graph can make it cyclic, which is quite counter-intuitive. In particular, two most commonly used types of joins, line joins and star joins, are both Berge-acyclic, to which we will pay special attention. Henceforth, "acyclic" will always mean "Berge-acyclic".

我们指出早期关于无环查询的研究（包括Yannakakis算法）采用了更宽松的$\alpha$-无环性定义。但$\alpha$-无环性不保留上述两个特性，特别是从$\alpha$-无环超图中移除超边可能使其变为有环，这相当反直觉。我们将特别关注两种最常用的连接类型——线型连接和星型连接，它们都是Berge-无环的。后文所述"无环"均指"Berge-无环"。

### 2.1 The AGM bound

### 2.1 AGM界

For a query $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$ ,let $x$ be a fractional edge cover for the hypergraph(V,E),i.e.,for any $v \in  \mathcal{V},\mathop{\sum }\limits_{{e,v \in  e}}x\left( e\right)  \geq$ 1. Then the AGM bound [2] states that

对于查询$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$，设$x$为超图(V,E)的分数边覆盖，即对任意$v \in  \mathcal{V},\mathop{\sum }\limits_{{e,v \in  e}}x\left( e\right)  \geq$≥1。根据AGM界[2]可得：

$$
\mathop{\max }\limits_{R}\left| {\mathcal{Q}\left( R\right) }\right|  = \mathop{\min }\limits_{x}\mathop{\prod }\limits_{e}N{\left( e\right) }^{x\left( e\right) }.
$$

Note that the optimal fractional edge cover $x$ can be found by solving a linear program on the $N\left( e\right)$ ’s,which takes $O\left( 1\right)$ time for constant query size.

LEMMA 1. In an acyclic query, there is always a relation that contains only one attribute, or an attribute that is contained in only one relation.

引理1. 在无环查询中，总存在仅含单个属性的关系，或仅属于单个关系的属性。

This leads to the following important observation of the AGM bound on acyclic queries. Let $x$ be the optimal fractional cover of $\mathcal{Q}$ .

由此可得无环查询上AGM界的重要推论。设$x$为$\mathcal{Q}$的最优分数覆盖：

LEMMA 2. For acyclic queries, $x\left( e\right)  = 0$ or 1 for each $e$ .

引理2. 对于无环查询，每个$e$的$x\left( e\right)  = 0$值为0或1。

Proof. Let $A$ be the incidence matrix of the linear program defined on $x$ ,which has a 1 at row $e$ and column $v$ if $v \in  e$ ,and 0 otherwise. It is known that the optimal solution of the linear program is integral if the determinant of any square submatrix of $A$ is $\pm  1$ or 0 . We prove this by induction on the size of the submatrix. For a $1 \times  1$ submatrix,this is trivially true. Suppose $\det \left( {A}^{\prime }\right)  =  \pm  1$ or 0 for any $k \times  k$ submatrix ${A}^{\prime }$ of $A$ . Consider any $\left( {k + 1}\right)  \times  \left( {k + 1}\right)$ submatrix ${A}^{\prime }$ of $A$ ,which corresponds to a subset of $k + 1$ vertices ${\mathcal{V}}^{\prime }$ and a subset of $k + 1$ edges ${\mathcal{E}}^{\prime }$ of the hypergraph. Since any sub-hypergraph of an acyclic hypergraph is acyclic, by Lemma 1 there is one relation in ${\mathcal{E}}^{\prime }$ that contains only one attribute in ${\mathcal{V}}^{\prime }$ or one attribute in ${\mathcal{V}}^{\prime }$ that is contained in only one relation in ${\mathcal{E}}^{\prime }$ . In either case, ${A}^{\prime }$ can be rearranged as

证明。设$A$为定义在$x$上的线性规划关联矩阵，当$v \in  e$时，其第$e$行第$v$列元素为1，否则为0。已知当$A$的任意方阵子式行列式为$\pm  1$或0时，该线性规划的最优解为整数解。我们通过对子矩阵规模的归纳法证明此命题。对于$1 \times  1$阶子矩阵，命题显然成立。假设$A$的任意$k \times  k$阶子矩阵${A}^{\prime }$的行列式为$\det \left( {A}^{\prime }\right)  =  \pm  1$或0。考虑$A$的$\left( {k + 1}\right)  \times  \left( {k + 1}\right)$阶子矩阵${A}^{\prime }$，其对应超图中$k + 1$个顶点${\mathcal{V}}^{\prime }$的子集与$k + 1$条边${\mathcal{E}}^{\prime }$的子集。由于无环超图的任意子超图皆无环，根据引理1，存在${\mathcal{E}}^{\prime }$中仅含${\mathcal{V}}^{\prime }$单个属性的关系，或${\mathcal{V}}^{\prime }$中仅被${\mathcal{E}}^{\prime }$单个关系包含的属性。无论哪种情况，${A}^{\prime }$均可重排为

$$
{A}^{\prime } = \left( \begin{matrix} 1 &  * \\  0 & {A}^{\prime \prime } \end{matrix}\right) ,
$$

where ${A}^{\prime \prime }$ is a $k \times  k$ submatrix of $A$ . Then by the induction hypothesis, $\det \left( {A}^{\prime }\right)  =  \pm  1 \cdot  \det \left( {A}^{\prime \prime }\right)  =  \pm  1$ or 0 .

其中${A}^{\prime \prime }$是$A$的$k \times  k$阶子矩阵。根据归纳假设，其行列式为$\det \left( {A}^{\prime }\right)  =  \pm  1 \cdot  \det \left( {A}^{\prime \prime }\right)  =  \pm  1$或0。

We classify the attributes and relations as follows. If an attribute $v \in  \mathcal{V}$ appears in only one relation,it is called a unique attribute, otherwise a join attribute. Note that any two relations have at most one common join attribute due to the acyclicity requirement. A relation $e$ is called an island if $e$ has no join attribute. A bud is a relation with only one join attribute and no unique attribute. A relation $e$ is called a leaf if it contains at least one unique attribute and exactly one join attribute. For a leaf $e$ ,let $\Gamma \left( e\right)$ be its neighbors,i.e., the set of other relations sharing the join attribute with $e$ . These terms are illustrated in Figure 2.

我们将属性和关系分类如下：若属性$v \in  \mathcal{V}$仅出现在单个关系中，则称其为唯一属性，否则称为连接属性。注意由于无环性要求，任意两个关系至多有一个共同连接属性。若关系$e$不含连接属性，则称其为孤岛。芽苞是指仅含一个连接属性且无唯一属性的关系。若关系$e$包含至少一个唯一属性且恰好一个连接属性，则称其为叶节点。对于叶节点$e$，令$\Gamma \left( e\right)$表示其邻域，即共享该连接属性的其他关系集合。这些术语如图2所示。

By Lemma 1, there is always an island, a bud, or a leaf in an acyclic query. One may wonder why we consider islands and buds as they are not very meaningful in a join query. The reason, as we shall see later, is that they can appear during the recursive processing of the join in our algorithm, so we have to consider them for full generality.

根据引理1，无环查询中必然存在孤岛、芽苞或叶节点。可能有人质疑为何要考虑在连接查询中意义不大的孤岛和芽苞。原因在于，如后文所述，它们可能出现在算法递归处理连接的过程中，因此必须考虑这些情形以保证普适性。

### 2.3 Handling skew

### 2.3 数据偏斜处理

Similar with the optimal join algorithms in internal memory [10], it is important to handle skew properly. In external memory,skew is defined with respect to the memory size $M$ .

与内存最优连接算法[10]类似，正确处理数据偏斜至关重要。在外存环境中，偏斜是相对于内存大小$M$定义的。

For a relation $R\left( e\right)$ and an attribute $v \in  e$ ,the set of tuples in $R\left( e\right)$ with value $a$ on attribute $v$ is denoted as ${\left. R\left( e\right) \right| }_{v = a}$ , and let ${\left. N\left( e\right) \right| }_{v = a} = {\left| R\left( e\right) \right| }_{v = a}$ .

对于关系$R\left( e\right)$和属性$v \in  e$，将$R\left( e\right)$中属性$v$取值为$a$的元组集合记为${\left. R\left( e\right) \right| }_{v = a}$，并设${\left. N\left( e\right) \right| }_{v = a} = {\left| R\left( e\right) \right| }_{v = a}$。

A value $a$ is heavy in $R\left( e\right)$ if ${\left. N\left( e\right) \right| }_{v = a} \geq  M$ ,otherwise light. Denote the set of heavy values in $\operatorname{dom}\left( v\right)$ with respect to $R\left( e\right)$ as

若${\left. N\left( e\right) \right| }_{v = a} \geq  M$，则称值$a$在$R\left( e\right)$上为重值(heavy)，否则为轻值(light)。将$\operatorname{dom}\left( v\right)$中关于$R\left( e\right)$的重值集合记为

$$
H\left( {e,v}\right)  = \left\{  {a \in  \operatorname{dom}\left( v\right)  : {\left. N\left( e\right) \right| }_{v = a} \geq  M}\right\}  .
$$

Note that by sorting $R\left( e\right)$ on the $v$ attribute,we can partition the tuples in $R\left( e\right)$ into those with heavy values on $v$ and those with light values.

注意通过对$R\left( e\right)$按$v$属性排序，我们可以将$R\left( e\right)$中的元组划分为$v$上的重值元组和轻值元组。

We will use the following operations in describing our algorithms. If $R\left( e\right)$ is sorted on $v$ ,we can handle the heavy and light values separately. For a heavy value $a$ ,the operation "load ${\left. R\left( e\right) \right| }_{v = a}$ into memory as $M\left( e\right)$ " means reading the next $M$ tuples of ${\left. R\left( e\right) \right| }_{v = a}$ into memory,and these tuples are denoted as $M\left( e\right)$ . This operation is usually repeatedly invoked,and and last invocation may read less than $M$ tuples from ${\left. R\left( e\right) \right| }_{v = a}$ . For light values,the operation "load $R\left( e\right)$ by $v$ into memory as $M\left( e\right)$ " means reading tuples from $R\left( e\right)$ by the order of $v$ until $M$ or more tuples are fetched, subject to the constraint that tuples with the same value on attribute $v$ must be loaded into memory together. Note that since all values are light,no more than ${2M}$ tuples will be loaded to memory,with no more than $M$ distinct values on $v$ . This operation can also be repeatedly invoked,and the last invocation may read less than $M$ tuples. If $R\left( e\right)$ is not sorted on any attribute,the operation "load $R\left( e\right)$ into memory as $M\left( e\right)$ " means reading the next $M$ tuples from $R\left( e\right)$ (again,the last invocation may read less than $M$ tuples).

算法描述中将使用以下操作：若$R\left( e\right)$已按$v$排序，则可分别处理重值与轻值。对于重值$a$，操作"将${\left. R\left( e\right) \right| }_{v = a}$作为$M\left( e\right)$载入内存"表示读取${\left. R\left( e\right) \right| }_{v = a}$的后$M$个元组到内存，这些元组记为$M\left( e\right)$。该操作通常被重复调用，最后一次调用可能从${\left. R\left( e\right) \right| }_{v = a}$读取少于$M$个元组。对于轻值，操作"按$v$将$R\left( e\right)$作为$M\left( e\right)$载入内存"表示按$v$顺序从$R\left( e\right)$读取元组，直到获取$M$个或更多元组，且要求$v$属性值相同的元组必须同时载入内存。由于所有值均为轻值，载入内存的元组不超过${2M}$个，且$v$上不同值不超过$M$个。该操作也可重复调用，最后一次可能读取少于$M$个元组。若$R\left( e\right)$未按任何属性排序，操作"将$R\left( e\right)$作为$M\left( e\right)$载入内存"表示从$R\left( e\right)$读取后$M$个元组（同样，最后一次调用可能读取少于$M$个元组）。

## 3. 预备知识

Before presenting our general join algorithm, we start with a review on 2-relation join algorithms and show how we can extend them to the 3-relation line join.

在介绍通用连接算法前，我们先回顾二元关系连接算法，并展示如何将其扩展至三元关系线连接。

For a join between 2 relations ${R}_{1}$ and ${R}_{2}$ ,we know that nested-loop join achieves $O\left( \frac{{N}_{1}{N}_{2}}{MB}\right) \mathrm{I}/\mathrm{{Os}}$ ,which is worst-case optimal as $\left| {\mathcal{Q}\left( R\right) }\right|$ can be as large as ${N}_{1}{N}_{2}$ in the worst case. In fact, by combining with sort-merge join, we can achieve instance optimality,i.e.,an algorithm that runs in $\widetilde{O}\left( \frac{\left| \mathcal{Q}\left( R\right) \right| }{MB}\right)$ $\mathrm{I}/\mathrm{{Os}}$ on any instance $R$ of $\mathcal{Q}$ . More precisely,we sort both relations on the join attribute $v$ ,and then "merge" them together. For each value $a \in  \operatorname{dom}\left( v\right)$ ,if $a$ is heavy in both ${R}_{1}$ and ${R}_{2}$ ,we run a nested-loop join on ${\left. {R}_{1}\right| }_{v = a} \boxtimes  {\left. {R}_{2}\right| }_{v = a}$ , costing $O\left( \frac{{N}_{1}{\left| {}_{v = a}{N}_{2}\right| }_{v = a}}{MB}\right) \mathrm{I}/\mathrm{{Os}}$ ; otherwise the merge can be done with a single pass of ${\left. {R}_{1}\right| }_{v = a}$ and ${\left. {R}_{2}\right| }_{v = a}$ . In fact, this algorithm has been described in textbooks [5], but it appears that its (I/O) instance optimality has never been formally stated.

对于两个关系${R}_{1}$与${R}_{2}$的连接操作，已知嵌套循环连接能实现$O\left( \frac{{N}_{1}{N}_{2}}{MB}\right) \mathrm{I}/\mathrm{{Os}}$，其最坏情况下是理论最优的——因为$\left| {\mathcal{Q}\left( R\right) }\right|$在最坏情况下可能达到${N}_{1}{N}_{2}$的量级。实际上，通过与排序归并连接相结合，我们可以实现实例最优性，即在任意$\mathcal{Q}$的实例$R$上，算法都能在$\widetilde{O}\left( \frac{\left| \mathcal{Q}\left( R\right) \right| }{MB}\right)$$\mathrm{I}/\mathrm{{Os}}$时间内完成。具体而言，我们首先按连接属性$v$对两个关系进行排序，然后执行"归并"操作。对于每个值$a \in  \operatorname{dom}\left( v\right)$，若其在${R}_{1}$和${R}_{2}$中均属于高频值，则对${\left. {R}_{1}\right| }_{v = a} \boxtimes  {\left. {R}_{2}\right| }_{v = a}$执行嵌套循环连接，耗时$O\left( \frac{{N}_{1}{\left| {}_{v = a}{N}_{2}\right| }_{v = a}}{MB}\right) \mathrm{I}/\mathrm{{Os}}$；否则只需单次扫描${\left. {R}_{1}\right| }_{v = a}$和${\left. {R}_{2}\right| }_{v = a}$即可完成归并。注意到$\left| {\mathcal{Q}\left( R\right) }\right|  = \mathop{\sum }\limits_{a}{N}_{1}{\left| {}_{v = a}{N}_{2}\right| }_{v = a}$，因此总I/O成本符合前述结论。值得注意的是，该算法虽在教材[5]中已有描述，但其（I/O层面的）实例最优性从未被正式阐明。

## 4. 无环连接的算法

### 4.1 The algorithm

### 4.1 算法描述

In this section, we generalize our 3-relation line join algorithm to handle arbitrary acyclic queries. The algorithm, described in Algorithm 2, recursively "peels off" a bud, an island, or a leaf.

本节将三关系线连接算法推广至任意无环查询。如算法2所述，该算法通过递归方式"剥离"芽点、孤岛或叶节点。

The base case is when only one relation remains, in which case we simply report all tuples (line 1-2). A bud can simply be ignored (line 3-4), as it has only one attribute and it appears in other relations. Since there are no dangling tuples, a bud cannot restrict other relations, either. Strictly speaking, however, ignoring a bud violates the emit model. But this can be easily fixed by attaching each tuple $t$ in the bud to all tuples it joins with. This takes linear I/Os in total, so it is not an issue.

基础情形是仅剩单个关系时，此时直接输出所有元组（第1-2行）。芽点可被忽略（第3-4行），因其仅含一个属性且存在于其他关系中。由于不存在悬挂元组，芽点也无法限制其他关系。严格来说，忽略芽点违反发射模型，但可通过将芽点中每个元组$t$附加到所有连接元组来修正，该操作总线性I/O成本可忽略。

An island $e$ can be peeled off by just using nested-loop join with $R\left( e\right)$ being the "outer relation" and the rest of $\mathcal{Q}$ as the "inner relation" (line 5-9). The rationale is that any tuple in $R\left( e\right)$ joins with any join result from the rest of $\mathcal{Q}$ , so the I/O cost inevitably will have $\frac{N\left( e\right) }{M}$ multiplied with the cost of computing the rest of $\mathcal{Q}$ .

剥离孤岛$e$时，只需以$R\left( e\right)$为"外表"、其余$\mathcal{Q}$为"内表"执行嵌套循环连接（第5-9行）。其原理在于$R\left( e\right)$中任何元组都会与$\mathcal{Q}$其余部分的连接结果结合，因此I/O成本必然包含$\frac{N\left( e\right) }{M}$与计算$\mathcal{Q}$其余部分成本的乘积。

To peel a leaf $e$ ,the idea is similar to the 3-relation line join algorithm, handling heavy (line 14-20) and light tuples (line 21-27) in $R\left( e\right)$ separately. There are two key differences, though. First,computing the join on (parts of) ${R}_{2}$ and ${R}_{3}$ will be replaced by recursion. Second, for a general acyclic join,a leaf $e$ may share its join attribute with more than one relations,namely,there can be more than one " ${R}_{2}$ ".

剥离叶子节点$e$的思路类似于三关系线连接算法，需分别处理$R\left( e\right)$中的重型元组（第14-20行）和轻型元组（第21-27行）。但存在两个关键差异：首先，对${R}_{2}$和${R}_{3}$（部分）执行连接运算将被递归替代；其次，对于一般无环连接，叶子节点$e$可能与多个关系共享连接属性，即可能存在多个"${R}_{2}$"。

We provide some more explanation on the algorithm for peeling off a leaf. First, a seemingly difficult decision is which leaf to peel. Indeed, different pealing strategies may lead to different costs. For example,on ${L}_{4}$ ,we will see later that different peeling strategies would lead to two different bounds, $\widetilde{O}\left( \frac{{N}_{1}{N}_{3}{N}_{4}}{{M}^{3}B}\right)$ and $\widetilde{O}\left( \frac{{N}_{1}{N}_{2}{N}_{4}}{{M}^{3}B}\right)$ ,respectively. Thus,a "smart" algorithm should first compare ${N}_{2}$ and ${N}_{3}$ ,and then choose the better peeling strategy. However, as we are not trying to optimize the dependency on $n$ ,the number of relations,we chose to simply pick a leaf $e$ nondeterministically (line 11). To convert this nondeterministic algorithm to a deterministic one, we use the standard simulation technique to explore all nondeterministic branches in a round-robin fashion, terminating the simulation as soon as any branch terminates. In effect, we attain the cost of the best peeling strategy,up to a factor that might be exponential in $n$ , which is a constant anyway.

我们进一步阐释剥离叶子节点的算法。首先，看似困难的是选择剥离哪个叶子节点——实际上不同剥离策略会导致不同代价。例如在${L}_{4}$上，后文将看到不同剥离策略分别产生$\widetilde{O}\left( \frac{{N}_{1}{N}_{3}{N}_{4}}{{M}^{3}B}\right)$和$\widetilde{O}\left( \frac{{N}_{1}{N}_{2}{N}_{4}}{{M}^{3}B}\right)$两种边界。因此，"智能"算法应先比较${N}_{2}$与${N}_{3}$，再选择更优的剥离策略。但由于我们未尝试优化对关系数量$n$的依赖，故选择非确定性地随机选取叶子节点$e$（第11行）。将此非确定性算法转换为确定性版本时，我们采用标准模拟技术以轮询方式探索所有非确定性分支，任一分支终止即停止模拟。最终获得的剥离策略代价，可能包含与$n$成指数关系的因子，但该因子始终为常数。

### 4.2 分析

We will bound the I/O-cost of Algorithm 4 in terms of $\Psi \left( {R,S}\right)$ ,the minimum cost of computing the subjoins. The first bound,stated below,uses all subsets $S$ of the relations.

我们将根据$\Psi \left( {R,S}\right)$（计算子连接的最小成本）界定算法4的I/O开销。如下所述的第一界限使用了所有关系子集$S$。

THEOREM 2. For an acyclic join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$ and instance $R$ ,the $I/O$ cost of Algorithm 2 is

定理2. 对于无环连接$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$和实例$R$，算法2的$I/O$成本为

$$
\widetilde{O}\left( {\mathop{\max }\limits_{{S \subseteq  \mathcal{E}}}\Psi \left( {R,S}\right) }\right) , \tag{3}
$$

where $S$ is over all subsets of $\mathcal{E}$ .

其中$S$遍历$\mathcal{E}$的所有子集。

The proof is by induction and naturally follows the recursion of the algorithm. The details are quite technical, though, and are given in Appendix A.1.

该证明采用归纳法，自然遵循算法的递归过程。不过具体细节涉及较多技术内容，详见附录A.1。

It is not hard to see that this bound cannot be tight. In particular, it does not depend on the peeling order, which means that this is actually a bound on the worst branch of the nondeterministic peeling process. The other source of looseness comes from a star. A star consists of a core ${e}_{0}$ that has no unique attributes,and $k$ petals ${e}_{1},\ldots ,{e}_{k},k \geq  1$ ,such that ${e}_{i} \cap  {e}_{0} \neq  \varnothing$ . Each petal contains one or more unique attributes and does not intersect with any relations except the core. The core connects with the rest of $\mathcal{Q}$ via exactly one join attribute. Please see Figure 5 for an illustration.

不难看出这个界限不可能紧致。特别地，它不依赖于剥离顺序，这意味着实际上这是非确定性剥离过程最差分支的界限。另一个宽松性来源是星型结构。星型结构由核心${e}_{0}$（无唯一属性）和$k$个花瓣${e}_{1},\ldots ,{e}_{k},k \geq  1$组成，满足${e}_{i} \cap  {e}_{0} \neq  \varnothing$。每个花瓣包含一个或多个唯一属性，且仅与核心相连。核心通过唯一连接属性与$\mathcal{Q}$其余部分关联。示意图见图5。

since ${R}_{0} \boxtimes  {R}_{1} \boxtimes  \cdots  \boxtimes  {R}_{k} \subseteq  {R}_{1} \boxtimes  \cdots  \boxtimes  {R}_{k}$ and $\Psi \left( {R,\left\{  {{e}_{0},{e}_{1}}\right. }\right.$ , $\left. \left. {\ldots ,{e}_{k}}\right\}  \right)$ has a larger denominator. 由于${R}_{0} \boxtimes  {R}_{1} \boxtimes  \cdots  \boxtimes  {R}_{k} \subseteq  {R}_{1} \boxtimes  \cdots  \boxtimes  {R}_{k}$和$\Psi \left( {R,\left\{  {{e}_{0},{e}_{1}}\right. }\right.$的分母更大，$\left. \left. {\ldots ,{e}_{k}}\right\}  \right)$意味着并非所有关系子集$S$都需要包含在(3)中。更重要的是，这个观察可递归应用。具体来说，当算法2连续剥离星型的花瓣及核心时，可作如下推论：若核心被纳入递归考虑，则不必包含所有花瓣；只有当核心未被包含时，所有花瓣才需出现在同一子连接中。

## 5. OPTIMALITY ON STAR JOINS

## 5. 星型连接的最优性

On a star query with $n$ petals,our analysis above immediately yields the following result.

对于具有$n$个花瓣的星型查询，我们上述分析直接得出以下结论。

COROLLARY 1. On a star join $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$ and an instance $R$ ,Algorithm 2 has $I/O$ cost

推论1. 在星型连接$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},N}\right)$和实例$R$上，算法2的$I/O$成本为

$$
\widetilde{O}\left( {\frac{\mathop{\prod }\limits_{{i = 1}}^{n}{N}_{i}}{{M}^{n - 1}B} + \mathop{\max }\limits_{{S \varsubsetneq  \mathcal{E},{e}_{0} \in  S}}\psi \left( {R,S}\right) }\right)  \tag{5}

### 6.1 Optimal edge cover

### 6.1 最优边覆盖

Let $x$ be the optimal edge cover of a $n$ -relation line join. First we give the characterization of $x$ :

设$x$为$n$关系线性连接的最优边覆盖。首先给出$x$的特征描述：

(1) ${x}_{1} = {x}_{n} = 1$ ;

(2) there are no two consecutive 0 ’s;

(2) 不存在连续两个0；

(3) there are no three consecutive 1 's ;

(3) 不存在连续三个1；

(4) there are no 5 consecutive ${x}_{i}$ ’s being(1,1,0,1,1).

(4) 不存在5个连续${x}_{i}$呈现(1,1,0,1,1)模式。

The first 3 rules are obvious; the last rule follows from the observation that(1,0,1,0,1)is always better than(1,1,0,1,1), since the size of the middle relation is smaller than the product of its two neighbors on fully reduced relations.

前三条规则显而易见；最后一条源于观测到(1,0,1,0,1)始终优于(1,1,0,1,1)，因为在完全归约关系上，中间关系的尺寸小于其两侧邻居关系的乘积。

Another simple observation is that $x$ has "sub-optimality", i.e.,for any ${x}_{i} = {x}_{j} = 1,i < j,\left( {{x}_{i},\ldots ,{x}_{j}}\right)$ must be an optimal edge cover for the subjoin ${R}_{i} \boxtimes  \cdots  \boxtimes  {R}_{j}$ . If not, we could replace $\left( {{x}_{i},\ldots ,{x}_{j}}\right)$ with a better one,which would improve $x$ for the whole join.

另一简单观察是$x$具有"次优性"，即对于任意${x}_{i} = {x}_{j} = 1,i < j,\left( {{x}_{i},\ldots ,{x}_{j}}\right)$，其必须为子连接${R}_{i} \boxtimes  \cdots  \boxtimes  {R}_{j}$的最优边覆盖。若非如此，我们可用更优方案替换$\left( {{x}_{i},\ldots ,{x}_{j}}\right)$，从而提升整个连接的$x$。

For any $i \leq  j,\left( {{x}_{i},\ldots ,{x}_{j}}\right)$ is called an alternating interval if $\left( {{x}_{i},\ldots ,{x}_{j}}\right)  = \left( {1,0,1,0,\ldots ,0,1}\right)$ . It is easy to see that $x$ must consist of one or more alternating intervals. A single ${x}_{i} = 1$ is also an alternating interval,but it can only appear at the two ends. For example,for $n = 4,x = \left( {1,0,1,1}\right)$ or (1,1,0,1).

若$\left( {{x}_{i},\ldots ,{x}_{j}}\right)  = \left( {1,0,1,0,\ldots ,0,1}\right)$，则称任意$i \leq  j,\left( {{x}_{i},\ldots ,{x}_{j}}\right)$为交替区间。显然$x$必须由一个或多个交替区间组成。单个${x}_{i} = 1$也是交替区间，但仅能出现在两端。例如$n = 4,x = \left( {1,0,1,1}\right)$或(1,1,0,1)。

### 6.2 Worst-case optimality

### 6.2 最坏情况最优性

In this subsection we give sufficient conditions under which Algorithm 2 is optimal.

本节给出算法2保持最优性的充分条件。

## When $n$ is odd.

## 当$n$为奇数时

For an odd $n$ ,we say that an $n$ -relation line join $\mathcal{Q}$ is balanced if

对于一个奇数$n$，当满足以下条件时，我们称$n$元关系线连接$\mathcal{Q}$是平衡的：

$$
{N}_{i}{N}_{i + 2}\cdots {N}_{j - 2}{N}_{j} \geq  {N}_{i + 1}{N}_{i + 3}\cdots {N}_{j - 3}{N}_{j - 1}
$$

for any $1 \leq  i < j \leq  n$ such that $j - i$ is an even number. Note that any 3-relation line join is always balanced after dangling tuples are removed. A 5-relation line join is balanced if ${N}_{1}{N}_{3}{N}_{5} \geq  {N}_{2}{N}_{4}$ .

对于任意$1 \leq  i < j \leq  n$，若$j - i$为偶数。注意所有3元关系线连接在移除悬空元组后总是平衡的。当${N}_{1}{N}_{3}{N}_{5} \geq  {N}_{2}{N}_{4}$时，5元关系线连接是平衡的。

LEMMA 3. On a balanced line join, the optimal edge cover $x$ must be alternating.

引理3. 在平衡线连接上，最优边覆盖$x$必须交替出现。

Proof. Suppose for contradiction that $x$ is not alternating,then by previous analysis, $x$ must consist of 3 or more alternating intervals. THEOREM 5. For odd $n$ ,Algorithm 2 is optimal for any balanced $n$ -relation line join.

证明. 只需证明对于$\mathcal{E}$的每个独立子集$S$，存在实例$I$使得$S$上的部分连接规模与该子集上的最大次级联规模相等，即$\left| {\mathcal{Q}\left( {I,S}\right) }\right|  = \mathop{\prod }\limits_{{e \in  S}}N\left( e\right) .$

It is easy to see that an instance $I$ in which each relation is the cross product of its two domains satisfies this requirement. However, we still need to ensure that such a construction is feasible. More precisely,suppose attribute ${v}_{i}$ has a domain size $\left| {\operatorname{dom}\left( {v}_{i}\right) }\right|  = {z}_{i}$ . Then the following is the sufficient and necessary condition for the feasibility of such an $I$ :

显然，若构造实例$I$使每个关系都是其两个域的笛卡尔积，则满足要求。但需确保该构造可行性。具体而言，设属性${v}_{i}$的域大小为$\left| {\operatorname{dom}\left( {v}_{i}\right) }\right|  = {z}_{i}$，则以下为$I$可行的充要条件：

## 8. CONCLUDING REMARKS

## 8. 结论与展望

In this paper, we have designed a worst-case I/O-optimal algorithm for computing a fairly large class of acyclic joins. Interestingly, we have been able to prove its optimality without deriving its worst-case bound explicitly. This is done by relating the I/O cost of the algorithm to all the subjoins sizes, and then showing that the subjoin sizes match the corresponding partial join sizes in the worst case.

本文设计了一种针对大规模无环连接的最坏情况I/O最优算法。值得注意的是，我们无需显式推导最坏情况边界即可证明其最优性。这是通过将算法I/O成本与所有子连接大小关联，并证明在最坏情况下子连接大小与对应部分连接大小相匹配来实现的。

We conclude by mentioning a few interesting open problems.

最后我们提出若干待解决的开放性问题：

1. For cases where our general algorithm is not optimal, in particular for line joins with 5 to 8 relations, we have designed special algorithms to achieve optimality. Is there a more unified way to tackle these cases?

1. 针对通用算法非最优的情况（特别是5至8个关系的线性连接），我们已设计特殊算法实现最优。是否存在更统一的处理方法？

2. Yannakakis' algorithm is instance optimal in internal memory. However, we conjecture that such an algorithm does not exist in external memory, even on 3 relations. Is there a formal proof? If it indeed does not exist, are there any conditions under which it does?

2. Yannakakis算法在内存中具有实例最优性。但我们推测外存中不存在此类算法（即使对3个关系）。是否存在形式化证明？若确实不存在，在何种条件下可能实现？

3. How about cyclic joins? So far, worst-case I/O-optimal algorithms are known only for triangle queries on relations of equal size.

3. 循环连接情况如何？目前仅知在关系大小相等时，三角形查询存在最坏情况I/O最优算法。
