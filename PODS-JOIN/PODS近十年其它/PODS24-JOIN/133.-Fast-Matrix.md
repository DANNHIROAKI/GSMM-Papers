## Fast Matrix Multiplication for Query Processing*

## 查询处理中的快速矩阵乘法*

XIAO HU, University of Waterloo, Canada

胡晓，加拿大滑铁卢大学

This paper studies how to use fast matrix multiplication to speed up query processing. As observed, computing a two-table join and then projecting away the join attribute is essentially the Boolean matrix multiplication problem, which can be significantly improved with fast matrix multiplication. Moving beyond this basic two-table query, we introduce output-sensitive algorithms for general join-project queries using fast matrix multiplication. These algorithms have achieved a polynomially large improvement over the classic Yannakakis framework. To the best of our knowledge, this is the first theoretical improvement for general acyclic join-project queries since 1981.

本文研究如何利用快速矩阵乘法加速查询处理。研究发现，计算两表连接后去除连接属性的操作本质上就是布尔矩阵乘法问题，而快速矩阵乘法能显著提升该运算效率。在基础两表查询之外，我们提出了基于快速矩阵乘法的输出敏感算法来处理通用连接-投影查询。这些算法相比经典的Yannakakis框架实现了多项式级的性能提升。据我们所知，这是自1981年以来针对无环连接-投影查询的首个理论突破。

## 1 INTRODUCTION

## 1 引言

Over the span of half of a century,the running time for multiplying two $U \times  U$ matrices has progressively improved from $O\left( {U}^{2.808}\right) \left\lbrack  {24}\right\rbrack$ to $O\left( {U}^{2.371552}\right) \left\lbrack  {{12},{27}}\right\rbrack$ . It is still a big open question whether it can be solved in ${U}^{2 + o\left( 1\right) }$ time eventually. Consider the multiplication of two matrices $\left( {a}_{ij}\right)$ and $\left( {b}_{jk}\right)$ . By treating each nonzero entry ${a}_{ij}$ as a tuple(i,j)(and similarly for ${b}_{jk}$ ),Boolean matrix multiplication can be written as a join-project query over two relations

半个世纪以来，两个$U \times  U$矩阵相乘的时间复杂度已从$O\left( {U}^{2.808}\right) \left\lbrack  {24}\right\rbrack$逐步优化至$O\left( {U}^{2.371552}\right) \left\lbrack  {{12},{27}}\right\rbrack$。能否最终实现${U}^{2 + o\left( 1\right) }$时间复杂度仍是悬而未决的问题。考虑两个矩阵$\left( {a}_{ij}\right)$与$\left( {b}_{jk}\right)$的乘法，将每个非零元素${a}_{ij}$视为元组(i,j)(对${b}_{jk}$同理)，布尔矩阵乘法可表示为两个关系上的连接-投影查询

$$
{\mathcal{Q}}_{\text{matrix }} = {\pi }_{A,C}{R}_{1}\left( {A,B}\right)  \bowtie  {R}_{2}\left( {B,C}\right) 
$$

However, both the input matrices and output matrix could be sparse, i.e., the number of nonzero entries can be much smaller than ${U}^{2}$ . We would like running times that depend on the number of non-zero entries in the input and output matrices,instead of $U$ . The naive algorithm that materializes the join results and then projects out attribute $B$ was the classic solution. Later, $\left\lbrack  {1,2,{11}}\right\rbrack$ investigated how to use fast matrix multiplication techniques to speedup sparse Boolean matrix multiplication, and [11] also showed strong evidence that these algorithms can significantly improve the classic solution in practice. A natural question arises: Can we exploit the fast matrix multiplication techniques in speeding up general join-project query processing? In this work, we answer this question in the affirmative by designing provably better output-sensitive algorithms for general join-project queries.

然而输入矩阵和输出矩阵都可能稀疏，即非零元素数量可能远少于${U}^{2}$。我们期望算法时间复杂度取决于输入输出矩阵的非零元素数量，而非$U$。传统解法是通过物化连接结果后去除属性$B$的朴素算法。$\left\lbrack  {1,2,{11}}\right\rbrack$探索了如何运用快速矩阵乘法技术加速稀疏布尔矩阵乘法，[11]也提供了这些算法在实践中显著优于经典解法的有力证据。这引出一个自然问题：能否将快速矩阵乘法技术应用于通用连接-投影查询的加速？本研究通过设计可证明更优的输出敏感算法，给出了肯定答案。

### 1.1 Problem Definition

### 1.1 问题定义

Join-Project queries. A join-project query is defined as a triple $Q = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ ,where $\mathcal{V} =$ $\left\{  {{A}_{1},{A}_{2},\ldots ,{A}_{\ell }}\right\}$ models the attributes, $\mathcal{E} = \left\{  {{e}_{1},{e}_{2},\ldots ,{e}_{k}}\right\}   \subseteq  {2}^{\mathcal{V}}$ models the subsets of attributes on which relations are defined and $\mathbf{y} \subseteq  \mathcal{V}$ models the output attributes (a.k.a. free attributes). We assume that $\mathcal{V} = \mathop{\bigcup }\limits_{{e \in  \mathcal{E}}}e$ . We also write $Q$ as $Q = {\pi }_{\mathbf{y}}\left( {{R}_{1}\left( {e}_{1}\right)  \boxtimes  {R}_{2}\left( {e}_{2}\right)  \boxtimes  \cdots  \boxtimes  {R}_{k}\left( {e}_{k}\right) }\right)$ . If $\mathbf{y} = \mathcal{V}$ , $Q$ is a full join; and if $\mathbf{y} = \varnothing ,Q$ is a Boolean query.

连接-投影查询。连接-投影查询被定义为一个三元组$Q = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$，其中$\mathcal{V} =$$\left\{  {{A}_{1},{A}_{2},\ldots ,{A}_{\ell }}\right\}$表示属性集合，$\mathcal{E} = \left\{  {{e}_{1},{e}_{2},\ldots ,{e}_{k}}\right\}   \subseteq  {2}^{\mathcal{V}}$表示定义关系的属性子集，$\mathbf{y} \subseteq  \mathcal{V}$表示输出属性（又称自由属性）。我们假定$\mathcal{V} = \mathop{\bigcup }\limits_{{e \in  \mathcal{E}}}e$。也可将$Q$记作$Q = {\pi }_{\mathbf{y}}\left( {{R}_{1}\left( {e}_{1}\right)  \boxtimes  {R}_{2}\left( {e}_{2}\right)  \boxtimes  \cdots  \boxtimes  {R}_{k}\left( {e}_{k}\right) }\right)$。若$\mathbf{y} = \mathcal{V}$，则$Q$为完全连接；若$\mathbf{y} = \varnothing ,Q$则为布尔查询。

Let $\operatorname{dom}\left( A\right)$ be the domain of attribute $A \in  \mathcal{V}$ . Let $\operatorname{dom}\left( \mathbb{A}\right)  = \mathop{\prod }\limits_{{A \in  \mathbb{A}}}\operatorname{dom}\left( A\right)$ be the domain of a subset of attributes $\mathbb{A} \subseteq  \mathcal{V}$ . A tuple $t$ defined over a subset of attributes $\mathbb{A} \subseteq  \mathcal{V}$ is a function that assigns a value from $\operatorname{dom}\left( A\right)$ to every attribute $A \in  \mathbb{A}$ . Furthermore,for a subset of attributes $X \subseteq  \mathbb{A}$ ,we denote ${\pi }_{X}t$ as the set of values that $t$ displays on every attribute in $X.{}^{1}$ An instance of $Q$ is a set of relations $\mathcal{R} = \left\{  {{R}_{e} : e \in  \mathcal{E}}\right\}$ ,where each relation ${R}_{e}$ consists a set of tuples defined over attributes $e$ . Given an instance $\mathcal{R}$ ,the query results of $\mathcal{Q}$ on $\mathcal{R}$ is defined as

设$\operatorname{dom}\left( A\right)$为属性$A \in  \mathcal{V}$的定义域。令$\operatorname{dom}\left( \mathbb{A}\right)  = \mathop{\prod }\limits_{{A \in  \mathbb{A}}}\operatorname{dom}\left( A\right)$表示属性子集$\mathbb{A} \subseteq  \mathcal{V}$的定义域。定义在属性子集$\mathbb{A} \subseteq  \mathcal{V}$上的元组$t$是一个函数，它为每个属性$A \in  \mathbb{A}$分配$\operatorname{dom}\left( A\right)$中的一个值。此外，对于属性子集$X \subseteq  \mathbb{A}$，我们用${\pi }_{X}t$表示元组$t$在$X.{}^{1}$中每个属性上呈现的值的集合。$Q$的一个实例是由关系集合$\mathcal{R} = \left\{  {{R}_{e} : e \in  \mathcal{E}}\right\}$构成，其中每个关系${R}_{e}$包含定义在属性$e$上的一组元组。给定实例$\mathcal{R}$，查询$\mathcal{Q}$在$\mathcal{R}$上的结果定义为

$$
\mathcal{Q}\left( \mathcal{R}\right)  = \left\{  {t \in  \operatorname{dom}\left( \mathbf{y}\right)  : \exists {t}^{\prime } \in  \operatorname{dom}\left( \mathcal{V}\right) ,{\pi }_{\mathbf{y}}{t}^{\prime } = t,\forall e \in  \mathcal{E},{\pi }_{e}{t}^{\prime } \in  {R}_{e}}\right\}  
$$

i.e., the projection (without duplicates) of all join results (combinations of tuples, one from each relation, such that they share the same values on their common attributes) onto attributes y. We denote $N = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {R}_{e}\right|$ as the input size of instance $\mathcal{R}$ and OUT $= \left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$ as the output size. We study the data complexity [25] of this problem,i.e., $k$ and $\ell$ are constants,and measure the time complexity of algorithms in terms of $N$ and OUT.

即：所有连接结果（来自各关系的元组组合，这些元组在其共有属性上具有相同值）在属性y上的投影（去重后）。我们将$N = \mathop{\sum }\limits_{{e \in  \mathcal{E}}}\left| {R}_{e}\right|$记作实例$\mathcal{R}$的输入规模，OUT$= \left| {\mathcal{Q}\left( \mathcal{R}\right) }\right|$记作输出规模。我们研究该问题的数据复杂度[25]，即视$k$和$\ell$为常数，并以$N$和OUT为度量标准评估算法时间复杂度。

Classification of Queries. There are some important classes of join-project queries, which will be discussed throughout the paper.

查询分类。连接-投影查询存在若干重要类别，本文后续将展开讨论。

- Acyclic Query [5,13,17]. There are many equivalent definitions of $\alpha$ -acyclic joins,and we use the one based on generalized join tree [17]. A generalized relation ${R}_{e}$ is defined on the projection of some input relation ${R}_{{e}^{\prime }}$ for ${e}^{\prime } \in  \mathcal{E}$ onto a subset of attributes $e \subseteq  {e}^{\prime }$ . A join-project query $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ is acyclic if there exists a tree $\mathcal{T}$ such that (1) each node in $\mathcal{T}$ corresponds to an input relation or a generalized relation; (2) every input relation in $\mathcal{E}$ corresponds to a node in $\mathcal{T}$ ; (3) for every attribute $A \in  \mathcal{V}$ ,the set of nodes containing it forms a connected subtree of $\mathcal{T}$ . $\mathcal{T}$ is called a generalized join tree of $Q$ . In the remaining of this paper,we use "join tree" to denote "generalized join tree" for simplicity.

- 无环查询[5,13,17]。关于$\alpha$无环连接存在多种等价定义，本文采用基于广义连接树[17]的定义。广义关系${R}_{e}$定义在输入关系${R}_{{e}^{\prime }}$对属性子集$e \subseteq  {e}^{\prime }$的投影上。当存在满足以下条件的树结构$\mathcal{T}$时，连接-投影查询$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$称为无环查询：(1)树中每个节点对应一个输入关系或广义关系；(2)$\mathcal{E}$中每个输入关系都对应树中节点；(3)对于任意属性$A \in  \mathcal{V}$，包含该属性的节点集合构成$\mathcal{T}$的连通子树。此树结构$\mathcal{T}$称为$Q$的广义连接树。为简洁起见，后文统一用"连接树"指代"广义连接树"。

- Free-connex Query [3]. A join-project query $Q = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ is free-connex if $Q$ is acyclic and $\left( {\mathcal{V},\mathcal{E}\cup \{ \mathbf{y}\} ,\mathbf{y}}\right)$ is also acyclic.

- 自由连接查询[3]。当连接-投影查询$Q = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$及其$\left( {\mathcal{V},\mathcal{E}\cup \{ \mathbf{y}\} ,\mathbf{y}}\right)$均为无环结构时，该查询称为自由连接查询。

Model of Computation. We use the standard RAM model with uniform cost measure. For an instance of size $N$ ,every register has length $O\left( {\log N}\right)$ . Any arithmetic operation (such as addition, subtraction,multiplication and division) on the values of two registers can be done in $O\left( 1\right)$ time. Concatenating the values of two registers can be done in $O\left( 1\right)$ time. Sorting the values of $N$ registers can be done in $O\left( {N\log N}\right)$ time.

计算模型。采用均匀成本度量的标准RAM模型。对于规模为$N$的实例，每个寄存器长度为$O\left( {\log N}\right)$。对两个寄存器值的算术运算（如加减乘除）可在$O\left( 1\right)$时间内完成。寄存器值的连接操作可在$O\left( 1\right)$时间内完成。对$N$个寄存器值的排序可在$O\left( {N\log N}\right)$时间内完成。

Notations. For a subset of attributes $\mathbb{A} \subseteq  \mathcal{V}$ ,we define the active domain of $\mathbb{A}$ with respect to an instance $\mathcal{R}$ as the set of tuples in $\operatorname{dom}\left( \mathbb{A}\right)$ appearing in at least one join result of $\mathcal{R}$ ,i.e., ${\pi }_{\mathbb{A}}{ \bowtie  }_{e \in  \mathcal{E}}{R}_{e}$ . For a pair of relations ${R}_{e}$ and ${R}_{{e}^{\prime }}$ ,we use ${R}_{e} \ltimes  {R}_{{e}^{\prime }} = {\pi }_{e}\left( {{R}_{e} \ltimes  {R}_{{e}^{\prime }}}\right)$ to denote the semi-join between ${R}_{e}$ and ${R}_{{e}^{\prime }}$ . For any $n \in  {\mathbb{Z}}^{ + }$ ,we use $\left\lbrack  n\right\rbrack$ to denote $\{ 1,2,\cdots ,n\}$ . For a pair of sets ${S}_{1}$ and ${S}_{2}$ ,we use ${S}_{1} - {S}_{2} = \left\{  {x \in  {S}_{1} : x \notin  {S}_{2}}\right\}$ to denote their set difference. We use $\widetilde{O}\left( t\right)$ to denote $O\left( {t}^{1 + o\left( 1\right) }\right)$ in all complexity results.

符号约定。对于属性子集$\mathbb{A} \subseteq  \mathcal{V}$，定义$\mathbb{A}$关于实例$\mathcal{R}$的活跃域为$\operatorname{dom}\left( \mathbb{A}\right)$中至少出现在一个连接结果的元组集合，即${\pi }_{\mathbb{A}}{ \bowtie  }_{e \in  \mathcal{E}}{R}_{e}$。对于关系对${R}_{e}$和${R}_{{e}^{\prime }}$，用${R}_{e} \ltimes  {R}_{{e}^{\prime }} = {\pi }_{e}\left( {{R}_{e} \ltimes  {R}_{{e}^{\prime }}}\right)$表示其半连接运算。对任意$n \in  {\mathbb{Z}}^{ + }$，用$\left\lbrack  n\right\rbrack$表示$\{ 1,2,\cdots ,n\}$。对于集合对${S}_{1}$和${S}_{2}$，用${S}_{1} - {S}_{2} = \left\{  {x \in  {S}_{1} : x \notin  {S}_{2}}\right\}$表示其差集。所有复杂度结果中$\widetilde{O}\left( t\right)$均表示$O\left( {t}^{1 + o\left( 1\right) }\right)$。

### 1.2 The Yannakakis framework

### 1.2 Yannakakis框架

In the RAM model, the Yannakakis framework [29] was proposed for acyclic join-project queries dated back to 1981. See Algorithm 4. It picks an arbitrary join tree ${}^{2}\mathcal{T}$ for $Q$ rooted at node $r$ . It first removes all dangling tuples in the input instance $\mathcal{R}$ ,i.e.,those won’t appear in any full join result,in $O\left( N\right)$ time via a bottom-up and then a top-down phase of semi-joins. If OUT $= 0$ , i.e., $\mathcal{Q}\left( \mathcal{R}\right)  = \varnothing$ ,all input tuples will be removed as dangling tuples. After done with semi-joins, Yannakakis framework performs joins and projections in a bottom-up way. Specifically, it takes two relation ${R}_{e}$ and ${R}_{{e}^{\prime }}$ such that $e$ is a leaf and ${e}^{\prime }$ is the parent of $e$ ,projects away non-output attributes that appear in $e$ but not in ${e}^{\prime }$ by replacing ${R}_{e}$ with ${\pi }_{\mathrm{y} \cup  \left( {e \cap  {e}^{\prime }}\right) }{R}_{e}$ ,and replaces ${R}_{{e}^{\prime }}$ with ${R}_{e} \bowtie  {R}_{{e}^{\prime }}$ . Then ${R}_{e}$ is removed and the step repeats until the root node ${R}_{r}$ remains. It just outputs ${\pi }_{\mathrm{y}}{R}_{r}$ as the final results. The running time of the Yannakakis framework is proportional to the largest intermediate join size (after dangling tuples are removed), which is no larger than the full join size. Hence, Yannakakis framework is always better than the naive algorithm that computes the full join results and then projects out non-output attributes. We note that the largest intermediate join size could differ drastically on different query plans, i.e., each query plan of the Yannakakis framework corresponds to a rooted join tree together with the bottom-up computations of joins and projections.

在RAM模型中，Yannakakis框架[29]最早于1981年针对无环连接-投影查询提出。参见算法4。该框架为$Q$选取任意以节点$r$为根的连接树${}^{2}\mathcal{T}$，通过自底向上和自顶向下两轮半连接操作，在$O\left( N\right)$时间内剔除输入实例$\mathcal{R}$中的所有悬空元组（即不会出现在完整连接结果中的元组）。若OUT$= 0$（即$\mathcal{Q}\left( \mathcal{R}\right)  = \varnothing$），所有输入元组都将作为悬空元组被剔除。完成半连接后，Yannakakis框架以自底向上方式执行连接和投影：选取两个关系${R}_{e}$与${R}_{{e}^{\prime }}$，其中$e$为叶节点，${e}^{\prime }$是其父节点，通过将${R}_{e}$替换为${\pi }_{\mathrm{y} \cup  \left( {e \cap  {e}^{\prime }}\right) }{R}_{e}$来投影掉$e$中出现但${e}^{\prime }$中不存在的非输出属性，并将${R}_{{e}^{\prime }}$替换为${R}_{e} \bowtie  {R}_{{e}^{\prime }}$。随后移除${R}_{e}$并重复该步骤直至仅剩根节点${R}_{r}$，最终输出${\pi }_{\mathrm{y}}{R}_{r}$作为结果。该框架的运行时间与最大中间连接规模（剔除悬空元组后）成正比，且该规模始终不大于完整连接结果规模，因此Yannakakis框架始终优于需先计算完整连接再投影的朴素算法。值得注意的是，不同查询计划对应的最大中间连接规模可能差异显著——Yannakakis框架中每个查询计划对应一个带根连接树及自底向上的连接投影计算过程。

If $Q$ is free-connex,there is a query plan that only generate at most $O$ (OUT) intermediate join results $\left\lbrack  {4,{18}}\right\rbrack$ ,hence free-connex queries can be computed in $O\left( {N + \mathrm{{OUT}}}\right)$ time,which is optimal. Note that any acyclic full join query is free-connex. For non-free-connex queries, Yannakakis gave an upper bound of $O\left( {N \cdot  \mathrm{{OUT}}}\right)$ on the largest intermediate join size. For ${Q}_{\text{matrix }}$ ,the simplest acyclic but non-free-connex query,this bound has been improved to $O\left( {N \cdot  \sqrt{\mathrm{{OUT}}}}\right) \left\lbrack  2\right\rbrack$ by a better analysis. This is also tight, since there are instances with intermediate join results (which is also the full join results for ${Q}_{\text{matrix }}$ ) as large as $\Theta \left( {N \cdot  \sqrt{\mathrm{{OUT}}}}\right)$ . This bound also extends to star queries,

若$Q$满足自由连接性，则存在仅生成最多$O$（OUT）个中间连接结果$\left\lbrack  {4,{18}}\right\rbrack$的查询计划，故自由连接查询可在最优的$O\left( {N + \mathrm{{OUT}}}\right)$时间内完成计算。需注意所有无环完整连接查询均满足自由连接性。对于非自由连接查询，Yannakakis给出了最大中间连接规模的上界$O\left( {N \cdot  \mathrm{{OUT}}}\right)$。以最简单的无环非自由连接查询${Q}_{\text{matrix }}$为例，通过更精细的分析该上界已改进至$O\left( {N \cdot  \sqrt{\mathrm{{OUT}}}}\right) \left\lbrack  2\right\rbrack$，且该界是紧致的——存在中间连接结果（即${Q}_{\text{matrix }}$的完整连接结果）规模达$\Theta \left( {N \cdot  \sqrt{\mathrm{{OUT}}}}\right)$的实例。该上界同样适用于星型查询，

$$
{Q}_{\text{star }} = {\pi }_{{A}_{1},{A}_{2},\cdots ,{A}_{k}}{R}_{1}\left( {{A}_{1},B}\right)  \bowtie  {R}_{2}\left( {{A}_{2},B}\right)  \bowtie  \cdots  \bowtie  {R}_{k}\left( {{A}_{k},B}\right) ,
$$

on which the tight bound is $O\left( {N \cdot  {\mathrm{{OUT}}}^{1 - \frac{1}{k}}}\right)$ . But,for line queries,

People have incorporated generalized hypertree decomposition techniques [15] together with worst-case optimal join algorithms $\left\lbrack  {{21},{26}}\right\rbrack$ into the Yannakakis framework to handle cyclic join-project queries. Khamis et al. And subw $= 1$ if and only if $Q$ is acyclic. If restricting the generalized hypertree decompositions to be free-connex, one can also obtain an algorithm that can compute a join-project query $Q$ in $O\left( {{N}^{\text{fc-subw }} + \mathrm{{OUT}}}\right)$ time,where fc-subw is the free-connex sub-modular width of $Q\left\lbrack  6\right\rbrack$ . Moreover,fc-subw = 1 if and only if $Q$ is free-connex. It is not hard to see that fc-subw $\geq$ subw for arbitrary join-project query. 人们已将广义超树分解技术[15]与最坏情况最优连接算法$\left\lbrack  {{21},{26}}\right\rbrack$整合到Yannakakis框架中，以处理循环连接-投影查询。Khamis等人[19]提出的PANDA算法结合Yannakakis框架，可在$O\left( {{N}^{\text{subw }} \cdot  \mathrm{{OUT}}}\right)$时间内计算连接-投影查询$Q$，其中subw$\geq  1$表示$Q\left\lbrack  {20}\right\rbrack$的子模宽度。当且仅当$Q$为无环查询时，subw$= 1$。若限制广义超树分解为自由连接型，则可得到在$O\left( {{N}^{\text{fc-subw }} + \mathrm{{OUT}}}\right)$时间内计算连接-投影查询$Q$的算法，其中fc-subw表示$Q\left\lbrack  6\right\rbrack$的自由连接子模宽度。当且仅当$Q$为自由连接查询时，fc-subw=1。显然对于任意连接-投影查询，fc-subw$\geq$subw。除非已知OUT值，否则这两种算法不可直接比较。

### 1.3 Fast Matrix Multiplication for ${Q}_{\text{matrix }}$

### 1.3 ${Q}_{\text{matrix }}$的快速矩阵乘法

As mentioned, people have also investigated how to use fast matrix multiplication techniques to speedup sparse Boolean matrix multiplication. The running time of computing two rectangular matrices of size ${U}^{a} \times  {U}^{b}$ and ${U}^{b} \times  {U}^{c}$ is denoted as $O\left( {U}^{\omega \left( {a,b,c}\right) }\right)$ . The parameter $\omega$ ,which is commonly-noted as the exponent of fast square matrix multiplication,refers to the case $\omega \left( {1,1,1}\right)$ . The currently best bounds on $\omega$ are $2 \leq  \omega  < {2.371552}$ [28]. Rectangular matrix multiplication can always be tackled by partitioning rectangles into squares,for example $\omega \left( {a,b,c}\right)  \leq  a + b + c -$ $\min \{ a,b,c\}  \cdot  \left( {3 - \omega }\right)$ ,but much better algorithms have been proposed. There are some important constants related to rectangular matrix multiplication,such as, $\alpha  \leq  1$ defined as the largest constant such that $\omega \left( {1,\alpha ,1}\right)  = 2$ ,and $\mu$ is the (unique) solution to the equation $\omega \left( {\mu ,1,1}\right)  = {2\mu } + 1$ . Note that $\alpha  = 1$ if and only if $\omega  = 2$ ,and the current best bounds on $\alpha$ are ${0.321334} < \alpha  \leq  1$ [28]. Moreover, $\mu  = \frac{1}{2}$ if $\omega  = 2$ ,and the current best bounds on $\mu$ are $\frac{1}{2} \leq  \mu  < {0.527661}$ [28].

如前所述，研究者还探索了如何利用快速矩阵乘法技术加速稀疏布尔矩阵乘法。计算尺寸为${U}^{a} \times  {U}^{b}$和${U}^{b} \times  {U}^{c}$的两个矩形矩阵的耗时记为$O\left( {U}^{\omega \left( {a,b,c}\right) }\right)$。参数$\omega$（通常称为快速方阵乘法的指数）特指$\omega \left( {1,1,1}\right)$情形。目前$\omega$的最佳边界是$2 \leq  \omega  < {2.371552}$[28]。矩形矩阵乘法总可通过划分矩形为正方形来处理（例如$\omega \left( {a,b,c}\right)  \leq  a + b + c -$$\min \{ a,b,c\}  \cdot  \left( {3 - \omega }\right)$），但已有更优算法被提出。与矩形矩阵乘法相关的重要常数包括：$\alpha  \leq  1$定义为满足$\omega \left( {1,\alpha ,1}\right)  = 2$的最大常数；$\mu$是方程$\omega \left( {\mu ,1,1}\right)  = {2\mu } + 1$的唯一解。注意当且仅当$\omega  = 2$时$\alpha  = 1$成立，当前$\alpha$的最佳边界为${0.321334} < \alpha  \leq  1$[28]。此外，若$\omega  = 2$则$\mu  = \frac{1}{2}$，当前$\mu$的最佳边界为$\frac{1}{2} \leq  \mu  < {0.527661}$[28]。

Amossen and Pagh [2] first proposed an algorithm for ${Q}_{\text{matrix }}$ by using fast matrix multiplication techniques,which runs in $\widetilde{O}\left( {{N}^{\frac{2}{3}} \cdot  {\mathrm{{OUT}}}^{\frac{2}{3}} + {N}^{\frac{\left( {2 - \alpha }\right) \omega  - 2}{\left( {1 + \omega }\right) \left( {1 - \alpha }\right) }} \cdot  {\mathrm{{OUT}}}^{\frac{2 - {\alpha \omega }}{\left( {1 + \omega }\right) \left( {1 - \alpha }\right) }} + \mathrm{{OUT}}}\right)$ time when OUT $\geq  N$ ,and $\widetilde{O}\left( {N \cdot  {\operatorname{OUT}}^{\frac{\omega  - 1}{\omega  + 1}}}\right)$ time when OUT $< N$ . If $\omega  = 2$ ,this result degenerates to $\widetilde{O}\left( {{N}^{\frac{2}{3}} \cdot  {\mathrm{{OUT}}}^{\frac{2}{3}} + N \cdot  {\mathrm{{OUT}}}^{\frac{1}{3}}}\right)$ . Very recently,Abboud et al. If $\omega  = 2$ ,this complexity can be simplified as $\widetilde{O}\left( {N \cdot  {\mathrm{{OUT}}}^{\frac{1}{3}} + \mathrm{{OUT}}}\right)$ . Surprisingly,when $\mathrm{{OUT}}$ becomes larger than ${N}^{\frac{3}{2}}$ ,this result further degenerates to $\widetilde{O}\left( {N + \text{OUT}}\right)$ ,which is (almost) optimal up to a poly-logarithmic factor. On the other hand, improving this result for any value of OUT is rather difficult, assuming the hardness of the all-edge-triangle problem [1]. There are many algorithm proposed for sparse Boolean matrix multiplication, whose complexity are also measured by domain size of attributes; and we refer readers to [1] for details.

Amossen与Pagh[2]首次提出利用快速矩阵乘法技术实现${Q}_{\text{matrix }}$的算法，当输出量$\geq  N$时时间复杂度为$\widetilde{O}\left( {{N}^{\frac{2}{3}} \cdot  {\mathrm{{OUT}}}^{\frac{2}{3}} + {N}^{\frac{\left( {2 - \alpha }\right) \omega  - 2}{\left( {1 + \omega }\right) \left( {1 - \alpha }\right) }} \cdot  {\mathrm{{OUT}}}^{\frac{2 - {\alpha \omega }}{\left( {1 + \omega }\right) \left( {1 - \alpha }\right) }} + \mathrm{{OUT}}}\right)$，输出量$< N$时则为$\widetilde{O}\left( {N \cdot  {\operatorname{OUT}}^{\frac{\omega  - 1}{\omega  + 1}}}\right)$。若$\omega  = 2$，该结果会退化为$\widetilde{O}\left( {{N}^{\frac{2}{3}} \cdot  {\mathrm{{OUT}}}^{\frac{2}{3}} + N \cdot  {\mathrm{{OUT}}}^{\frac{1}{3}}}\right)$。最近，Abboud等人[1]将其全面改进至$\widetilde{O}\left( {N \cdot  {\mathrm{{OUT}}}^{\frac{\mu }{1 + \mu }} + \mathrm{{OUT}} + {N}^{\frac{\left( {2 + \alpha }\right) \mu }{1 + \mu }} \cdot  {\mathrm{{OUT}}}^{\frac{1 - {\alpha \mu }}{1 + \mu }}}\right)$。当$\omega  = 2$时，该复杂度可简化为$\widetilde{O}\left( {N \cdot  {\mathrm{{OUT}}}^{\frac{1}{3}} + \mathrm{{OUT}}}\right)$。令人惊讶的是，当$\mathrm{{OUT}}$超过${N}^{\frac{3}{2}}$时，结果会进一步退化为$\widetilde{O}\left( {N + \text{OUT}}\right)$，这个结果（几乎）在多对数因子范围内达到最优。另一方面，基于全边三角形问题的计算难度假设[1]，针对任意输出量改进该结果都相当困难。现有诸多稀疏布尔矩阵乘法算法，其复杂度同样通过属性域大小衡量，详见文献[1]。

### 1.4 Other Results

### 1.4 其他研究成果

Deep et al. [11] extended the algorithm for ${Q}_{\text{matrix }}$ to ${Q}_{\text{star }}$ ,but without giving any theoretical analysis, but their results are completely dominated by our new results (see Appendix B). Hu et al. [16] studied tree (i.e., acyclic and each relation contains at most two attributes) join-aggregate queries defined over semi-rings in the massively parallel computation model, without using fast matrix multiplication. Interestingly, we revisit their algorithms in the RAM model for join-project queries,and observe some improvements over the Yannakakis framework on ${Q}_{\text{line }}$ and ${Q}_{\text{star }}$ by incorporating the best algorithm [1] for sparse matrix multiplication (see Appendix E). But, these improvements are also completely dominated by our new results. In addition, there has been a large body of works studying the fine-grained complexity of detecting or listing graph patterns (such as triangle, cycles and cliques), and their algorithms also use fast matrix multiplication. We refer interested readers to $\left\lbrack  {7,9,{10},{23}}\right\rbrack$ for details.

Deep等人[11]将${Q}_{\text{matrix }}$算法扩展至${Q}_{\text{star }}$，但未提供理论分析，其成果被我们的新结果全面超越（见附录B）。Hu等人[16]在大规模并行计算模型中研究了定义在半环上的树形（即无环且每个关系至多含两个属性）连接聚合查询，未采用快速矩阵乘法。有趣的是，我们在RAM模型中重新审视其算法对连接投影查询的应用，发现通过结合稀疏矩阵乘法最佳算法[1]，在${Q}_{\text{line }}$和${Q}_{\text{star }}$上对Yannakakis框架有所改进（见附录E）。但这些改进同样被我们的新结果全面超越。此外，现有大量研究探讨检测或列举图模式（如三角形、环和团）的精细复杂度，相关算法也采用快速矩阵乘法，详见$\left\lbrack  {7,9,{10},{23}}\right\rbrack$。

Limitation of Yannakakis Framework. One may wonder what we can benefit from incorporating the best algorithm for ${Q}_{\text{matrix }}$ as a primitive into Yannakakis framework. Recall that in each step,it takes two relation ${R}_{e}$ and ${R}_{{e}^{\prime }}$ such that $e$ is a leaf and ${e}^{\prime }$ is the parent of $e$ ,projects away non-output attributes that appear in $e$ but not in ${e}^{\prime }$ by replacing ${R}_{e}$ with ${\pi }_{\mathrm{y} \cup  \left( {e \cap  {e}^{\prime }}\right) }{R}_{e}$ ,and replaces ${R}_{{e}^{\prime }}$ with ${R}_{e} \bowtie  {R}_{{e}^{\prime }}$ . If $e$ is the last child of ${e}^{\prime }$ ,then we can merge the last join with the subsequent projection of ${R}_{{e}^{\prime }}$ when ${e}^{\prime }$ turns to be a leaf node,into one join-project query. More specifically,it suffices to compute ${\pi }_{\mathrm{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }{R}_{e} \bowtie  {R}_{{e}^{\prime }}$ ,where $\operatorname{anc}\left( {e}^{\prime }\right)$ denotes the set of attributes that appear in both ${e}^{\prime }$ and any ancestor of ${e}^{\prime }$ . This could be captured as a matrix multiplication problem if $e \cap  \mathbf{y} - {e}^{\prime } \neq  \varnothing$ , $e \cap  {e}^{\prime } \cap  \left( {\mathcal{V} - \mathbf{y}}\right)  - \operatorname{anc}\left( {e}^{\prime }\right)  \neq  \varnothing$ and $\left( {\mathbf{y} \cap  {e}^{\prime }}\right)  \cup  \operatorname{anc}\left( {e}^{\prime }\right)  - e \neq  \varnothing$ . However,its output size is not necessarily bounded by $O\left( \mathrm{{OUT}}\right)$ . In the worst case,this output size can be as large as $\Theta \left( {N \cdot  \mathrm{{OUT}}}\right)$ . See Appendix C. Hence, materializing intermediate query results (not intermediate join size) is still the bottleneck of whole algorithm, no matter which algorithm is used for tackling the matrix multiplication problem.

Yannakakis框架的局限性。人们可能会思考，将针对${Q}_{\text{matrix }}$的最佳算法作为原语集成到Yannakakis框架中能带来什么优势。需注意的是，在每一步中，该框架会选取两个关系${R}_{e}$和${R}_{{e}^{\prime }}$，其中$e$为叶节点而${e}^{\prime }$是$e$的父节点，通过用${\pi }_{\mathrm{y} \cup  \left( {e \cap  {e}^{\prime }}\right) }{R}_{e}$替换${R}_{e}$来投影掉存在于$e$但不在${e}^{\prime }$中的非输出属性，并将${R}_{{e}^{\prime }}$替换为${R}_{e} \bowtie  {R}_{{e}^{\prime }}$。若$e$是${e}^{\prime }$的最后一个子节点，则当${e}^{\prime }$转为叶节点时，可将最后的连接操作与后续对${R}_{{e}^{\prime }}$的投影合并为一个连接-投影查询。具体而言，只需计算${\pi }_{\mathrm{y} \cup  \operatorname{anc}\left( {e}^{\prime }\right) }{R}_{e} \bowtie  {R}_{{e}^{\prime }}$即可，其中$\operatorname{anc}\left( {e}^{\prime }\right)$表示同时出现在${e}^{\prime }$及其任意祖先节点中的属性集合。当满足条件$e \cap  \mathbf{y} - {e}^{\prime } \neq  \varnothing$、$e \cap  {e}^{\prime } \cap  \left( {\mathcal{V} - \mathbf{y}}\right)  - \operatorname{anc}\left( {e}^{\prime }\right)  \neq  \varnothing$和$\left( {\mathbf{y} \cap  {e}^{\prime }}\right)  \cup  \operatorname{anc}\left( {e}^{\prime }\right)  - e \neq  \varnothing$时，该问题可转化为矩阵乘法问题。然而，其输出大小并不必然受限于$O\left( \mathrm{{OUT}}\right)$。最坏情况下，输出规模可能高达$\Theta \left( {N \cdot  \mathrm{{OUT}}}\right)$（详见附录C）。因此，无论采用何种算法处理矩阵乘法问题，物化中间查询结果（非中间连接规模）始终是整个算法的性能瓶颈。

## 3 ACYCLIC QUERIES

## 3 无环查询

We finally move to general acyclic join-project queries. Consider an acyclic join-project query $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ and an instance $\mathcal{R}$ . All dangling tuples (that do not participate in any join result) are removed in $O\left( N\right)$ time. We start with two procedures cleanse and decompose. An attribute $A \in  \mathcal{V}$ is unique if it only appears in one relation,i.e., $\left| {\{ e \in  \mathcal{E} : A \in  e\} }\right|  = 1$ ,and joint otherwise.

最后我们转向一般无环连接-投影查询。考虑无环连接-投影查询$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$和实例$\mathcal{R}$。所有悬空元组（不参与任何连接结果）已在$O\left( N\right)$时间内移除。我们从清理（cleanse）和分解（decompose）两个流程开始。若属性$A \in  \mathcal{V}$仅出现在单个关系中（即$\left| {\{ e \in  \mathcal{E} : A \in  e\} }\right|  = 1$），则称其为唯一属性，否则为联合属性。

CLEANSE(Q,R). For a join-aggregate query $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ and an instance $\mathcal{R}$ ,the cleanse procedure iteratively (i) removes a unique non-output attribute $A \in  e$ and updates ${R}_{e}$ with ${\pi }_{e - A}{R}_{e}$ ; or (ii) removes a relation $e \in  \mathcal{E}$ if there exists another relation ${e}^{\prime } \in  \mathcal{E}$ with $e \subseteq  {e}^{\prime }$ and updates ${R}_{{e}^{\prime }}$ with ${R}_{{e}^{\prime }} \ltimes  {R}_{e}$ . We describe this procedure in Algorithm 5. This can be done in $O\left( N\right)$ time,where $N$ is the input size of the instance. A join-project query $Q$ is called cleansed if no more attribute or relation can be removed by the cleanse procedure, and non-cleansed otherwise. In a cleansed query, every unique attribute must be an output attribute.

清理(Q,R)。对于连接-聚合查询$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$和实例$\mathcal{R}$，清理流程迭代执行：(i)移除唯一的非输出属性$A \in  e$并用${\pi }_{e - A}{R}_{e}$更新${R}_{e}$；或(ii)当存在满足$e \subseteq  {e}^{\prime }$的另一关系${e}^{\prime } \in  \mathcal{E}$时移除关系$e \in  \mathcal{E}$，并用${R}_{{e}^{\prime }} \ltimes  {R}_{e}$更新${R}_{{e}^{\prime }}$。该流程详见算法5，可在$O\left( N\right)$时间内完成（$N$为实例输入规模）。若无法通过清理流程移除更多属性或关系，则称连接-投影查询$Q$为洁净查询，反之为非洁净查询。在洁净查询中，所有唯一属性必须为输出属性。

Decompose(Q,R). We define the existential connectivity of $\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$ by modeling it as a graph ${G}_{Q}^{\exists }$ ,where each $e \in  \mathcal{E}$ is a vertex,and there is an edge between $e,{e}^{\prime } \in  \mathcal{E}$ if they share some non-output attribute(s),i.e., $e \cap  {e}^{\prime } - \mathbf{y} \neq  \varnothing$ . Let ${\mathcal{E}}_{1},{\mathcal{E}}_{2},\cdots ,{\mathcal{E}}_{h} \subseteq  \mathcal{E}$ be the connected components of ${G}_{Q}^{\exists }$ . Each ${\mathcal{E}}_{i}$ defines a subquery ${\mathcal{Q}}_{i} = \left( {\mathop{\bigcup }\limits_{{e \in  {\mathcal{E}}_{i}}}e,{\mathcal{E}}_{i},\mathop{\bigcup }\limits_{{e \in  {\mathcal{E}}_{i}}}e \cap  \mathbf{y}}\right)$ and a sub-instance ${\mathcal{R}}_{i} = \left\{  {{R}_{j} \in  \mathcal{R} : {e}_{j} \in  {\mathcal{E}}_{i}}\right\}$ . It is not hard to see that if $Q$ is cleansed,each sub-query ${Q}_{i}$ is also cleansed, since no more non-output attributes become unique and no more relations become a subset of another relation in the decompose procedure. A critical observation is stated below (intuitively, relations across different sub-queries can only join via output attributes):

分解(Q,R)。我们将$\mathcal{Q} = \left( {\mathcal{V},\mathcal{E},\mathbf{y}}\right)$的存在连通性定义为图模型${G}_{Q}^{\exists }$，其中每个$e \in  \mathcal{E}$作为顶点，当$e,{e}^{\prime } \in  \mathcal{E}$共享某些非输出属性时（即$e \cap  {e}^{\prime } - \mathbf{y} \neq  \varnothing$）则存在边。设${\mathcal{E}}_{1},{\mathcal{E}}_{2},\cdots ,{\mathcal{E}}_{h} \subseteq  \mathcal{E}$为${G}_{Q}^{\exists }$的连通分量，每个${\mathcal{E}}_{i}$定义了一个子查询${\mathcal{Q}}_{i} = \left( {\mathop{\bigcup }\limits_{{e \in  {\mathcal{E}}_{i}}}e,{\mathcal{E}}_{i},\mathop{\bigcup }\limits_{{e \in  {\mathcal{E}}_{i}}}e \cap  \mathbf{y}}\right)$和子实例${\mathcal{R}}_{i} = \left\{  {{R}_{j} \in  \mathcal{R} : {e}_{j} \in  {\mathcal{E}}_{i}}\right\}$。显然，若$Q$是清洁的，则每个子查询${Q}_{i}$也保持清洁，因为在分解过程中不会新增唯一非输出属性，也不会产生新的关系子集。关键观察如下（直观而言，跨子查询的关系只能通过输出属性进行连接）：

一般情形(1)：$\left| \mathcal{L}\right|  = 1$。我们将此类连接-投影查询$Q$称为花型查询，具体算法将在3.2节单独描述。

General Case (2): $\left| \mathcal{L}\right|  \geq  2$ . Our algorithm will iteratively choose a node $e \in  \mathcal{L}$ and merge all leaf nodes in $\mathcal{T}$ incident to $e$ . In this way,we keep partitioning the input instance into multiple pieces, while decreasing the size of $\mathcal{Q}$ until $\left| \mathcal{L}\right|  = 1$ . We show this algorithm in Section 3.3.

一般情形(2)：$\left| \mathcal{L}\right|  \geq  2$。算法将迭代选择节点$e \in  \mathcal{L}$，合并$\mathcal{T}$中所有与$e$相邻的叶节点。通过这种方式不断将输入实例分割为多个片段，同时缩减$\mathcal{Q}$的规模直至$\left| \mathcal{L}\right|  = 1$。该算法详见3.3节。

Post-processing. Our recursive algorithm above will reduce $Q$ into $O\left( 1\right)$ sub-queries,each of them could produce $O\left( \mathrm{{OUT}}\right)$ query results. The last step is to remove possible duplicates between them, which can be done via sorting.
